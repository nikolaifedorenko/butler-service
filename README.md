# Батлер Сервис — система учёта рабочего времени

Веб-интерфейс и расчётный движок **v7.1** для службы батлеров: Табель и График
«ФИО × дни месяца», отметки прихода/ухода кнопками с телефона, банк часов,
управленческий табель (УТ) с кодами переработок **ДЯ / ДН / ДЯ2 / ДН2**, закрытие
и пересчёт периодов, доска «кто сейчас на работе», история сессий и выгрузки в
**Excel/PDF**.

Расчёт ведётся детерминированным движком по спецификации
[`docs/overtime_spec_v7_1_final.md`](docs/overtime_spec_v7_1_final.md)
(единственный нормативный документ): чистые функции
«данные → данные», пять слоёв (`domain / application / ports / adapters / interface`),
поведение из справочников CFG-*, трассируемость каждого действия, 55 приёмочных
примеров EX-01…EX-55 в автотестах.

## Быстрый старт

```bash
cd butler-service
pip install -r requirements.txt        # всё, включая PDF (reportlab)
./run.sh                      # или: python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```
`./run.sh` сам создаёт `.venv`, **доустанавливает недостающие пакеты** и проверяет, что
приложение запускается. Режимы: `./run.sh --reinstall` (пересоздать окружение),
`PDF=off ./run.sh` (быстрый старт без PDF-движка), `PORT=9000 ./run.sh` (другой порт).

Откройте http://127.0.0.1:8000 — при первом запуске база создастся и заполнится
демо-данными: 11 сотрудников, циклы блоков, Табель из циклов, График из Табеля,
отметки, начальный банк (посев `OPENING_SEED`) у каждого сотрудника.

> **Переход с прежних версий.** Расчётные данные движка v4 (до 15.10.2026) с моделью v7.1
> несовместимы и автоматически **не** очищаются: демо-базу такого возраста пересоздайте
> (удалите `timetrack.db` — сид заполнит её заново). Боевых баз на старых версиях нет
> (решение владельца 21.10.2026); схема дальше обновляется ревизиями Alembic (ADR-0002).

## Шахматка (модуль `stays`)

Кто из гостей где и когда живёт и кто из батлеров их ведёт — весь фонд отеля (виллы,
имение, апартаменты, номера). Вкладки: шахматка объектов, шахматка батлеров, табло
дня, сводная загрузка; у батлера — «Мои гости» с телефона. Любое изменение брони или
назначения можно сначала «примерить» (кнопка «Проверить»): видно, куда встанет бронь,
какие чужие брони сдвинутся, какие появятся предупреждения и как изменится нагрузка.
Предупреждения («вне смены», «нужна подмена», перегруз, гости без батлера) считаются
против актуального Графика при каждом открытии. Права — раздел «Шахматка» в
«Правах доступа»; уровень «Загрузка без гостей» не получает с сервера ни одного поля
гостя. Спецификация —
[`docs/superpowers/specs/2026-10-23-stays-chessboard-design.md`](docs/superpowers/specs/2026-10-23-stays-chessboard-design.md).

## Тесты и проверки

Для dev-инструментов (смоуки интерфейса, eslint) нужен **Node ≥ 22**:
jsdom 30+ тянет undici 7, который на Node 20 падает на `markAsUncloneable`.

```bash
pip install -r requirements-dev.txt
python -m pytest tests/ -q                    # весь набор
python -m pytest tests/engine -q --cov=app.modules.timesheet.domain --cov-report=term   # покрытие домена ≥ 95 %
python -m ruff check .                        # линтер Python
npm install && npm run lint                   # ESLint (no-undef по списку глобальных имён)
npm run globals:check                         # tools/js_globals.json актуален
python tools/check_api_contract.py --verbose  # фронтенд не зовёт несуществующие маршруты
python tools/bump_version.py --check          # версии статики согласованы
```

Что покрывают тесты: **приёмочные примеры EX-01…EX-55** (каждый подкейс — отдельный
тест, полное сравнение `SettleResult`/`FlagsResult` в канонической форме), все
инварианты INV-* (включая property-based фаззинг «размещение → каскад → повторное
размещение» на шагах 15/30/60 и детерминизм при перестановке отметок/переносов),
юнит-тесты каждой функции каталога 8.1, валидацию трёх уровней (включая
`CHK-PUNCH-SEQUENCE` и уровень 3 адаптера Графика), архитектурные законы (граф
импортов, чистота домена, независимость конвейеров вкладок, «доска без тяжёлого
конвейера»), четыре режима `view`/чтение/`close`/`recalculate` (truth table 7.2),
R35–R40 (трудоустройство, гранулярность, посев, доска, два плана, yet_to_come),
API и права ролей, бюджет SQL-запросов (доска ≤ 5 батч-запросов; сетка не масштабируется
запросами на сотрудника), ночные отчёты, электрокары, документы, миграции.

CI (`.github/workflows/ci.yml`): ruff + pytest (3.10–3.12) + `node --check` +
контракт API + Docker-сборка, а также смоук интерфейса в jsdom (три роли) и сценарии
действий: «Настройки», норматив 12.10.2026, «График = 4 слоя», обход электрокаров
(`tools/run_night_cars_scenario.sh` — сверяет окно ночной отметки кара с окном возврата
и сохраняет отметку с фото), ночной обход v2 (`tools/run_night_zones_scenario.sh` —
зоны → объекты → чек-лист, шаблон зоны и индивидуальные правки объекта) и «Шахматка»
(`tools/run_stays_scenario.sh` — бронь с предпросмотром, назначение батлеров, «вне
смены» → «Добавить смену», табло дня; под ролями — смоук вкладок и «Мои гости»).
