# Батлер Сервис — система учёта рабочего времени

Светлый веб-интерфейс для службы батлеров: графики смен «ФИО × дни месяца» с блоками смен
и цветами должностей, отметки прихода/ухода кнопками с телефона, автоматический табель
с дневными (ДЯ) и ночными (ДН) часами, переработками и «банком часов», выгрузка
итогового табеля в **Excel** в формате «ФИО × дни» с ячейками «ДЯ 10 ДН 2».

Учёт ведётся **кратно часу** (округление к ближайшему часу), при этом менеджеры видят
**точное** время каждой отметки. Перерывы и денежные расчёты не ведутся — только часы.

## Быстрый старт

```bash
cd timetrack
pip install -r requirements.txt        # ядро (PDF-движок — отдельно: requirements-pdf.txt)
./run.sh                      # или: python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```
`./run.sh` сам создаёт `.venv`, **доустанавливает недостающие пакеты** и проверяет, что
приложение запускается (поэтому ошибка вида `ModuleNotFoundError: No module named 'docx'`
лечится повторным `./run.sh`). Режимы: `./run.sh --reinstall` (пересоздать окружение),
`PDF=off ./run.sh` (быстрый старт без PDF-движка), `PORT=9000 ./run.sh` (другой порт).

PDF заявлений — **необязательная** функция: `brew install --cask libreoffice` (точный вид бланка)
или `pip install -r requirements-pdf.txt` (встроенный рендер). Без них работают DOCX и печать
через браузер — приложение не ломается.

Откройте http://127.0.0.1:8000 — при первом запуске база создастся и заполнится демо-данными
(11 сотрудников, 4 блока графика, графики на 3 месяца, отметки за полтора месяца).

> При старте с более старой версией база **мигрирует автоматически** (схема дополняется при
> запуске сервера, данные сохраняются: блоки «Администрация» переименовываются в «Пятидневку»,
> по датам приёма/увольнения создаются периоды работы, словарю докладываются новые смены).
> Самодиагностика схемы: http://127.0.0.1:8000/api/selfcheck.

## Возможности

### 1. График (менеджеры правят, батлеры смотрят)
* Сетка **ФИО × дни месяца**, сгруппированная по блокам: **«Смена 1»**, **«Смена 2»**,
  **«Пятидневка»** (бывшая «Администрация»), **«Другие смены»**. Заголовки блоков и колонка
  ФИО закреплены: при горизонтальной прокрутке они остаются на месте. Кнопка «Сегодня»
  открывает текущий месяц и докручивает сетку до сегодняшней колонки.
* **Цвета должностей**: батлер — серый, старший батлер — оранжевый, менеджер/документооборот —
  жёлтый, ночная бригада — серо-синий (плюс своя палитра). Цвет виден полосой у ФИО, точкой
  у должности и в строках табеля. Переключатель «Цвет смен / Цвет должностей» меняет заливку
  рабочих ячеек всей сетки.
* **Базовый цикл объекта** задаётся только для Смены 1/2 (2/2, 3/3… в противофазе).
  У **«Пятидневки»** выходные назначаются каждому сотруднику отдельно (у начальника вс/пн,
  у бэк-специалиста сб/вс) — в карточке: «Перевод в блок». **«Другие смены»** — контейнер
  индивидуальных графиков: 3/3, 1/3, сутки через трое, произвольный цикл «РРВВРВ» или ручное
  заполнение; шаблон указывается там же и виден подписью в блоке сетки.
* **Вид «План / Факт»**: факт показывает в ячейках интервалы реальной работы («08–12 15–24»),
  отклонения (опоздание, ранний уход, несогласованный перерыв, переработка, «смена не закрыта»),
  отсутствия и незакрытые смены «прямо сейчас». Из редактора ячейки можно зафиксировать
  неявку (НН) одним кликом.
* Клик по ячейке — редактор: рабочая смена, выходной, больничный, отпуск, отпуск за свой счёт,
  выходной за часы, выходной оплачиваемый + примечание.
* **«Отпросился» — частичное отсутствие** внутри рабочей смены (например с 14:00 до 16:00):
  план дня уменьшается на согласованное окно, отметки внутри него НЕ дают опозданий и ранних
  уходов, несогласованным перерывом не считаются, а часы списываются с банка (без предупреждений).
  Печатается заявление «об отсутствии на рабочем месте» с `{from_time}`/`{until_time}`.
* **«Назначить отсутствие» на период любой длины** — в т.ч. через границы месяцев (с 28.09
  по 05.10): график заполняется целиком, экран переходит к началу периода; заявление на печать
  находит весь период, а не только открытый месяц. Есть режим «только на рабочие дни»
  (для отгулов и отпуска за свой счёт).
* **Периоды работы**: приём → увольнение → **повторный приём** с любой даты. В сетке видны
  смены до увольнения, неактивные дни между периодами и активные дни после нового приёма;
  отметки вне периодов работы запрещены. Вся история (табель, документы) сохраняется.
* **Корпоративные бланки документов**: загрузите свой .docx (шрифты, подложка, колонтитулы)
  с плейсхолдерами `{full_name}`, `{full_name_genitive}`, `{date_from_ru}`, `{days_word}`,
  `{nationality}`, `{subdivision}`, `{department}`, `{from_time}`, `{until_time}`, `{hours}`… —
  из ячейки графика скачивается заполненное заявление в DOCX или **PDF, который собирается на
  сервере** (LibreOffice, а без него — встроенный рендер со шрифтами DejaVu из `assets/fonts/`)
  и открывается в новой вкладке готовым к печати. Документы доступны для всех отсутствий,
  у которых в словаре смен указан тип заявления: оплачиваемый отпуск, отпуск за свой счёт,
  выходной за отработанные часы, «отпросился». Кнопка «Пример .docx» в настройках отдаёт
  готовый образец; «ФИО в родительном падеже» хранится в карточке сотрудника, при пустом
  поле — склоняется автоматически. Инструкция: `docs/TEMPLATES.md`.
* **Любые циклы графиков**: 2/2, 3/3, 4/2, 4/3, 1/3, сутки… и **произвольная последовательность**
  «РРВВВВРР» / «ВВРРРРВВ» (режим «Произвольный цикл» с живым предпросмотром) — любые переходы
  «смена-смена», включая несимметричные недели.
* **5/2 и 6/1 с выбором выходных дней недели** (например, пн+вт вместо сб+вс).
* Сдвиг фазы для бригад, копирование периода, «только пустые ячейки», печать.
* **Печать и PDF**: кнопка «Печать» открывает чистое окно с сеткой месяца (альбомная A4);
  кнопка **PDF** скачивает тот же график файлом — сервер собирает DOCX и конвертирует
  его в PDF (LibreOffice, а без него встроенный рендер; если движка нет — подскажет,
  что поставить, а «Печать» и Excel работают всегда).
* **Батлеры видят график только на просмотр**: та же сетка плана (цвета, коды смен,
  блоки), но без отметок, переработок, часов и банка; ячейки не кликаются, менеджерских
  кнопок нет, сверху — плашка «только просмотр». Отметки и «Кто на работе» — как раньше.
* **Любые часы работы**: словарь смен пополняется в «Настройках» (08:00–17:00, 09:00–18:00,
  ночные, сутки…) — с авторасчётом длительности и признаком «через полночь».
* Адаптив: телефон (портрет и ландшафт), планшет, десктоп; PWA — ставится на главный экран.

### 1b. Сотрудники: карточка, банк часов, словарь смен
* В карточке: **гражданство**, **подразделение/служба** (для официальных документов) и
  департамент — попадают в заявления через `{nationality}`, `{subdivision}`, `{department}`;
  периоды работы, история должностей, переводы между блоками (с шаблоном графика),
  контакты близких.
* **Ручные корректировки банка часов** (+/−) — только администратор и менеджер, с обязательной
  причиной («почему»), датой действия и автором; каждая правка видна в карточке и в аудите.
* **Словарь смен не ломает прошлое**: «удаление» смены = архив (прошлые графики и табели
  продолжают по ней считаться, в новых ячейках она недоступна, можно вернуть из архива);
  изменение часов создаёт ревизию — отработанные дни остаются посчитанными по прежним
  значениям, новые действуют с указанной даты. У отсутствий настраивается тип заявления,
  признак «списывать часы из банка» и **можно ли работнику жать «Пришёл»/«Ушёл»** во время
  этого отсутствия (например, в отпуске отметки запрещены — кнопка в «Моих отметках»
  становится серой с подписью «сейчас статус: …»). При назначении отсутствия на ячейку
  или период флаг можно переопределить индивидуально («как в словаре / разрешить / запретить»).
* **Справочники «Департаменты» и «Службы/подразделения»** (Настройки): добавление,
  переименование, удаление. В карточке сотрудника служба выбирается из справочника;
  переименование обновляет карточки, удаление — очищает поле. Значения попадают в документы
  (`{department}`, `{subdivision}`).

### 2. Отметки сотрудника
* Большие кнопки **«Пришёл на работу» / «Ушёл с работы»**, карточка смены, «вы на смене N ч»,
  отработано/ночные/переработка сегодня, банк часов, история отметок.
* Отметиться можно только в период работы (до приёма / после увольнения система не пускает).
* Если у вида отсутствия (или у конкретной ячейки) запрещены отметки — кнопка неактивна,
  показан текущий статус («сейчас статус: отпуск — отмечать приход запрещено»), а попытка
  отметиться через API отклоняется (409). Менеджерские корректировки не блокируются.
* Раздел **«Кто на работе»** — реальный check-in прямо сейчас (кто пришёл и ещё не ушёл,
  с какого времени, сколько уже работает, план до) — **доступен всем ролям**, включая
  рядовых сотрудников; обновляется каждые 30 секунд. В карточках — **кликабельные контакты**:
  телефон (`tel:`) и Telegram (`t.me`), чтобы сменщику можно было позвонить/написать одним нажатием.
* Если после ухода есть переработка — система предлагает **описать переработку**:
  «с кем работал, что делал». Описание попадает в табель и на отдельный лист Excel.
  Добавить/изменить описание можно позже из истории (кнопка «★ описание»).
* Менеджер может поставить или исправить отметку за сотрудника, в т.ч. задним числом (аудит).

### 3. Посещения (контроль)
* «Кто сейчас на смене» — живые карточки: точный приход, длительность, план до
  (для сотрудников то же самое в разделе «Кто на работе»).
* Таблица за день: план, точный приход/уход, зачтённые часы, переработка, статусы
  (опоздание, ранний уход, нет отметок, смена не закрыта, работа вне графика).
* Менеджер может **отменить ошибочную отметку** (✕ у времени прихода/ухода):
  отметка удаляется, день табеля пересчитывается, действие попадает в аудит.

### 4. Табель и выгрузки
* Кнопка **PDF** рядом с «Печать»: сводка план/факт/ДЯ/ДН/переработки/недоработки/отгулы/банк
  со строкой ИТОГО — тем же конвейером DOCX→PDF, что и график.
* План / факт / ДЯ / ДН / переработка / недоработка / отгулы / **банк часов**; итоги по объекту;
  раскрытие строки — расшифровка по дням с предупреждениями движка и описаниями переработок.
  Банк = стартовый баланс + переработки − отгулы/недоработки − списанные «отпросился» часы
  ± ручные корректировки.
* Блок «Требует внимания».
* **Excel (xlsx)**: лист «Табель» — сетка `ФИО | 01.09 | 02.09 | … | ДЯ | ДН | Всего | Перераб. |
  Недораб. | Отгулы | Банк`, в ячейках «ДЯ 10 ДН 2» / коды отсутствий (В, Б, ОТ, ДО, НВ, ОВ, НН);
  лист «Переработки» — дата, сотрудник, часы, «с кем работал / что делал».
* **CSV** той же сеткой («;» + BOM — открывается в Excel).
* **Дни двойной оплаты (ДЯ2/ДН2)**: производственный календарь (отдельные списки для сменных
  графиков и пятидневки, «на год вперёд», правка по ходу года) и ВИП-периоды сотрудников;
  переработки таких дней выводятся к оплате кодами ДЯ2/ДН2 по двойному тарифу; списания из
  двойных часов снимаются вполовину (8 часов оплаты = 4 часа ДЯ2). В выгрузках — колонки
  ДЯ2/ДН2 и «Всего к выплате» в одинарных часах.

### 5. Настройки (администратор)
* Словарь смен (создание/правка любых часов, архив вместо удаления, ревизии с датой
  вступления, тип заявления, «часы из банка» и разрешение отметок у отсутствий).
* **Виды заявлений — расширяемый справочник**: встроенные (отпуск, отпуск за свой счёт,
  выходной за часы, «отпросился») + свои виды (код, название, текст с плейсхолдерами
  `{full_name_genitive}`, `{period_ru}`…). У каждого вида — свой фирменный бланк .docx
  (перекрывает текст, сохраняя шрифты/логотип/колонтитулы) и образец для скачивания.
  Вид привязывается к отсутствию в словаре смен — документы печатаются из ячейки графика.
* Справочники **департаментов** и **служб/подразделений** (добавление/переименование/удаление).
* Базовый цикл объекта — только Смена 1/2; шаблоны пятидневки и «других смен» задаются
  у каждого сотрудника.
* Правила расчёта (правятся в интерфейсе, применяются после «Пересчитать»):

| Правило | По умолч. | Смысл |
|---|---|---|
| `round_mode` | `nearest` | округление факта к ближайшему часу (`floor`/`ceil` тоже) |
| `round_step_min` | `60` | шаг округления — учёт кратен часу |
| `grace_minutes` | `5` | допуск опоздания для статуса |
| `late_by_raw_time` | `0` | `1` — опоздание по точной отметке, а не по округлённому часу |
| `count_early_arrival` | `0` | засчитывать часы до начала смены |
| `count_late_departure` | `1` | часы после конца смены = переработка |
| `auto_close_missing_out` | `1` | нет «Ушёл» → закрыть плановым временем + предупреждение |
| `night_start` / `night_end` | `22:00` / `06:00` | ночной период (ДН), ст. 96 ТК РФ |
| `night_reduce_hours` | `0` | сокращать ночную смену на 1 ч без отработки |
| `punch_window_before_h` / `after_h` | `4` / `6` | окно приёма отметок вокруг смены |

* **Дни двойной оплаты (производственный календарь) и ВИП-гости**: bulk-добавление дат
  (списком или периодом с фильтром по дням недели), списки «сменные / пятидневка / все»,
  периоды двойных переработок по сотрудникам; любая правка сразу пересчитывает табель.
* Журнал аудита: кто и когда менял график, отметки, правила.

## Правила расчёта (как считает движок)

1. **Округление**: 08:12 → 08:00, 19:50 → 20:00. Точное время отметок сохраняется и видно
   менеджерам; в табель идут округлённые часы.
2. **Смена относится к дате начала.** Ночная 22.09 20:00–08:00 = рабочий день 22.09
   (22.09 20:00–24:00 + 23.09 00:00–08:00) — как в официальном табеле.
3. **День + оставшись в ночь**: если сотрудник отработал дневную смену и остался в ночную
   (или стоит в ночь, но отработал и день), все часы и вся переработка записываются в день
   начала смены — «как будто он был в день».
4. **ДН** = часы 22:00–06:00, **ДЯ** = 06:00–22:00. Часы всегда целые.
5. **Переработка** = факт − план (в день начала смены); **недоработка** фиксируется отдельно;
   банк часов = стартовый баланс + переработка − «выходные за часы» − недоработка.
6. **Отсутствия**: больничный (Б), отпуск (ОТ), за свой счёт (ДО), выходной за часы (НВ,
   списывает из банка длительность смены по графику), оплачиваемый выходной (ОВ), неявка (НН),
   «отпросился» (согласованное окно внутри смены: план уменьшается, часы списываются с банка).
7. Пересечения отметок склеиваются (двойные часы не суммируются), короткие «случайные»
   сессии игнорируются, будущие дни не считаются неявкой.
8. Перерывы и деньги в системе не ведутся (часы «как есть») — по требованию заказчика.

Тесты (`tests/`, 120 проверок) фиксируют каждое правило числами, включая марафон
«день+ночь = 24 ч в один день», произвольные циклы графиков, отсутствие через границы
месяцев, «отпросился» без опозданий, повторный приём, корректировки банка, архив и ревизии
словаря смен.

## Продакшен-заметки

* БД: SQLite по умолчанию; для боевого режима `DATABASE_URL=postgresql://…` в `.env`.
  Для SQLite автоматически включается **WAL** и `busy_timeout=10000` — одновременные
  отметки на пересменке не блокируют чтение и не падают с «database is locked».
* Часовой пояс объекта: `APP_TZ` (по умолчанию `Europe/Moscow`). Все бизнес-даты
  (статусы дней, «кто на работе», даты в документах, банк часов) считаются в нём,
  независимо от TZ сервера; в Docker `TZ` выставляется из `APP_TZ`.
* Секрет сессий: `SECRET_KEY` — **обязательно** задайте уникальный (генерация:
  `python -c "import secrets; print(secrets.token_hex(32))"`); при старте со значением
  по умолчанию сервер пишет предупреждение. `setup_macos.sh` генерирует ключ сам.
* Docker: БД и загруженные бланки заявлений (`templates/`) лежат в томах —
  пересборка образа данные не теряет.
* Бэкапы: регулярно копируйте файл БД (`sqlite3 timetrack.db ".backup backup.db"`)
  или snapshot тома; в базе — персональные данные.
* Telegram-бот подключается как ещё один клиент API (`POST /api/punches`, `source=telegram`).
* Зарплатный модуль намеренно не ведётся; при необходимости ставки и доплаты добавляются
  отдельным слоем поверх готовых почасовых данных табеля.
