# Изменения 16.10.2026 — значения Табеля плашками: только коды и часы из справочников

Редактор ячейки «Слой 0 · Табель» предлагал выбрать код дня из выпадающего списка
и вручную ввести плановые часы. Часы, которых нет в CFG-WINDOWS, сервер честно
отклонял (CHK-WINDOW-EXISTS, 16.5) — но пользователь узнавал об этом только
после попытки сохранения: введённое значение нельзя было сохранить, а подсказка
объясняла причину постфактум. Предложение владельца: убрать список и ручной ввод,
показать значения справочников плашками — «Я 10,75», «Я 9», «Я 8», «К 10,75»,
«ОТ», «В» и т.д.

## Что сделано

- **Фронтенд** (`section_v4.js`, `tabelCellModal`): вместо пары
  «select кода + input часов» — облако плашек, собранных строго из справочников:
  * код без часов (CFG-DAY-CODES) — одна плашка («В», «ОТ», «ДО», «Б», «НН»…);
  * код с часами — по плашке на каждую строку CFG-WINDOWS («Я 8», «Я 9», «Я 12»,
    «К 12»…), в подсказке плашки — подпись кода и границы окна (08:00–20:00);
  * «✕ Очистить» — прежнее «— очистить ячейку —»;
  * код с часами, у которого нет ни одной строки окон, показан отключённой
    плашкой с объяснением (значение нельзя задать, пока окно не добавлено
    в «Настройках») — раньше такой код выбирался и падал в 422 после ввода часов.
  Плашка и есть значение: часы вне справочника ввести невозможно, невалидная
  комбинация не уходит даже в запрос. Цвет плашки — цвет кода Табеля
  (`v4CodeColor`, payload настроек → `cssColor`).
- **Состояние модалки**: текущее значение ячейки предвыбирается плашкой;
  старое значение вне справочника (legacy) не подсвечивается и показывается
  строкой «Сейчас в ячейке: …» — сохранение требует явного выбора. Строка под
  плашками показывает выбранное значение с подписью кода и окном. Блок печати
  заявления появляется, как и раньше, только для кода отсутствия с заявлением;
  пустой код («Очистить») теперь заведомо не матчится с видами смен без кода
  Табеля (tzh_code = '' — потенциальное ложное срабатывание прежнего `kindOfCode('')`).
- **Поля «Применить по число месяца» и «Примечание», печать DOCX/PDF — без изменений.**
- **Бэкенд** (`app/api/tabel_api.py`): GET /api/tabel дополнительно отдаёт
  `windows` — границы окна по каждому значению CFG-WINDOWS (`{"Я 12": ["08:00","20:00"]}`)
  для подсказок плашек. Валидация записи не менялась: те же доменные проверки
  (check_known_day_codes / check_plan_minutes / check_day_values), вторых копий
  правил на стороне записи нет (16.5, дух антипаттерна 12.23).
- **CSS**: `.tc-chips/.tc-chip` — форма плашек, состояние выбора (`.sel`),
  «Очистить» (`.clear`) и отключённый код без окон (`.off`).
- Версия статики `2026-10-16b` (index.html ↔ sw.js SHELL).

## Проверки

- `tools/norms_scenario.mjs`: сценарий T3 переведён на плашки и дополнен —
  плашки из справочников есть, ручного ввода часов нет (`#tc-hours`/`#tc-code`
  отсутствуют), текущее значение предвыбрано, в подсказке плашки с часами видно
  окно CFG-WINDOWS, выбор подсвечивается; сохранение «НН» и «ОТ» (T3/Q4)
  работает через клик плашки — 76/76.
- `tests/test_v4_api.py::test_tabel_values_carry_windows`: `windows` в ответе
  GET /api/tabel покрывает все `values`, границы в формате HH:MM и не пересекают
  полночь (3.5).
- Смоук трёх ролей, сценарии «График = 4 слоя» (58/58) и «Настройки» (62/62) —
  без регрессий; `pytest` — 515 passed; ruff, eslint, контракт API, openapi — OK.

Путь пользователя был: ячейка → список → ввести часы → 422 «нет строки окна» →
поиск допустимых часов в подсказке. Стал: ячейка → плашка «Я 10,75» → сохранить.
