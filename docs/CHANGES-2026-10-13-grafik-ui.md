## Навигация: один пункт «График» с четырьмя слоями (Q2)

- **Меню** (`static/js/app.js`): прежние четыре пункта (График, Факт, Табель,
  Управленческий табель) объединены в один — «График» (иконка слоёв). Пункт виден,
  если есть право хотя бы на один слой. Доска **«Отметки» остаётся отдельным пунктом
  меню (Q7)**.
- **Слои** (`GRAFIK_LAYERS`): панель вкладок над экраном —
  **0 · Табель** (первоисточник, бухгалтерия) → **1 · План / График** (операционный
  план, флаги) → **2 · Факт** (отметки, округление до шага) → **3 · Управленческий
  Табель** (результат, банк, закрытие). Каждый слой показывает только то, на что у
  роли есть право (`tabel.view`, `schedule.view`, `presence.view`, `mgmt.view` —
  модель прав не менялась). Слой по умолчанию — 1 · План/График (как прежний раздел
  «График»).
- **Сборка существующих экранов**: слои — это прежние разделы без изменения логики
  (панели вложены в обёртку `#view-grafik`, `index.html`); заголовки дополнены
  номером слоя («Слой 0 · Табель» и т.д.). Старые имена разделов работают как алиасы:
  `navigate('timesheet')`, `navigate('schedule')`, `navigate('fact')`,
  `navigate('mgmt')` открывают «График» на нужном слое — глубокие переходы из
  модалок (например, «В Табель» из ячейки Графика) и сценарии не сломаны.
- **CSS** (`static/css/app.css`): стили панели слоёв (`.layer-tabs`, `.layer-tab`,
  `.layer-pane`) и чипов сетки «Номера» (`.punch-chip`, `.seg-chip`); на узких
  экранах подписи слоёв скрываются, остаются номера.

## Слой 2 · Факт: сетка «Номера» (Q7) + прежние «Сессии»

- **Режимы слоя** (`static/js/section_v4.js`): переключатель «Номера» / «Сессии».
  «Сессии» — прежняя история «пришёл — ушёл» без округления (16.4), перенесена без
  изменений. «Номера» — новый экран дня по нормативу 12.10.
- **`GET /api/fact/day?date=`** (`app/api/fact_api.py`): один день глазами движка для
  всех трудоустроенных в этот день сотрудников (R35); не-менеджер видит только себя
  (как в истории сессий). В строке:
  * `marks` — сырые отметки СКУД (локальное время) и их округление `rounded` —
    то же правило `to_calc_mark`/RUL-ROUND-MOMENTS, что в расчёте;
  * `segments` — сопряжённые сессии после округления (ядро `pair_marks` c
    opening-отметкой, R31/R32), обрезанные границами дня; открытая сессия помечена;
  * `card` — карточка дня из `settle` периода, содержащего день (`view_period`;
    закрытый период читается из сохранённых результатов без пересчёта):
    значение Табеля, **окно из кода Табеля (Q1 — жёстко, CFG-WINDOWS)**, план
    (длина окна, R34), план строки (R39), факт, отработано (факт ∩ окно),
    недостача, переработка и коды ДЯ/ДН (границы категорий — из настроек,
    замечание 2), «План=Факт», флаги из Графика (`evaluate_flags`);
  * `error` / `out_of_staff` — типизированный отказ движка (например,
    «Сначала закройте предыдущий период») показывается в строке, отметки при этом
    видны; день вне трудоустройства — «не в штате».
  * `step_minutes` — шаг из настроек периода: **интерфейс ничего не пересчитывает и
    шаг не переключает** (в прототипе переключатель 15/30/60 был демо-упрощением,
    риск 4 ревью: источник истины — движок и его настройки).
- **Таблица «Номера»**: Сотрудник · Отметки (СКУД → округление) · Окно (из Табеля) ·
  План · Отработано · Недоработка · Переработка · Флаги (из Графика) — состав колонок
  как в согласованном прототипе (v2.1, слой 2). Навигация по дням (‹ ›, дата,
  «Сегодня»), в шапке — шаг округления и период расчёта.
