# Изменения 15.10.2026 (батч 3) — доска и личный экран: одна правда по времени

## Дефект доски (найден владельцем на тестовой базе, 15.10.2026 ~11:01)

Доска «кто на работе» показывала сотрудника «на работе с 07:53», хотя он ушёл
(последняя по времени отметка — OUT 08:25), а личный экран показывал «не на
работе». Причина: батч-запрос `last_marks` брал последнюю отметку как
`MAX(Punch.id)` — по порядку создания строк, а не по времени. Порядок создания
расходится с порядком ts штатно: отметки задним числом; сид суточных смен
(ночная сессия закрывается OUT'ом позже, чем создаётся IN следующей смены).

Фикс (`app/engine/adapters/sql_punch.py`): оконная функция
`row_number() OVER (PARTITION BY employee_id ORDER BY ts DESC, id DESC)` —
по-прежнему один батч-запрос (бюджет 16.2 цел). Данные править не нужно:
фикс читает ту же таблицу правильно.

Почему не ловилось: фейки портов (`tests/engine/fakes.py`) реализуют контракт
7.4 корректно — ломался только SQL-адаптер; API-тесты не подавали отметки вне
порядка ts.

## Выравнивание окон (решение владельца: смены до ~3 суток — норма)

Личный экран искал открытую сессию в окне «план − 4 ч», доска — по всей
истории: при длинных сменах экраны расходились, а личный экран предлагал
«Пришёл» поверх открытой сессии (дубль IN, который sanitize отбрасывает, —
данные всё равно склеивались до правки менеджером). Окно удалено: открытая
сессия = последняя по (ts, id) отметка является IN — едино для доски, личного
экрана, кнопки и «авто» (ADR-0009). Побочно: явный «Пришёл» при любой открытой
сессии теперь отклоняется (409) — дубли IN перестали протекать в данные;
`is_late` корректен для многосуточных смен.
