# Release Verification and Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify all remediation PRs together, publish a release, and deploy it safely when target access is available.

**Architecture:** Verification runs from a clean main checkout after PRs 1–6 merge. The release commit only changes version/cache metadata; deployment uses the documented tagged compose flow after backup and rollback checks.

**Tech Stack:** GitHub CI, pytest, Ruff, mypy, ESLint, Docker Compose, Playwright/Chromium, Git tags.

**Spec:** `docs/superpowers/specs/2026-11-23-pr224-238-remediation-design.md`

## Global Constraints

- Never claim green without fresh command output.
- Never deploy an untagged or CI-failing commit.
- Never deploy before a fresh encrypted backup and known rollback path.

## Review Focus

- Alembic upgrades a database containing multiple distinct deferred rows.
- Service-worker update replaces old unversioned JavaScript in an existing browser profile.
- All custom permission roles render only authorized guest data/actions.
- Desktop and 375px mobile flows have no overlay or FAB collisions.
- Production health and representative authenticated flows work after deployment.
