# Release Verification and Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify all remediation PRs together, publish a release, and deploy it safely when target access is available.

**Architecture:** Verification runs from a clean main checkout after PRs 1–6 merge. The release commit only changes version/cache metadata; deployment uses the documented tagged compose flow after backup and rollback checks.

**Tech Stack:** GitHub CI, pytest, Ruff, mypy, ESLint, Docker Compose, Playwright/Chromium, Git tags.

**Spec:** `docs/superpowers/specs/2026-11-23-pr224-238-remediation-design.md`

## Global Constraints

- Never claim green without fresh command output.
- Never deploy an untagged or CI-failing commit.
- Never deploy before a fresh encrypted backup and known rollback path.

## Review Focus

- Alembic upgrades a database containing multiple distinct deferred rows.
- Service-worker update replaces old unversioned JavaScript in an existing browser profile.
- All custom permission roles render only authorized guest data/actions.
- Desktop and 375px mobile flows have no overlay or FAB collisions.
- Production health and representative authenticated flows work after deployment.

---

### Task 1: Full local verification

**Files:**
- Modify only if a verification failure reveals a regression in PRs 1–6.

**Interfaces:**
- Produces: captured pass evidence for every required suite.

- [ ] Rebase/update from merged main and confirm `git status --short` is clean.
- [ ] Run `ruff check app tests`, `mypy app`, `npm run lint`, full `pytest`, compose config checks, and API contract checks.
- [ ] Run the full Playwright matrix with system Chromium and retain failure traces.
- [ ] Diagnose any failure with `superpowers:systematic-debugging`, fix it in the owning PR/follow-up, and repeat the failed plus full relevant suite.
- [ ] Inspect admin, manager, names-only, occupancy-only, and butler flows at desktop and 375px widths.

### Task 2: Version/cache release PR

**Files:**
- Modify: `static/index.html`
- Modify: `static/sw.js`
- Modify: project version source identified by `tools/bump_version.py`.

**Interfaces:**
- Produces: one release commit/tag whose app version and service-worker shell version agree.

- [ ] Run the repository version-bump tool once and inspect its diff.
- [ ] Run cache-update Playwright smoke using an existing browser profile controlled by the previous service worker.
- [ ] Re-run required CI-equivalent checks.
- [ ] Commit, push, open the release PR, wait for CI, fix failures, and merge.
- [ ] Tag the exact merged commit and push the tag after CI is green.

### Task 3: Production deployment

**Files:**
- No repository changes unless deployment documentation is proven incorrect.

**Interfaces:**
- Consumes: release tag, production target, encrypted backup configuration, and documented compose commands.
- Produces: deployed healthy version or an exact handoff when access is unavailable.

- [ ] Resolve the production target and verify current version, credentials, compose project, and rollback owner without changing state.
- [ ] Create a fresh encrypted backup and verify the artifact; confirm restore-check/rollback instructions and previous tag.
- [ ] Check out the release tag and run `docker compose -f docker-compose.prod.yml up -d --build`.
- [ ] Verify compose health, `/api/health` version, login, chessboard icons/Guests section, print, and one non-destructive representative flow.
- [ ] If health checks fail, collect logs and roll back using the verified previous tag/database recovery rule.
- [ ] Report deployed tag, health evidence, backup artifact reference, and any follow-up.
