# Non-root Backup Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the non-root backup container start correctly in local-only and remote-copy modes with actionable credential diagnostics.

**Architecture:** SSH setup is conditional on `BACKUP_REMOTE`. Remote credentials are validated and copied into the backup user's home with strict permissions; local-only mode never touches SSH mounts.

**Tech Stack:** POSIX shell, Docker Compose, pytest subprocess tests.

**Spec:** `docs/superpowers/specs/2026-11-23-pr224-238-remediation-design.md`

## Global Constraints

- Keep the container non-root and encrypted-backup behavior unchanged.
- Do not suppress host ownership failures in documentation.
- Test both execution modes without contacting a real remote server.

## Review Focus

- Missing SSH mount is valid when `BACKUP_REMOTE` is empty.
- Unreadable private key fails before the backup loop with a precise message.
- Destination key is mode `0600` and owned by the backup user.
- Missing/unreadable `known_hosts` fails in remote mode.
- An unwritable `/backups` directory remains a hard failure.
