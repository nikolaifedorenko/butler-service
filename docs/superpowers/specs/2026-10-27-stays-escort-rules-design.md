# Шахматка (stays), часть 3: сопровождение по правилам — дизайн

**Статус:** черновик на ревью владельца, 27.10.2026. Решения владельца собраны в обсуждении
25–27.10.2026; открытые вопросы — §8. Опирается на часть 1 (версии фонда, дерево групп).

## 1. Зачем

Сейчас «нужен ли батлер» решает один флаг категории «с сопровождением» и флаг брони «гость
отказался». В работе сопровождение назначается по нескольким признакам, и VIP-гость может жить в
категории без сопровождения.

## 2. Решения владельца

Сопровождение нужно, если выполнено **любое** из условий:

1. объект брони — в **категории** с сопровождением;
2. объект — в **узле дерева** с сопровождением (корпус, «Винные виллы», «Японские виллы»…; узел
   действует на всю ветку);
3. у брони **VIP-код** из списка кодов, требующих сопровождения; код **один** — код главного
   гостя (как в Fidelio);
4. среди проживающих есть гость **VIP или VVIP** (уровень профиля, даже без VIP-кода), — **на
   его дни** проживания.

**Ручная отметка в брони перекрывает правила в обе стороны:** «по правилам» (по умолчанию) /
«требуется» / «не требуется (гость отказался)».

## 3. Модель

* **Категория:** `escorted` — уже в версии фонда (часть 1, `stays_category_states`).
* **Узел дерева:** новое поле версии `stays_group_states.escorted BOOL` — меняется с даты, как
  всё в фонде.
* **VIP-коды:** справочник `stays_vip_codes`: `id, code TEXT(16) UNIQUE, title, escorted BOOL,
  sort_order, archived` (не версионируется, как флаги).
* **Бронь:** `vip_code_id → stays_vip_codes NULL`; `escort_mode` = `rules | required | declined`
  вместо `declined_butler` (миграция: `true → declined`, `false → rules`).
* Уровень гостя (`regular | vip | vvip`) — как сейчас в профиле.

## 4. Вычисление

Для брони R в ночь D (`application/escort.py`, чистая функция в `domain/escort.py`):

```
mode = R.escort_mode
если mode == declined → не нужно (причина «гость отказался»)
если mode == required → нужно (причина «отмечено вручную»)
иначе нужно, если хоть одно:
  категория объекта R в ночь D (версия дня) escorted
  какой-либо узел на пути объекта (версия дня) escorted
  vip_code брони escorted
  среди проживающих в ночь D есть vip/vvip
```

Результат — `EscortNeed(required: bool, reasons: tuple[str, ...])`: причины показываются в
карточке и на табло («VIP-гость Петров», «узел Винные виллы», «код V3»).

Брони без объекта (не распределены) — по категории брони и правилам 3–4.

## 5. Где действует

* **Предупреждение «дыра»** — по `EscortNeed` вместо `cat.escorted and not declined`.
* **Табло дня:** статус сопровождения и причина; фильтр «только с сопровождением» — по
  `EscortNeed` на дату.
* **Шахматка объектов и «Брони»:** фильтр «с сопровождением» — бронь, которой нужен батлер хотя
  бы в одну ночь периода.
* **Нагрузка батлера** не меняется: вес категории + надбавки VIP/VVIP (как сейчас).
* **Подбор кандидатов и подмена** — без изменений, только для броней, которым нужен батлер.

## 6. Экраны

* **Настройки → Сопровождение:** список «сопровождают гостей» и надбавки (как сейчас) +
  **справочник VIP-кодов** (код, название, «требует сопровождения», архив) + сводка правил:
  какие категории и узлы с сопровождением на выбранную дату (ссылка на «Фонд» — правятся там,
  черновиком с даты).
* **Фонд (часть 1):** в карточке категории и узла — галочка «с сопровождением».
* **Форма брони:** поле «VIP-код» (выбор из справочника), «Сопровождение: по правилам /
  требуется / не требуется (гость отказался)» с подсказкой, что дают правила на даты брони.

## 7. Права и тесты

* VIP-коды — `stays.setup`; `vip_code` и `escort_mode` брони — `stays.edit`; батлер
  (`stays.mine_res_edit`, часть 4) их **не** меняет.
* VIP-код виден уровню «с фамилиями» и выше; уровню «без персональных данных» — нет (это
  признак человека).
* Тесты: каждое правило по отдельности; «или» правил; узел действует на ветку; узел/категория с
  даты (версия дня); VIP-гость только на свои дни; ручные «требуется» и «не требуется»
  перекрывают; миграция `declined_butler`; дыра и фильтр по новым правилам; утечка VIP-кода на
  уровень occupancy — нет.

## 8. Открытые вопросы (предложение по умолчанию)

1. **VIP-код — на брони или в профиле гостя?** В Fidelio он у профиля главного гостя, но
   владелец сказал «код один, у primary гостя». *Предлагаю: поле брони (как приходит из
   Fidelio вместе с бронью), выбор из справочника; в профиле гостя — уровень VIP/VVIP, как сейчас.*
2. **VIP-гость в брони «не требуется (отказался)»** — ручная отметка главнее? *Предлагаю: да,
   ручная отметка главнее всех правил (как сказано владельцем).*
3. **Узел «с сопровождением», но категория в нём — без** (номер корпуса в «Японских виллах»)?
   *Предлагаю: «или» — нужен батлер.*
