# Шахматка (stays), часть 3: сопровождение по правилам, VIP-коды, «Особый гость» — дизайн

**Статус:** ред. 2, 27.10.2026 — открытые вопросы закрыты ответами владельца (§9). Опирается на
часть 1 (версии фонда, дерево групп).

## 1. Зачем

Сейчас «нужен ли батлер» решает один флаг категории «с сопровождением» и флаг брони «гость
отказался», а нагрузка — вес категории плюс надбавки VIP/VVIP. В работе сопровождение назначается
по нескольким признакам: категория, место в фонде, **VIP-код Fidelio** («03», «13», «14»…) и
наша пометка важного гостя; от кода зависит и сложность работы батлера.

## 2. Решения владельца

Сопровождение нужно, если выполнено **любое** из условий:

1. объект брони — в **категории** с сопровождением;
2. объект — в **узле дерева** с сопровождением (корпус, «Винные виллы», «Японские виллы»…; узел
   действует на всю ветку); узел с сопровождением и категория без — **нужно** («или»);
3. у брони **VIP-код**, у которого в справочнике отмечено «сопровождение»;
4. среди проживающих есть **«Особый гость»** — на его дни проживания.

**Ручная отметка в брони перекрывает правила в обе стороны:** «по правилам» (по умолчанию) /
«требуется» / «не требуется (гость отказался)». Отказ действует и для «Особого гостя» и любого
VIP-кода: дыры нет, в карточке — «сопровождение: отказался».

**VIP-код** — как в Fidelio: живёт в **брони**, берётся из **профиля главного гостя**.

**«Особый гость»** — флаг в профиле гостя вместо трёх уровней обычный / VIP / VVIP: если стоит —
это очень важный гость, сопровождение обязательно (по правилам), вес большой.

**Нагрузка — перемножение коэффициентов:** вес брони в ночь = вес категории × коэффициент
VIP-кода брони × коэффициент «Особого гостя».

## 3. Модель

* **Категория:** `escorted` и `weight` — в версии фонда (часть 1, `stays_category_states`).
* **Узел дерева:** новое поле версии `stays_group_states.escorted BOOL` — меняется с даты, как
  всё в фонде.
* **Справочник VIP-кодов** `stays_vip_codes`: `id, code TEXT(8) UNIQUE, title TEXT(80)` («простое
  сопровождение», «сложный гость»), `escorted BOOL, factor NUMERIC(4,2) ≥ 0.1 DEFAULT 1.0,
  sort_order, archived`. Код — строка цифр, ведущий ноль значим («03» ≠ «3»), сравнение текстом.
  Не версионируется (как флаги); изменение коэффициента действует на все даты.
* **Профиль гостя:** `vip_code_id → stays_vip_codes NULL` и `special BOOL DEFAULT false`
  («Особый гость») вместо `level (regular|vip|vvip)`.
* **Бронь:** `vip_code_id → stays_vip_codes NULL`; `escort_mode` = `rules | required | declined`
  вместо `declined_butler`.
* **Настройки сопровождения:** коэффициент «Особого гостя» `special_factor` (по умолчанию 2.0)
  вместо надбавок VIP/VVIP.
* **Миграция:** `declined_butler true → declined`, `false → rules`; `level vip|vvip → special =
  true`; надбавки VIP/VVIP удаляются (приложение не в проде).

### 3.1 VIP-код брони из профиля

* При создании брони и при смене главного гостя код **копируется** из профиля главного гостя.
* В брони код можно поправить вручную (`stays.edit`).
* Смена кода в профиле предлагает обновить его в **текущих и будущих** бронях, где этот гость
  главный (галочка «обновить в бронях: N», включена по умолчанию; прошлые брони не меняются).
  Обновление — одна операция с предпросмотром (дыры, нагрузка).
* Правила сопровождения и нагрузка смотрят **только на код брони**.

## 4. Вычисление

### 4.1 Нужен ли батлер

Для брони R в ночь D (`application/escort.py`, чистая функция в `domain/escort.py`):

```
mode = R.escort_mode
если mode == declined → не нужно (причина «гость отказался»)
если mode == required → нужно (причина «отмечено вручную»)
иначе нужно, если хоть одно:
  категория объекта R в ночь D (версия дня) escorted
  какой-либо узел на пути объекта (версия дня) escorted
  vip_code брони escorted
  среди проживающих в ночь D есть «Особый гость»
```

Результат — `EscortNeed(required: bool, reasons: tuple[str, ...])`: причины показываются в
карточке и на табло («◆ Особый гость Петров», «узел Винные виллы», «код 13 — полноценное»).

Брони без объекта (не распределены) — по категории брони и правилам 3–4.

### 4.2 Вес брони (нагрузка)

```
weight(R, D) = category.weight(версия дня D)
             × (vip_code брони ? vip_code.factor : 1)
             × (среди проживающих в ночь D есть «Особый гость» ? special_factor : 1)
```

* Нагрузка батлера в день — сумма весов броней, которые он ведёт (как сейчас), сравнение с
  лимитом; вес дробный, показ — с одним знаком («5,5»).
* Коэффициенты перемножаются: «вилла 2 × код 14 (×2) × Особый (×1,5) = 6».
* После миграции лимит нагрузки нужно один раз подобрать заново (подсказка в настройках).
* Бронь «не требуется (отказался)» батлера не требует, но если батлер всё же назначен — вес
  считается тем же правилом.

## 5. Где действует

* **Предупреждение «дыра»** — по `EscortNeed` вместо `cat.escorted and not declined`.
* **Табло дня:** статус сопровождения и причина; фильтр «только с сопровождением» — по
  `EscortNeed` на дату.
* **Шахматка объектов и «Брони»:** фильтр «с сопровождением» — бронь, которой нужен батлер хотя
  бы в одну ночь периода; фильтр «◆ Особый гость» и «VIP-код» вместо «VIP/VVIP» (часть 1 §7).
* **Нагрузка батлера** — по §4.2.
* **Подбор кандидатов и подмена** — без изменений, только для броней, которым нужен батлер.

## 6. Экраны

* **Настройки → Сопровождение:** список «сопровождают гостей» (как сейчас); **справочник
  VIP-кодов** — код, что значит, «сопровождение» да/нет, коэффициент, порядок, архив;
  коэффициент «Особого гостя»; сводка правил — какие категории и узлы с сопровождением на
  выбранную дату (ссылка на «Фонд» — правятся там, черновиком с даты).
* **Фонд (часть 1):** в карточке категории и узла — галочка «с сопровождением».
* **Профиль гостя:** «◆ Особый гость» (галочка), «VIP-код» (выбор из справочника).
* **Форма брони:** «VIP-код» (подставлен из главного гостя, можно поменять), «Сопровождение: по
  правилам / требуется / не требуется (гость отказался)» с подсказкой, что дают правила на даты
  брони.
* **Шахматка, табло, «Брони»:** значок ◆ у особого гостя вместо ★ VIP/VVIP; код — рядом.

## 7. Права и тесты

* VIP-коды и коэффициенты — `stays.setup`; `vip_code` и `escort_mode` брони, «Особый гость» и
  VIP-код профиля — `stays.edit`; батлер (`stays.mine_guest_edit`, `stays.mine_res_edit`,
  часть 4) их **не** меняет.
* VIP-код и ◆ видны уровню «с фамилиями» и выше; уровню «без персональных данных» — нет (это
  признак человека).
* Тесты: каждое правило по отдельности; «или» правил; узел с сопровождением при категории без —
  нужно; узел действует на ветку; узел/категория с даты (версия дня); Особый гость только на свои
  дни; ручные «требуется» и «не требуется» перекрывают, в том числе для Особого гостя и кода с
  сопровождением; код «03» ≠ «3»; код копируется из профиля главного гостя при создании и смене
  главного; обновление кода в профиле меняет текущие и будущие брони, не прошлые; вес —
  произведение (2 × 2 × 1,5 = 6); миграция `declined_butler` и `level`; дыра и фильтр по новым
  правилам; утечка кода и ◆ на уровень occupancy — нет.

## 9. Ответы владельца на открытые вопросы (27.10.2026)

1. **Где VIP-код:** в Fidelio поле живёт в брони, но берётся из профиля главного гостя — так же.
2. **Ручная отметка «отказался» главнее всех правил** — да, в том числе для важных гостей.
3. **Коды настраиваются:** что значит, есть ли сопровождение, вес; «14 — сложный, вес больше; 03 —
   простое сопровождение; 13 — полноценное».
4. **Наша пометка VIP** → флаг **«Особый гость»**: если стоит — супер важный гость с большим
   весом.
5. **Веса не складываются, а перемножаются коэффициенты.**
6. **Узел с сопровождением, категория без** — «или», батлер нужен.
