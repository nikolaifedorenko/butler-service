# Шахматка (stays), часть 2: OOO по половинкам суток, блоки по категориям, пожелания гостей — дизайн

**Статус:** черновик на ревью владельца, 27.10.2026. Решения владельца собраны в обсуждении
25–27.10.2026; открытые вопросы — §9, у каждого предложение по умолчанию.
Опирается на часть 1 (`2026-10-26-stays-fund-versions-design.md`): фонд на дату, части
сегментов на границах версий, дерево групп, флаги объектов, вкладка «Загрузка» (§6.1).

## 1. Зачем

Сейчас OOO и блок устроены одинаково (как в PoC): конкретный объект, целые сутки с–по,
разница только в цвете. В работе отеля это разные вещи:

* **OOO (Out of order)** — конкретная вилла или номер выводится из оборота (ремонт и т. п.).
  Ставится **как бронь, по половинкам суток**: после выезда гостя объект в тот же день уходит в
  OOO, и с заездом так же.
* **Блок** — по сути **групповая бронь без гостей**: «Блок Гендира — семейных вилл столько,
  императорских столько, даты у каждой свои». В Fidelio блок — это категории и количество; нам
  важен **визуальный контроль**: блок виден на шахматке полосами, как бронь, сразу видно, где и
  как будут жить, а свободные объекты не выглядят свободными.

## 2. Решения владельца

* OOO — один объект; половинки суток, как бронь; ставится поверх брони — бронь **вытесняется**
  (уходит в «не распределено», если ей не нашлось другого объекта).
* Блок — **несколько строк**: категория + количество + свои даты; количество может меняться по
  дням. На любую категорию (виллы и номера корпуса).
* Блок раскладывается по объектам **автоматически**, по дням — может «переезжать» между виллами,
  но **старается держаться одной виллы**. Часть блока можно **закрепить** за объектом вручную.
* Блоку **батлер не нужен**: он не участвует в покрытии, дырах и нагрузке.
* Брони к блокам **не привязываются** (в рамках проекта): бронь не «снимается из блока»
  автоматически, менеджер сам правит блок.
* Объектов не хватает только при «минусе» — тогда **предупреждение**, решает пользователь
  (правит блок или OOO).
* Блоки и OOO видны **всем уровням, с названиями** — персональных данных в них нет.

## 3. Модель

### 3.1 OOO

`stays_ooo`: `id, unit_id → stays_units, start DATE, end DATE, start_half (AM|PM), end_half
(AM|PM), reason TEXT(120), version INT, created_at, author_id`.

* Ввод как у брони: «с» по умолчанию **PM** (с вечера дня выезда), «по» — **AM** (до утра дня
  заезда); галочки «с утра» (`start_half = AM`) и «до вечера» (`end_half = PM`) — сутки целиком.
* Интервал занятости `[pos(start, start_half), pos(end, end_half)]`; `end ≥ start`, при
  `start == end` нужна пара `AM..PM` (полсуток минимум — одна половинка).
* OOO на дни, когда объекта нет в фонде, — 422 «объекта N нет в фонде дд.мм–дд.мм».
* Пересечение двух OOO одного объекта — 409.

### 3.2 Блок

`stays_blocks`: `id, title TEXT(120), note TEXT, color (необязательно, по умолчанию цвет блока),
version INT, created_at, author_id`.

`stays_block_lines`: `id, block_id, category_id → stays_categories, start DATE, end DATE,
start_half, end_half, quantity INT ≥ 1`.

* Строка — «столько объектов категории X на этот интервал». Количество меняется по дням
  **несколькими строками** одной категории: «VEG ×3 01.10–10.10», «VEG ×5 11.10–20.10».
  Строки одной категории **могут** пересекаться — количество на ночь складывается.
* Половинки суток — как у брони и OOO (по умолчанию PM..AM).
* `stays_block_pins`: `block_id, category_id, slot INT, start DATE, end DATE, unit_id` —
  ручное закрепление «слота» блока (см. §4.2) за объектом на интервал.

Нынешние `stays_holds` миграция переводит: `kind = ooo` → `stays_ooo` (целые сутки:
`AM..PM`); `kind = block` → блок с одной строкой (категория объекта на дату начала,
количество 1) и закреплением на этот объект. Приложение не в проде — перенос без истории.

## 4. Распределение

### 4.1 Слоты блока

Блок превращается в **слоты** — «виртуальные брони» без гостей. На каждую ночь блок требует
`Σ quantity` строк категории на эту ночь; слот `k` категории X существует в те ночи, где
требуемое количество ≥ k. Слоты нумеруются с 1, непрерывные интервалы слота — его **сегменты**
(как у брони; режутся на границах версий фонда как части, часть 1 §5).

Пример: «VEG ×3 01–10, VEG ×5 11–20» → слоты 1–3 на 01–20, слоты 4–5 на 11–20.

### 4.2 Порядок и приоритеты

Распределитель (`domain/allocate.py`) получает: OOO (как занятость объекта, жёстко), брони,
слоты блоков. Порядок назначения:

1. **OOO** — занимает объект безусловно. Бронь или слот, закреплённые на объект под OOO, —
   предупреждение `pin_conflict_ooo`, закрепление на эти дни не действует, часть уходит в
   автораспределение.
2. **Закрепления** броней и слотов.
3. **Брони** — по правилам части 1 (+ §4.3).
4. **Слоты блоков** — тем же first-fit, после броней.

Брони раньше блоков: реальные гости важнее резерва (вопрос §9.1). Чего не хватило —
предупреждение и «не распределено»:
* бронь — `unassigned` (как сейчас);
* слот блока — `block_short`: «Блок Гендир: не хватает 1 VEG на 10–12.11».

### 4.3 Правила выбора объекта (уточнение части 1)

При равных возможностях объект выбирается по приоритетам:

1. закрепление;
2. **непрерывность**: часть того же сегмента и следующий день слота — в том же объекте;
3. **пожелание гостя** (§5) — только для броней;
4. **меньше оборотов в день (HK)**: заезд не ставится в объект, где в этот же день выезд, если в
   той же категории есть объект, свободный со вчера;
5. первый по порядку (категория, натуральная сортировка номера).

Правило 4 — мягкое: если выбора нет, оборот допускается.

### 4.4 Прошлое

Как в части 1: части, закончившиеся до сегодня, заморожены — и брони, и слоты блоков.

## 5. Пожелания гостей при распределении

`stays_guest_prefs`: `guest_id, kind (group|flag|unit), ref_id, priority INT` — в профиле
гостя: «предпочитает: Первая линия», «Тихая сторона», «вилла 4011». Узел — вся ветка; флаг —
по версии фонда дня; объект — по постоянному id (после деления — по `lineage`, часть 1).

Бронь учитывает пожелания **главного гостя** (вопрос §9.3); мягко: сначала объекты, где выполнено
больше пожеланий (по `priority`), иначе — любые. На карточке брони — «пожелание выполнено / нет».

## 6. Отображение

* **Шахматка объектов:** OOO — красная полоса по половинкам с причиной; слоты блока — полосы
  цвета блока с пунктиром и названием блока, соседние ночи одного слота в одном объекте — одна
  полоса. Клик по полосе блока — карточка блока (строки, сколько разложено, нехватка).
* **Вкладка «Загрузка»:** строки «OOO» и «Блоки» (часть 1 §6.1) — по половинкам суток: ночь D
  занята, если занята половинка PM дня D.
* **Список блоков** — в карточке «Блоки» на вкладке «Брони» (фильтр «показывать блоки») или
  отдельной кнопкой «Блоки» на шахматке (вопрос §9.4).
* **Табло дня:** OOO, начинающиеся/заканчивающиеся сегодня, — в списке «Требуют внимания».

## 7. Операции и права

* Создание/правка/удаление OOO и блоков — `stays.edit`, с **предпросмотром** (`run_operation`):
  кто вытеснен, куда переехал, что осталось без объекта, где нехватка блока.
* Закрепить слот блока — из карточки блока или перетаскиванием полосы (как закрепление брони).
* Оптимистическая версия у OOO и блока — 409 при одновременной правке.
* Окно снимка предпросмотра для OOO и блоков ограничено ±62 днями вокруг изменения (находка
  P2 аудита: блок на годы не должен гонять контекст по тысячам дней).
* Аудит: `stays_ooo`, `stays_block`.

## 8. Тесты

* OOO: половинки (выезд утром + OOO с вечера в тот же день — не конфликт); галочки «с утра /
  до вечера»; вытеснение брони на другой объект; вытеснение в «не распределено»; закрепление под
  OOO → `pin_conflict_ooo`; OOO на объект вне фонда — 422.
* Блок: слоты из строк с разным количеством; пересекающиеся строки складываются; слот держит
  одну виллу при свободной; переезд слота при занятой; `block_short` при минусе; брони
  распределяются раньше слотов; закрепление слота; блок не создаёт дыр и нагрузки.
* Пожелания: выполнено при свободном объекте; не мешает при занятом; флаг по версии дня.
* HK-правило: из двух свободных выбирается без оборота; при одном — оборот допускается.
* «Загрузка»: OOO и блоки по половинкам; предпросмотр ≡ сохранение.

## 9. Открытые вопросы (предложение по умолчанию)

1. **Кто уступает при нехватке — бронь или блок?** *Предлагаю: блок (брони распределяются
   раньше), предупреждение `block_short`.*
2. **Нужно ли блоку что-то кроме названия и строк** (заказчик, контакт, срок опциона «держим до
   дд.мм»)? *Предлагаю: название, примечание, цвет; остальное — позже.*
3. **Чьи пожелания учитывает бронь** — главного гостя или всех проживающих? *Предлагаю: главного.*
4. **Где список блоков** — отдельной кнопкой на шахматке или в вкладке «Брони»?
   *Предлагаю: кнопка «Блоки» на шахматке объектов (список с поиском и нехваткой).*
5. **OOO поверх закреплённой брони** — вытеснять так же, как незакреплённую? *Предлагаю: да,
   с предупреждением; OOO главнее.*
