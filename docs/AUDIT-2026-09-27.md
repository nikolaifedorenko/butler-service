## 2. Баги и уязвимости (по убыванию важности)

### 🔴 2.1 Path Traversal — ✅ ИСПРАВЛЕНО: любой файл сервера без аутентификации — `app/main.py:336-343`

Catch-all маршрут `spa` делает `STATIC_DIR / full_path` и отдаёт файл, **не проверяя**,
что путь остался внутри `static/`. Проверено живыми запросами (без единой cookie):

```
GET /css%2f..%2f..%2ftimetrack.db   → 200, 561 152 байта — ВСЯ база SQLite
                                      (хеши паролей, персональные данные, аудит)
GET /css%2f..%2f..%2f.env           → 200, SECRET_KEY
GET /css%2f..%2f..%2fapp%2fconfig.py → 200, исходники
```

Mount `/static/` защищён самим Starlette, а вот самописный SPA-обработчик — нет.
**Фикс (3 строки):** `candidate = (STATIC_DIR / full_path).resolve()` и отдавать файл
только при `candidate.is_relative_to(STATIC_DIR.resolve())`, иначе — index.html/404.
После фикса — **обязательно сменить SECRET_KEY** (он считался «протёкшим»).

### 🟠 2.2 Расщепление часового пояса — ✅ ИСПРАВЛЕНО: Europe/Moscow vs дата сервера

`APP_TZ=Europe/Moscow`, есть `now_local()/local_date()` — но ~20 мест берут
`dt.date.today()` (дата в TZ сервера). В Docker контейнер живёт в UTC, поэтому
**с 00:00 до 03:00 МСК даты расходятся**:

| Место | Что ломается |
|---|---|
| `app/timesheet.py:546` | статус «planned» для будущих дней (ночная смена, идущая через полночь) |
| `app/factview.py:76` | маркер «●сейчас» (открытая смена) в табеле |
| `app/doc_render.py:243` | `{today}` в заявлениях — вчерашняя дата |
| `app/api/employees.py` (~14 мест) | даты приёма/увольнения/перевода, `bank_as_of`, `deleted_at` |
| `app/api/settings_api.py:76,122`, `app/shiftrev.py:121,123` | пересчёт, заморозка ревизий |

Отметки при этом пишутся через `local_date()` (МСК) — то есть одна и та же ночь
в разных частях системы относится к разным дням. Тесты тоже TZ-зависимы
(`TODAY = dt.date.today()` в tests/): на сервере с UTC ≠ МСК они будут падать в это окно.
**Фикс:** единое правило «бизнес-дата = `local_date()`» + `ENV TZ`/`APP_TZ` в Dockerfile
+ тест границы полуночи (freezegun).

### 🟠 2.3 SECRET_KEY по умолчанию — ✅ ИСПРАВЛЕНО — `.env`, `docker-compose.yml`

`SECRET_KEY=change-me-in-production…` в `.env` репозитория и как fallback в compose.
Ключ подписывает сессионные cookie: зная ключ, можно **подделать cookie админа**.
`setup_macos.sh` генерирует случайный, но текущий `.env` — дефолтный (и уже «утёк»
через п.2.1). **Фикс:** сгенерировать новый ключ сейчас; при старте с дефолтным
ключом — громко предупреждать (или отказывать в не-debug режиме).

### 🟠 2.4 Docker: загруженные бланки — ✅ ИСПРАВЛЕНО заявлений теряются при пересборке

`TEMPLATES_DIR = <проект>/templates`, а volume смонтирован только в
`/srv/timetrack/data`. После `docker compose up -d --build` фирменные бланки (.docx
из «Настройки → Шаблоны документов») исчезают; БД при этом выживает — тихая потеря
данных. **Фикс:** перенести templates под `data/` или добавить второй volume.

### 🟡 2.5 SQLite без WAL — ✅ ИСПРАВЛЕНО — риск «database is locked» в пиковые минуты

`PRAGMA journal_mode` = `delete` (проверено), `busy_timeout` не выставлен. В режиме
`delete` писатель блокирует и читателей; на пересменке, когда десятки людей
одновременно жмут «Пришёл/Ушёл», возможны 500-е. **Фикс:** при подключении
`PRAGMA journal_mode=WAL; PRAGMA busy_timeout=10000` (SQLAlchemy `event.listens_for(engine, "connect")`).
Для продакшена 50+ пользователей дальше — PostgreSQL (переключение уже заложено в `db.py`).

### 🟡 2.6 `counts_as_worked` — ✅ ИСПРАВЛЕНО — мёртвый флаг (подтверждено кодом)

Движок (`timesheet.py`) флаг **не читает вообще**; PAID_OFF считается обычным отсутствием.
Опция «оплачиваемое отсутствие» в модалке смены (`app.js:2450-2451, 2501`) — decoration,
вводящая менеджера в заблуждение. Совпадает с вашим выводом «ни на что не влияет» →
удаляем в рамках батча (п.1).
