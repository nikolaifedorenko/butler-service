# Установка и развертывание Батлер Сервис

## 1. Локальная машина (любая ОС)

Приложение и база (PostgreSQL) запускаются в Docker.

### Требования
* Docker Desktop (или Docker Engine с плагином compose);
* ~1,5 ГБ места под образы; интернет для первой сборки.

### Запуск
```bash
cd butler-service
docker compose up -d --build
```
Откройте **http://127.0.0.1:8000**. При первом запуске база заполняется демо-данными
(демо-сотрудники, блоки графика, отметки за ~1,5 месяца, шахматка).

| Команда | Что делает |
|---|---|
| `docker compose up -d --build` | собрать и запустить (после обновления кода — то же самое) |
| `docker compose logs -f app` | журнал приложения |
| `docker compose down` | остановить, данные сохранить |
| `docker compose down -v` | остановить и удалить данные (сброс демо-базы) |
| `PORT=9000 docker compose up -d` | другой порт |
| `DEMO_SEED=0 ADMIN_PASSWORD=… docker compose up -d` | пустая база с одним администратором |

Локальный профиль — только для своей машины: пароль базы и ключ сессий в нём учебные, порты
слушают `127.0.0.1`. Боевой профиль — раздел 2.

### Демо-доступы (пароль `demo1234`)
`admin` (администратор), `smirnov` (менеджер), `gromova` (старший батлер),

Полный список — на экране входа («Демо-доступы»).

### Разработка: тесты и сценарии интерфейса
```bash
docker compose up -d db          # только PostgreSQL, порт 127.0.0.1:54329
uv sync                          # окружение из uv.lock (uv: https://docs.astral.sh/uv/)
source .venv/bin/activate
python -m pytest tests/ -q       # параллельно; у каждого потока своя база. Один поток: -n 0
./tools/run_ui_check.sh 8141 gromova   # смоук интерфейса (нужен Node.js: npm install)
```
Другой сервер PostgreSQL для тестов задаёт `TEST_DATABASE_SERVER`
(по умолчанию `postgresql+psycopg2://postgres:dev@127.0.0.1:54329`).

Запуск приложения без контейнера — на базе из compose:
```bash
POSTGRES_HOST=127.0.0.1 POSTGRES_PORT=54329 POSTGRES_USER=postgres POSTGRES_PASSWORD=dev \
POSTGRES_DB=postgres SECRET_KEY=$(openssl rand -hex 32) DEMO_SEED=1 \
python -m uvicorn app.main:app --port 8000
```

### Полезное
* **PDF** собирает встроенный рендер (шрифты DejaVu лежат в `assets/fonts/`). Он передаёт текст,
  таблицы, фоны ячеек и картинки; точный вид фирменного бланка (подложка, сложная вёрстка)
  даёт кнопка «DOCX». Состояние видно в Настройки → Шаблоны документов и в
  `GET /api/docs/kinds` (`pdf`).
* **Обновление версии:** `docker compose up -d --build` — схема БД мигрирует при старте,
  данные сохраняются. Проверка схемы: http://127.0.0.1:8000/api/selfcheck. Если после
  обновления появились странные ошибки кэша — очистите кэш браузера или откройте страницу в
  режиме инкогнито.
* **Swagger API:** http://127.0.0.1:8000/api/docs
* **Телефон в той же сети:** локальный профиль слушает только `127.0.0.1`. Для проверки с
  телефона замените в `docker-compose.yml` публикацию порта приложения на `"8000:8000"`.

### Если приложение не стартует

| Что видно | Что делать |
|---|---|
| `docker compose ps`: `app` перезапускается | `docker compose logs app` — причина в последних строках |
| «База данных не задана» | приложение запущено без compose: задайте `POSTGRES_HOST` и остальные `POSTGRES_*` |
| `port is already allocated` | порт занят: `PORT=8010 docker compose up -d` |
| Тесты: «Тестам нужен PostgreSQL по адресу …» | `docker compose up -d db` |
| Белый экран в браузере | консоль браузера (F12); чаще всего — кэш, лечится `Cmd+Shift+R` |

## 3. Первый вход и настройка под себя
1. Войдите под `admin` (пароль — `ADMIN_PASSWORD` первого старта; на демо-базе `demo1234` —
   тогда смените демо-пароли: «Сотрудники» → «Изменить» → новый пароль).
2. Задайте сотрудников, группы графика («Смена 1», «Смена 2», «Администрация») и цвета должностей.
3. В «Настройках» добавьте нужные смены (часы) и проверьте правила расчёта (округление, окна отметок).
4. Заполните график на месяц («Заполнить графиком»: цикл, сдвиг фазы, только пустые ячейки).
5. Раздайте сотрудникам логины; покажите кнопку «Пришёл на работу» (раздел «Мои отметки»).
