## 1. Модели: `app/models.py` → пакет `app/models/`

808 строк одного файла разбиты по поддоменам **без изменения классов**:
`common` (роли, utcnow), `directory` (сотрудники, справочники, пользователи,
банк, двойные), `schedule` (смены, ревизии, отсутствия), `punch`, `engine_store`
(Табель, закрытия, переносы, Setting), `night`, `cars`, `media`, `audit`,
`access`. Фасад `__init__.py` ре-экспортирует все 45 публичных имён —
существующие импорты `from ..models import X` не менялись. Межмодульные
`relationship()` SQLAlchemy разрешает по реестру; для линтера аннотации закрыты
`TYPE_CHECKING`-импортами.

## 2. Сервисный слой `app/services/` (ADR-0006 в действии)

Образец `app/cars.py` + тонкий `cars_api.py` распространён на узлы, которые
мешали защитить границы контрактами:

- **`errors.py`** — доменные ошибки (NotFound/Forbidden/Validation/Conflict/
  Gone); `main.py` маппит их в HTTP-статусы обработчиками. Тело ответа прежнее
  (`{"detail": …}`) — контракт не изменился. Сервисы не знают про FastAPI.
- **`employee_lifecycle.py`** — use-case'ы перевода должности, смены блока
  графика, увольнения, повторного приёма + общие помощники (parse_date,
  touch_position/touch_block, normalize_block_history, build_pattern_json —
  их используют и оставшиеся в роутерах create/update). Данные передаются
  примитивами и `dataclass BlockChange`, а не pydantic-DTO api-слоя.
  `employees.py`: **1110 → 913 строк**, четыре роутера стали тонкими.
- **`punch_plan.py`** — «план на сегодня» вынесен из `punches.py`: он нужен
  двум api-модулям (punches и auth_routes `/me`), а api-модули больше не
  импортируют друг друга.
- **`engine_common.py`** переехал из `app/api/` (мост к движку — общий сервис,
  а не «одного из роутеров»).
- **`app/photos.py`**: `resolve_photo_file`/`delete_photo` — алиасы ночного
  отчёта больше не зовут роут-функции `photos_api`.
- Переходное исключение (зафиксировано в ADR-0006): `auth.can_manage_user`
  исторически бросает HTTPException(403) — сервисы вызывают его как есть.
