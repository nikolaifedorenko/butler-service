# Батлер Сервис — полная спецификация

Версия документа: 1.0 · соответствует коду в `app/`, `static/`, `tests/`
Назначение: система учёта рабочего времени для объектов с посменным персоналом
(батлеры, старшие батлеры, менеджеры, документооборот).

---

## 1. Термины и обозначения

| Термин | Значение |
|---|---|
| **Смена (ячейка графика)** | Назначение «сотрудник × дата»: тип смены (рабочая или отсутствие) + примечание |
| **Отметка (punch)** | Событие «Пришёл на работу» (IN) или «Ушёл с работы» (OUT) с точным временем |
| **Сессия** | Пара IN→OUT; единица расчёта отработанного времени |
| **ДЯ** | Дневные часы: 06:00–22:00 |
| **ДН** | Ночные часы: 22:00–06:00 (ст. 96 ТК РФ) |
| **План** | Длительность типа смены (разница начала и конца, ночные — через полночь) |
| **Факт** | Сумма округлённых сессий дня |
| **Переработка** | max(0, факт − план) дня |
| **Недоработка** | max(0, план − факт) дня |
| **Банк часов** | Стартовый баланс + переработки − «выходные за часы» − недоработки |
| **Табель** | Месячная матрица «сотрудник × день» с расчётными строками |
| **Группа графика (блок)** | «Смена 1», «Смена 2», «Администрация»; сотрудник может переходить между блоками — тогда он виден в обоих, а «чужие» дни залиты одним цветом |
| **Работа в выходной** | Отметки в день типа «выходной»/«выходной за часы»: часы начисляются как переработка, ячейка в сетке окрашивается отдельным цветом |
| **Цвет должности** | Цвет акцента сотрудника (полоса у ФИО, опционально заливка ячеек) |

Коды отсутствий (колонка табеля / Т-13): `В` выходной, `Б` больничный, `ОТ` отпуск,
`ДО` за свой счёт, `НВ` выходной за часы, `ОВ` оплачиваемый выходной, `НН` неявка,
`НЕ` работа вне графика; рабочие дни в выгрузках пишутся часами: `ДЯ n ДН m`.

## 4. Движок расчёта (app/timesheet.py)

### 4.1.Pipeline одного дня
1. **Окно отметок**: для плана дня D — `[start − punch_window_before_h, end + punch_window_after_h]`;
   собираются отметки за D−1…D+1, пары IN→OUT строятся хронологически
   (повторный IN игнорируется с предупреждением; одинокий OUT игнорируется).
2. **Привязка сессии к дате**: если IN попал в окно плана дня C — сессия принадлежит C
   (ночная 22.09 20:00→23.09 08:00 принадлежит 22.09); иначе — календарной дате IN
   («работа вне графика»). Следствие: «день + остался в ночь» и «ночь + вышел днём»
   целиком попадают в день начала смены — переработка пишется туда же
   (требование «по официальному табелю он в день»).
3. **Обрезка**: начало — по плановому старту, если `count_early_arrival=0`;
   конец — по плановому концу, если `count_late_departure=0` (по умолчанию 1 → переработка считается).
4. **Округление до часа** (`round_mode`: nearest/floor/ceil, шаг `round_step_min`=60):
   08:12→08:00, 19:50→20:00. Точные отметки сохраняются в `fact_in/fact_out` и видны менеджеру.
5. **ДЯ/ДН**: часовые блоки классифицируются по `night_start/night_end` (22:00/06:00);
   часы всегда целые. Опция `night_reduce_hours` — минус 1 ночной час (ст. 96 ч. 2 ТК РФ).
6. **Агрегат дня**: факт = Σ сессий; переработка/недоработка к плану; сессии короче
   `min_session_min` игнорируются; пересечения склеиваются (двойные часы не суммируются).
7. **Незакрытая смена**: нет OUT → при `auto_close_missing_out=1` закрывается плановым концом,
   статус `unclosed` + предупреждение; иначе часы не начисляются.
8. **Статус**: опоздание/ранний уход — по округлённому времени зачёта с допуском
   `grace_minutes` (по умолчанию 5); режим `late_by_raw_time=1` — по точной отметке.
9. **Отсутствия**: план 0; `TIMEOFF_HOURS` списывает 8 ч банка (`timeoff_hours`);
   отметки в нерабочий день не попадают в часы, но фиксируются предупреждением.
10. **Будущие дни**: статус `planned`, дефицит не начисляется.
11. **Описание переработки**: `note` отметки OUT агрегируется в `ot_note` дня.

### 4.2. Два контура учёта, банк часов и реестр к выплате

**Внутренний контур (факт/банк):** сессия относится к дате начала; если её хвост накрывает
плановое окно следующего дня (ночь → день), сессия режется по границе плана — оба дня чистые.
Часы до начала смены не входят в факт/банк при `count_early_arrival=0`, часы после конца —
входят при `count_late_departure=1`.

**Внешний контур (то, что вносится в систему учёта зарплаты):** часы сессий раскладываются по
**календарным** дням, из них вычитается «официальное окно» дня (часы обычной смены; для ночной —
номинальное дневное окно 08:00–20:00 той же длительности). Остаток — начисления ДЯ/ДН по
календарным дням. Одновременно считается **не отработанные в официальном окне часы**
(`unused_hours`: опоздания, ранние уходы; для неявок не создаются — их официальный табель
оформляет отдельно). В зачёте неиспользованные окна гасят начисления хронологически: поэтому
ночь 01.09 + день 02.09 «стыком» (24 ч факт при 24 ч официальных) дают **ноль к выплате**,
а сутки «день+ночь+день» (36 ч факт при 24 ч официальных) дают ровно
«01.09 ДЯ 2 ДН 2» и «02.09 ДЯ 2 ДН 6». Непокрытые списания становятся долгом и гасят
переработки следующих месяцев.

**Зачёт списаний:** опоздания, ранние уходы и «выходные за часы» гасят начисления хронологически,
сначала дневные часы самых ранних дней; непокрытое списание становится **долгом** и гасит
переработки следующих месяцев. Банк часов также накопительный: сальдо конца месяца = старт
следующего.

### 4.2-old. Банк часов и реестр переработок к выплате

**Банк часов** (нетто): старт + переработки рабочих дней + часы работы в выходной − недоработки
(опоздания/ранние уходы) − «выходные за часы». Регулярные смены банк не меняют.

**Реестр переработок к выплате** (брутто, `/api/timesheet/overtime`, панель в «Табеле»,
лист «Переработки к выплате» в Excel):
1. Начисления: ранние приходы (до начала смены), поздние уходы (после конца смены),
   работа в выходной — с разбивкой на ДЯ/ДН по часам суток (`pay_ot_day`, `pay_ot_night`).
2. Списания: опоздания (`late_hours`), ранние уходы (`early_hours`), «выходные за часы»
   (`timeoff_hours`).
3. Зачёт (`settle_overtime`): каждое списание вычитается **сначала из дневных часов самых
   ранних дней** с переработками, затем из ночных (дневные дешевле); журнал зачёта
   показывается в деталях и в Excel. Остаток после зачёта — то, что подаётся к выплате
   (ДЯ и ДН раздельно).

### 4.2b. Дни двойной оплаты: ДЯ2/ДН2 (app/doublepay.py)

Правила компании: **стоимость рабочего дня одинаковая всегда, вдвое оплачиваются только
переработки**. Поэтому в «двойной» день (производственный календарь для своего списка —
сменные/пятидневка — или ВИП-период сотрудника) часы сверх официального окна попадают
в реестр к выплате кодами **ДЯ2/ДН2** (`pay_ot_day2`/`pay_ot_night2`), а часы внутри окна
остаются обычной зарплатой.

**Списания из двойных часов — вполовину.** Списания (опоздания, ранние уходы, отгулы, долг
прошлых периодов) выражены в одинарных часах оплаты; съедая двойные часы, они снимают их
вдвое меньшим количеством часов кода: снять 8 часов оплаты = убрать 4 часа ДЯ2. Если же
списание гасится часами обычных дней — оно идёт 1=1 (поэтому ранний уход в двойной день,
попавший на обычные часы другого дня, не «удешевляет» списание). Порядок зачёта в
`settle_overtime`: ДЯ → ДН → ДЯ2 → ДН2 (обычные часы берегут двойные).

**Календарь и список.** К какому списку относится сотрудник в дату, решает его шаблон
графика: «Пятидневка» (kind=week5) → список пятидневки; остальные блоки (Смена 1/2,
«Другие смены») → список сменных. `scope=all` действует на всех.

**Пересчёт.** Любая правка календаря/ВИП-периодов точечно пересчитывает строки табеля,
где есть (или были) часы к выплате либо отметка о двойном дне (`recalc_double_rows`), —
реестр актуален сразу, историю это не ломает. Банк часов двойная оплата не меняет
(часы остаются часами).

### 4.3. Банк часов
`банк = balance_hours(старт) + Σ ot_hours − Σ timeoff_hours − Σ deficit_hours` за период
(отображается в табеле; стартовое значение правится у сотрудника).

### 4.3. Пересчёт
`recalc_day` / `recalc_range` пересчитывают строки табеля из отметок и графика
(вызывается при каждой отметке, правке ячейки, массовых операциях и вручную:
«Табель → Пересчитать», «Настройки → Пересчитать месяц»).

### 4.4. Правила (settings) — значения по умолчанию
`round_mode=nearest`, `round_step_min=60`, `count_early_arrival=0`, `count_late_departure=1`,
`min_session_min=10`, `auto_close_missing_out=1`, `grace_minutes=5`, `night_start=22:00`,
`night_end=06:00`, `night_reduce_hours=0`, `late_by_raw_time=0`,
`punch_window_before_h=4`, `punch_window_after_h=6`.

## 5. Графики и циклы (app/schedule_patterns.py, app/base_schedule.py, app/groups.py)

Блоков сетки четыре (`app/groups.py`): **«Смена 1»**, **«Смена 2»** — считаются базовым
циклом объекта из настроек (в противофазе); **«Пятидневка»** — у каждого сотрудника СВОИ
выходные (шаблон `week5` в `block_assignments.pattern_json`); **«Другие смены»** —
индивидуальные циклы (`cycle`: 3/3, 1/3, сутки через трое, «custom:РРВВ») или `manual`.
Старое название «Администрация» автоматически приводится к «Пятидневке» (миграция +
`normalize_group`). Индивидуальный шаблон важнее общих настроек блока; виртуальную смену
дня возвращает `base_shift()` — с учётом перевода между блоками, периодов работы и ревизий
словаря смен.

* **N/M** — любые числа: 2/2, 3/3, 4/2, 4/3, 1/3… (цикл от даты начала + `offset` — сдвиг фазы бригады).
* При заполнении для блоков «Смена 1»/«Смена 2» включена **инверсия фаз** (`sync_blocks`):
  дни, когда работает другая смена, автоматически ставятся выходными — пересечений нет.
* **5/2, 6/1** — привязка к дням недели; `off_weekdays` — какие дни выходные (0=пн…6=вс).
* **custom** — произвольная строка цикла «РРВВВВРР» / «11000011» / «ВВРРРРВВ»
  (символы Р/В, 1/0, W/O; разделители необязательны) — любые переходы «смена-смена».
* Массовое заполнение: список сотрудников, период, рабочая смена, что ставить в выходные,
  `only_empty` (не трогать отпуска/больничные), копирование периода `src → dst`.

| **Отметка (punch)** | Событие «Пришёл на работу» (IN) или «Ушёл с работы» (OUT) с точным временем |
| **Сессия** | Пара IN→OUT; единица расчёта отработанного времени |
| **ДЯ** | Дневные часы: 06:00–22:00 |
| **ДН** | Ночные часы: 22:00–06:00 (ст. 96 ТК РФ) |
| **План** | Длительность типа смены (разница начала и конца, ночные — через полночь) |
| **Факт** | Сумма округлённых сессий дня |
| **Переработка** | max(0, факт − план) дня |
| **Недоработка** | max(0, план − факт) дня |
| **Банк часов** | Стартовый баланс + переработки − «выходные за часы» − недоработки |
| **Табель** | Месячная матрица «сотрудник × день» с расчётными строками |
| **Группа графика (блок)** | «Смена 1», «Смена 2», «Администрация»; сотрудник может переходить между блоками — тогда он виден в обоих, а «чужие» дни залиты одним цветом |
| **Работа в выходной** | Отметки в день типа «выходной»/«выходной за часы»: часы начисляются как переработка, ячейка в сетке окрашивается отдельным цветом |
| **Цвет должности** | Цвет акцента сотрудника (полоса у ФИО, опционально заливка ячеек) |

Коды отсутствий (колонка табеля / Т-13): `В` выходной, `Б` больничный, `ОТ` отпуск,
`ДО` за свой счёт, `НВ` выходной за часы, `ОВ` оплачиваемый выходной, `НН` неявка,
`НЕ` работа вне графика; рабочие дни в выгрузках пишутся часами: `ДЯ n ДН m`.

## 4. Движок расчёта (app/timesheet.py)

### 4.1.Pipeline одного дня
1. **Окно отметок**: для плана дня D — `[start − punch_window_before_h, end + punch_window_after_h]`;
   собираются отметки за D−1…D+1, пары IN→OUT строятся хронологически
   (повторный IN игнорируется с предупреждением; одинокий OUT игнорируется).
2. **Привязка сессии к дате**: если IN попал в окно плана дня C — сессия принадлежит C
   (ночная 22.09 20:00→23.09 08:00 принадлежит 22.09); иначе — календарной дате IN
   («работа вне графика»). Следствие: «день + остался в ночь» и «ночь + вышел днём»
   целиком попадают в день начала смены — переработка пишется туда же
   (требование «по официальному табелю он в день»).
3. **Обрезка**: начало — по плановому старту, если `count_early_arrival=0`;
   конец — по плановому концу, если `count_late_departure=0` (по умолчанию 1 → переработка считается).
4. **Округление до часа** (`round_mode`: nearest/floor/ceil, шаг `round_step_min`=60):
   08:12→08:00, 19:50→20:00. Точные отметки сохраняются в `fact_in/fact_out` и видны менеджеру.
5. **ДЯ/ДН**: часовые блоки классифицируются по `night_start/night_end` (22:00/06:00);
   часы всегда целые. Опция `night_reduce_hours` — минус 1 ночной час (ст. 96 ч. 2 ТК РФ).
6. **Агрегат дня**: факт = Σ сессий; переработка/недоработка к плану; сессии короче
   `min_session_min` игнорируются; пересечения склеиваются (двойные часы не суммируются).
7. **Незакрытая смена**: нет OUT → при `auto_close_missing_out=1` закрывается плановым концом,
   статус `unclosed` + предупреждение; иначе часы не начисляются.
8. **Статус**: опоздание/ранний уход — по округлённому времени зачёта с допуском
   `grace_minutes` (по умолчанию 5); режим `late_by_raw_time=1` — по точной отметке.
9. **Отсутствия**: план 0; `TIMEOFF_HOURS` списывает 8 ч банка (`timeoff_hours`);
   отметки в нерабочий день не попадают в часы, но фиксируются предупреждением.
10. **Будущие дни**: статус `planned`, дефицит не начисляется.
11. **Описание переработки**: `note` отметки OUT агрегируется в `ot_note` дня.

### 4.2. Два контура учёта, банк часов и реестр к выплате

**Внутренний контур (факт/банк):** сессия относится к дате начала; если её хвост накрывает
плановое окно следующего дня (ночь → день), сессия режется по границе плана — оба дня чистые.
Часы до начала смены не входят в факт/банк при `count_early_arrival=0`, часы после конца —
входят при `count_late_departure=1`.

**Внешний контур (то, что вносится в систему учёта зарплаты):** часы сессий раскладываются по
**календарным** дням, из них вычитается «официальное окно» дня (часы обычной смены; для ночной —
номинальное дневное окно 08:00–20:00 той же длительности). Остаток — начисления ДЯ/ДН по
календарным дням. Одновременно считается **не отработанные в официальном окне часы**
(`unused_hours`: опоздания, ранние уходы; для неявок не создаются — их официальный табель
оформляет отдельно). В зачёте неиспользованные окна гасят начисления хронологически: поэтому
ночь 01.09 + день 02.09 «стыком» (24 ч факт при 24 ч официальных) дают **ноль к выплате**,
а сутки «день+ночь+день» (36 ч факт при 24 ч официальных) дают ровно
«01.09 ДЯ 2 ДН 2» и «02.09 ДЯ 2 ДН 6». Непокрытые списания становятся долгом и гасят
переработки следующих месяцев.

**Зачёт списаний:** опоздания, ранние уходы и «выходные за часы» гасят начисления хронологически,
сначала дневные часы самых ранних дней; непокрытое списание становится **долгом** и гасит
переработки следующих месяцев. Банк часов также накопительный: сальдо конца месяца = старт
следующего.

### 4.2-old. Банк часов и реестр переработок к выплате

**Банк часов** (нетто): старт + переработки рабочих дней + часы работы в выходной − недоработки
(опоздания/ранние уходы) − «выходные за часы». Регулярные смены банк не меняют.

**Реестр переработок к выплате** (брутто, `/api/timesheet/overtime`, панель в «Табеле»,
лист «Переработки к выплате» в Excel):
1. Начисления: ранние приходы (до начала смены), поздние уходы (после конца смены),
   работа в выходной — с разбивкой на ДЯ/ДН по часам суток (`pay_ot_day`, `pay_ot_night`).
2. Списания: опоздания (`late_hours`), ранние уходы (`early_hours`), «выходные за часы»
   (`timeoff_hours`).
3. Зачёт (`settle_overtime`): каждое списание вычитается **сначала из дневных часов самых
   ранних дней** с переработками, затем из ночных (дневные дешевле); журнал зачёта
   показывается в деталях и в Excel. Остаток после зачёта — то, что подаётся к выплате
   (ДЯ и ДН раздельно).

### 4.2b. Дни двойной оплаты: ДЯ2/ДН2 (app/doublepay.py)

Правила компании: **стоимость рабочего дня одинаковая всегда, вдвое оплачиваются только
переработки**. Поэтому в «двойной» день (производственный календарь для своего списка —
сменные/пятидневка — или ВИП-период сотрудника) часы сверх официального окна попадают
в реестр к выплате кодами **ДЯ2/ДН2** (`pay_ot_day2`/`pay_ot_night2`), а часы внутри окна
остаются обычной зарплатой.

**Списания из двойных часов — вполовину.** Списания (опоздания, ранние уходы, отгулы, долг
прошлых периодов) выражены в одинарных часах оплаты; съедая двойные часы, они снимают их
вдвое меньшим количеством часов кода: снять 8 часов оплаты = убрать 4 часа ДЯ2. Если же
списание гасится часами обычных дней — оно идёт 1=1 (поэтому ранний уход в двойной день,
попавший на обычные часы другого дня, не «удешевляет» списание). Порядок зачёта в
`settle_overtime`: ДЯ → ДН → ДЯ2 → ДН2 (обычные часы берегут двойные).

**Календарь и список.** К какому списку относится сотрудник в дату, решает его шаблон
графика: «Пятидневка» (kind=week5) → список пятидневки; остальные блоки (Смена 1/2,
«Другие смены») → список сменных. `scope=all` действует на всех.

**Пересчёт.** Любая правка календаря/ВИП-периодов точечно пересчитывает строки табеля,
где есть (или были) часы к выплате либо отметка о двойном дне (`recalc_double_rows`), —
реестр актуален сразу, историю это не ломает. Банк часов двойная оплата не меняет
(часы остаются часами).

### 4.3. Банк часов
`банк = balance_hours(старт) + Σ ot_hours − Σ timeoff_hours − Σ deficit_hours` за период
(отображается в табеле; стартовое значение правится у сотрудника).

### 4.3. Пересчёт
`recalc_day` / `recalc_range` пересчитывают строки табеля из отметок и графика
(вызывается при каждой отметке, правке ячейки, массовых операциях и вручную:
«Табель → Пересчитать», «Настройки → Пересчитать месяц»).

### 4.4. Правила (settings) — значения по умолчанию
`round_mode=nearest`, `round_step_min=60`, `count_early_arrival=0`, `count_late_departure=1`,
`min_session_min=10`, `auto_close_missing_out=1`, `grace_minutes=5`, `night_start=22:00`,
`night_end=06:00`, `night_reduce_hours=0`, `late_by_raw_time=0`,
`punch_window_before_h=4`, `punch_window_after_h=6`.

циклом объекта из настроек (в противофазе); **«Пятидневка»** — у каждого сотрудника СВОИ
выходные (шаблон `week5` в `block_assignments.pattern_json`); **«Другие смены»** —
индивидуальные циклы (`cycle`: 3/3, 1/3, сутки через трое, «custom:РРВВ») или `manual`.
Старое название «Администрация» автоматически приводится к «Пятидневке» (миграция +
`normalize_group`). Индивидуальный шаблон важнее общих настроек блока; виртуальную смену
дня возвращает `base_shift()` — с учётом перевода между блоками, периодов работы и ревизий
словаря смен.

* **N/M** — любые числа: 2/2, 3/3, 4/2, 4/3, 1/3… (цикл от даты начала + `offset` — сдвиг фазы бригады).
* При заполнении для блоков «Смена 1»/«Смена 2» включена **инверсия фаз** (`sync_blocks`):
  дни, когда работает другая смена, автоматически ставятся выходными — пересечений нет.
* **5/2, 6/1** — привязка к дням недели; `off_weekdays` — какие дни выходные (0=пн…6=вс).
* **custom** — произвольная строка цикла «РРВВВВРР» / «11000011» / «ВВРРРРВВ»
  (символы Р/В, 1/0, W/O; разделители необязательны) — любые переходы «смена-смена».
* Массовое заполнение: список сотрудников, период, рабочая смена, что ставить в выходные,
  `only_empty` (не трогать отпуска/больничные), копирование периода `src → dst`.

## 7. Интерфейс (static/)

Светлая тема, адаптив: десктоп, планшет, телефон-портрет, телефон-ландшафт; PWA-манифест.

* **График**: сетка ФИО×дни с липкими шапкой/колонкой ФИО; блоки «Смена 1 / Смена 2 /
  Администрация» (порядок: группы `schedule_group`, прочие по алфавиту, пустые в конце);
  цветная полоса и точка должности у ФИО; переключатель «Цвет смен / Цвет должностей»
  (заливка рабочих ячеек); выходные и «сегодня» подсвечены; примечание — точка в ячейке;
  легенда; клик по ячейке — редактор (смены/отсутствия + примечание); печать.
* **Заполнить графиком**: пресеты N/M, custom-цикл с предпросмотром, 5/2 с выбором выходных,
  сдвиг фазы, «только пустые»; **Копировать период**.
* **Посещения**: карточки «на смене сейчас» (пульс, приход, длительность, план до),
  статплитки (на смене/по графику/опоздания/требуют внимания), таблица дня:
  план-пилюля, точный приход (красный при опоздании), уход или «на смене», часы, переработка, статус.
* **Табель**: статплитки (план/факт/ДН/переработка/отклонения), таблица сотрудников
  (план, факт, ДЯ, ДН, перераб, недораб, отгулы, банк, проблемы) с акцентом группы;
  раскрытие строки — чипы дней (отметки, ДЯ/ДН, перераб, ★описание, предупреждения);
  блок «Требует внимания»; кнопки «Пересчитать», «CSV», «Скачать Excel».
* **Сотрудники**: список-минимум (ФИО, должность, блок, статус) → клик открывает **карточку**
  (табельный №, приём, телефон, почта, Telegram, контакты близких, банк, роль, истории
  должностей и блоков) с действиями: Изменить, Войти как сотрудник, Перевод на должность
  (с датой), Перевод между блоками (с датой), Уволить (с датой), Удалить (история сохраняется).
  Редактор: несколько контактов близких, Telegram, почта, пароль с подтверждением.
* **Мои отметки**: карточка смены дня, большая кнопка «Пришёл на работу» / «Ушёл с работы»,
  «вы на смене N ч», статплитки (отработано/ДН/переработка/банк), история отметок
  с кнопкой «★ описание» у уходов; модалка описания переработки сразу после ухода с переработкой.
* **Настройки**: словарь смен (создание/правка любых часов, авто-признак «через полночь»,
  цвет, код табеля), правила расчёта (переключатели/поля + «по умолчанию»), счётчики,
  пересчёт месяца, журнал аудита.

Формат выгрузки Excel (лист «Табель»): строка 4 — шапка `ФИО | 01.09 | 02.09 | … | ДЯ | ДН |
Всего | Перераб. | Недораб. | Отгулы | Банк`; ячейки — `ДЯ 12`, `ДЯ 4 ДН 8`, коды отсутствий,
`НН` при неявке; итоги по сотруднику справа и строка «ИТОГО по объекту»; congelation panes B5;
лист «Переработки»: дата, сотрудник, часы, описание.

## 9. Ограничения и точки роста

* Миграции схемы: используется `create_all` (новые таблицы добавляются сами);
  изменение колонок требует ручного переноса — на боевой БД держите бэкапы
  (при желании подключается Alembic).
* Сессии stateless: нет отзывa одной сессии и онлайн-списка «кто в системе».
* Нет CSRF-токена (SameSite=Lax), rate-limit и 2FA — см. чек-лист в `docs/AUTH.md`.
* Telegram-бот: подключается как клиент API (`POST /api/punches` c `source=telegram`),
  разметка кнопок тривиальна (status/punch).
* Зарплатный модуль не ведётся (по требованию); почасовая база для него уже есть
  (ДЯ/ДН/переработки по дням).
* Пуш-уведомления «забыл отметку» (автозакрытие в 20:00) — cron/фоновая задача поверх
  `recalc_range` + мессенджер.

## 10. Корпоративные шаблоны документов (.docx)

Источник истины — **вид заявления** (`statement_kinds`): код, название и текст
с плейсхолдерами. Встроенные виды (отпуск оплачиваемый/за свой счёт, выходной за часы,
«отпросился») создаются при первом запуске; менеджер/администратор может добавлять свои
(«Настройки → Виды заявлений и шаблоны»). Фирменный бланк компании в Word (свои шрифты,
подложка, колонтитулы) хранится в `templates/<code>.docx` и **перекрывает** текст вида:
оформление бланка сохраняется, плейсхолдеры подставляются в его run'ы. Загрузка/удаление —
в модалке вида (только роли manager и выше), API: `GET|POST|DELETE /api/docs/templates?type=<code>`,
рендер — `POST /api/docs/render`.

* Плейсхолдеры — `{имя}` в тексте, таблицах и колонтитулах. Word часто разбивает текст
  на несколько run: при подстановке текст параграфа склеивается, заменяется целиком и
  возвращается в первый run (форматирование первого run сохраняется), остальные очищаются.
* Набор плейсхолдеров: `{company} {director} {full_name} {full_name_genitive} {short_name} {position} {tab_number}
  {group} {phone} {telegram} {email} {emergency_name} {emergency_phone} {date_from} {date_to}
  {date_from_ru} {date_to_ru} {days} {days_word} {today} {today_ru}` (даты прописью —
  «01» октября 2026 г., дни прописью — двенадцать). При загрузке система показывает найденные
  плейсхолдеры; неизвестные `{…}` остаются как есть.
* `{full_name_genitive}` — ФИО в родительном падеже («от Федоренко Николая Сергеевича»):
  берётся из поля карточки сотрудника; если поле пустое — склоняется автоматически
  (`app/names.py`, правила русского языка с поправкой на пол по фамилии/имени). Кнопка
  «Подсказать» в карточке предлагает вариант, его можно исправить вручную.
* Кнопка «Пример .docx» (Настройки) скачивает образец бланка со всеми плейсхолдерами
  (`GET /api/docs/sample?type=…`) — удобно оформить под свой фирменный бланк и загрузить.
  Подробная инструкция: `docs/TEMPLATES.md`.
* Значения периода: заявление берёт отпуск целиком (серия соседних ячеек с тем же кодом),
  как и экранная печать.
* Выход DOCX — всегда; PDF — конвертацией заполненного docx через `soffice --headless`
  (LibreOffice на сервере). Без него API честно отвечает 501 с подсказкой, UI показывает
  пояснение в настройках.
* Если шаблон не загружен — рендерится встроенный текст заявления (plain docx), чтобы
  кнопка работала «из коробки».
* Загрузка/рендер пишутся в журнал аудита (`doc_template_upload`, `doc_render`).
