# Изменения 20.10.2026 — долг №1 закрыт: «менеджерская видимость» → ключи прав (§5.2)

Решение владельца: вариант A, **без укрупнения** — отдельные права на каждую
семантику. Последний ролевой атавизм экранной авторизации (inline-ветвления
`principal.is_manager`, отложенные этапом B и фазой C4) переведён на каталог
`PERMISSIONS`. В модулях не осталось ни одного чтения `is_manager` (страж —
`test_permissions_unification.py::test_inline_is_manager_v_modulyah_bolshe_net`).

## 1. Было → стало (11 ветвлений)

| Экран / эндпоинт | Было (роль) | Стало (ключ) |
|---|---|---|
| Факт: история сессий (403 «Доступна только своя история сессий») | `is_manager` | **`fact.view_all`** |
| Факт: сетка месяца и «Номера» (фильтр строк до себя, флаг `all_employees`) | `is_manager` | **`fact.view_all`** |
| Отметки: журнал (сотрудник — только свои) | `is_manager` | **`punches.view_all`** |
| Отметки: комментарий к чужой отметке (403 «Можно комментировать только свои отметки») | `is_manager` | **`punches.view_all`** |
| Отметки: отметка за другого (`employee_id`, `source=manual`) | `is_manager` | **`punches.punch_for_others`** |
| Отметки: отметка задним числом (`ts`) | `is_manager` | **`punches.backfill`** (второй гейт после `punches.manage`) |
| График: `readonly` сетки | `is_manager` | **`schedule.edit`** (существующий ключ — семантика «можно править») |
| График: срез ячеек до плана (`_strip_to_plan`: без заметок и id записей) | `is_manager` | **`schedule.view_all`** |

Итого 5 новых ключей каталога (секции «Отметки» ×3, «Факт», «График») +
переиспользование `schedule.edit`. Тексты 403 обновлены там, где ссылались на
роль («…может поставить только менеджер» → «…требует права «Отметки: отметка
задним числом»»); тестами/openapi старые тексты закреплены не были.

## 2. Поведение ролей НЕ изменилось

`MANAGER_ROLES = (admin, manager, supervisor)`; базовые наборы `ROLE_DEFAULTS`
устроены так, что новые ключи автоматически входят в admin/manager/supervisor
и не входят в employee — аудитория ровно прежняя (проверено тестом
`test_klyuchi_v_kataloge_i_defoltnaya_auditoriya`). Отличие от этапа B:
**никаких ужесточений** — перевод 1:1.

Новое (управляемость): ключи выдаются/снимаются грантами в «Настройки → Права
доступа» — тесты покрывают оба направления: `fact.view_all`/`punches.view_all`/
`punches.backfill`/`schedule.view_all+edit` батлеру (allow) и `deny`
`punches.backfill` менеджеру (роль больше не решает).

## 3. Свойство `Principal.is_manager`

Сохранено в `core/auth.py` как утилита ролевой иерархии (для `can_manage_user`
и совместимости); комментарии обновлены — для экранной авторизации его
использовать не следует, только каталог. `can_manage_user` (страж
анти-эскалации, §0 п.8) не тронут.

## 4. Фронтенд

Не менялся: UI не гейтит эти действия по роли (проверено grep); `readonly` и
`all_employees` приходят в payload как раньше; `/api/auth/me` уже отдаёт
`permissions` — будущее переключение кнопок на права возможно без бэкенда.

## 6. Открытые продуктовые вопросы (не блокируют)
