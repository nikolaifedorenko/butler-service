Слой 1 · План / График

Операционный план: кто когда стоит. По умолчанию показывается табельная смена — стандартное окно кода Табеля (Я 8 → 09:00–18:00, Я 10,75 → 08:00–20:00); её можно заменить на ручную смену из справочника. Ручная смена (в т.ч. ночная) Табель, окно и часы НЕ меняет — движок считает как сейчас (решение Q1). Правка Графика влияет только на флаги и доску.
Из Графика назначается только «отпросился (выходной за часы)» ✂ — информационно: чтобы сотрудника не ждали; неотработанные часы окна уйдут в недостачу (Q8). Отпуск / больничный / за свой счёт / оплачиваемый выходной — из Табеля (слой 0). «Недопуск» не добавляется — если понадобится, владелец введёт новый код Табеля (замечание от 12.10.2026).

Слой 2 · Факт

Отметки СКУД, округлённые до шага. План / отработано / недоработка / переработка считаются от ОКНА из Табеля (слой 0); флаги опоздания, раннего ухода и «вне графика» — от ГРАФИКА (слой 1). Деление переработки на категории ДЯ/ДН — по границам из НАСТРОЕК («Категории дневных кодов», по умолчанию ДЯ 06:00–22:00 / ДН 22:00–06:00).

Слой 3 · Управленческий Табель

Результат: итоговые коды и переработки в часах, банк часов, закрытие периода. Вопросы и решения владельца (ответы от 12.10.2026)

Q1. ✅ Ручное окно Графика — влияет ли на часы? Нет. Окно — из кода Табеля; График по умолчанию показывает табельное окно, заменяется на ручную смену; ручная смена Табель не меняет.
Принято как есть («сейчас это так же работает»). Задача T6 (режим переопределения окна) снята.
Q2. ✅ Название пункта меню. «График» — подтверждено; слой 1 внутри — «План / График».
Q3. ✅ «Отпросился» и «выходной за часы» — одна сущность. Подтверждено: одна запись словаря, две точки ввода (интервал / вся смена).
Q4. ✅ Отсутствия из Графика — только «за счёт часов». Отпуск / больничный / за свой счёт / оплачиваемый выходной — из Табеля (там же заявления). «Недопуск» не добавлять (замечание 1).
Q5. ✅ «Сбросить» в Табеле. Подтверждено: убирает введённые вручную коды за период, возвращает автозаполнение; закрытых периодов не касается — как в прототипе.
Q6. ✅ Код «НД» (недопуск к работе). Не добавляется: «забудь пока о нём; если будет надо — я введу в табель новый код» (замечание 1). Задача T2 снята.
Q7. ✅ Доска «Отметки». Согласовано: оперативная доска — отдельный пункт меню; сетка номеров с округлением — внутри слоя «Факт».
Q8. ✅ «Выходной за часы» на всю смену. Только информация («чтобы не ждали сотрудника»). Отсутствие отработанных часов в стандартном окне уходит в недостачу; при закрытии её оплачивает банк 1:1 — расчёт не меняется.
Q9. ✅ APP-SHIFT-CODE (6 ошибок в панели здоровья). Модель не меняется: код Табеля → стандартное окно → эти же часы попадают в График первоначальными сменами, далее редактируются. Правка техническая: редактор смены сейчас записывает в поле «код в табеле» короткое имя смены («08-20») — это не код Табеля, из-за чего health выдаёт 6 ошибок, а ночные/суточные смены перестали заполнять Табель из циклов. Лечение: в этом поле — только коды из словаря Табеля («Я», «Н», …) или пусто; границы смены уже хранятся отдельно. Новых сущностей не нужно (задача T1).
Замечание 2. ✅ Деление переработок ДЯ/ДН — из настроек. Границы категорий дневных кодов (по умолчанию ДЯ 06:00–22:00 / ДН 22:00–06:00) берутся из раздела настроек «Категории дневных кодов»; движок уже читает их из конфигурации. В прототипе — константы CFG.dayFrom/dayTo с теми же значениями.

Упрощения прототипа

  • Нет сервера и БД: данные демо, состояние живёт до перезагрузки страницы.
  • Переработки и флаги считаем в пределах суток (ночные смены через полночь не моделируются).
  • Границы категорий ДЯ/ДН — константы CFG (06:00–22:00); в приложении они берутся из настроек («Категории дневных кодов») — замечание владельца от 12.10.2026.
  • Каскад при закрытии: сначала ДН, потом ДЯ — порядок упрощён относительно движка.
  • Отметки за дни без явных punches подставляются «чистые» по окну (демо полного выгруза СКУД).
  • Флаги: опоздание > 5 мин, ранний уход > 5 мин, «вне графика» — только если факт вообще не пересекается со сменой.
Доска
Оперативная доска (кто на смене сейчас) остаётся отдельным инструментом — вопрос Q7. В прототипе не моделируется.
Сотрудники
Справочники сотрудников и смен — в рабочем приложении (раздел «Сотрудники», словарь смен). В прототипе не моделируется.
