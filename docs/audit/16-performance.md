# 16. Узкие места производительности

Замеры запуском — [16b-query-budget.md](16b-query-budget.md): роль manager, SQLite, 11 и 71
сотрудник. ID → [REPORT.md](REPORT.md).

## 16.1. N+1 и число запросов
| Экран | SQL (11 / 71 сотр.) | Рост | Когда станет проблемой | Находка |
|---|---|---|---|---|
| `GET /api/night/reports` (архив, по умолчанию 60, максимум 365) | **750** на 31 отчёт | ~24 SQL на отчёт: ленивые `rep.areas` → `items` (`night_api.py:895-903`, `night.py:505-525`) | при архиве за год ~8 800 запросов и несколько секунд на запрос уже сейчас | PERF-01 |
| `GET /api/mgmt` и `/api/mgmt/xlsx` | 179 / 1 019 | 14 на сотрудника | 100 сотрудников ≈ 1 500 SQL, около 0,2 с на SQLite; на PostgreSQL по сети ×(1–2 мс) ≈ 2–3 с. Конвейер на сотрудника — осознанное свойство движка (`test_query_budget.py:21`, бюджет 40 на сотрудника) | PERF-02 |
| `GET /api/tabel` | 96 / 456 | 6 на сотрудника | 100 сотрудников ≈ 650 SQL; на PostgreSQL ≈ 1 с | PERF-02 |
| `GET /api/fact/month` | 64 / 304 | 4 на сотрудника | то же | PERF-02 |
| `GET /api/schedule` | 22 / 22 | не растёт | — (тест-страж есть) | — |
| `GET /api/presence/board` (поллинг каждые 30 с) | 15 / 15 | не растёт | 30 клиентов × 2/мин = 900 SQL/мин — нормально | — |
| `GET /api/employees`, `/api/cars`, `/api/audit`, `/api/settings`, `/api/engine-settings*` | 6–20 | не растёт | — | — |

Тест-страж `tests/test_query_budget.py` покрывает сетку, доску, сотрудников и УТ. **Не покрыты**:
архив ночи, Табель, Факт, кары, настройки, аудит. Предлагается добавить бюджеты (PLAN, фаза 6).

## 16.2. Права на запрос
`effective_permissions` (3–4 SQL) вызывается **1–2 раза** на запрос: в `require_perm` и повторно
в обработчике (`principal_permissions`, `has_perm`). Пример — `/api/schedule`, `/api/tabel`,
`/api/cars`: колонка «Права» в 16b-query-budget.md. Сейчас это не узкое место; при модульной
схеме прав предлагается кэш на запрос (`request.state`), см. TARGET-ARCHITECTURE.md §2.

## 16.3. Тяжёлые операции внутри запроса
- **PERF-04.** PDF через LibreOffice до 180 с (`deploy/nginx.conf:51-53` поднимает
  `proxy_read_timeout` до 200 с), DOCX, XLSX — синхронно в потоке threadpool. Клиентский
  таймаут — 20 с (UI-03). Одновременные PDF занимают потоки. При целевой нагрузке это
  терпимо, но кнопка «повторить» плодит процессы LibreOffice.
- Отправка недостатков службам: последовательные сетевые вызовы по 20 с (CONC-02).
- Вложения отправки читаются в память целиком (`attachments_of` → `a.blob`,
  `notify/application/dispatch.py:48-70`): видео до 50 МБ × число медиа. При пяти видео в
  отправке это 250 МБ RAM воркера (Вероятно, по коду).

## 16.4. Объём ответа и фронтенд
- `GET /api/schedule` на 71 сотрудника — **465 КБ** JSON за месяц. Gzip в приложении и nginx есть,
  но на телефоне 465 КБ парсятся заметно.
- JS: 11 файлов, около 520 КБ без минификации (`settings.js` 179 КБ, `night.js` 109 КБ,
  `timesheet_v4.js` 103 КБ) и `app.css` 79 КБ. Всё грузится на каждом устройстве: PWA сотрудника
  тянет экраны настроек и УТ, которыми он не пользуется. Service worker кэширует, так что
  повторно это стоит только после смены версии. ADR-0008 (без сборки) допускает ленивую
  загрузку разделов динамическим `<script>` без сборщика (TARGET-ARCHITECTURE.md §1).

## 16.5. Пагинация и индексы
| Список | Пагинация | Индекс |
|---|---|---|
| Журнал аудита | `limit ≤ 500`, `offset` (`audit_api.py:76-86`); CSV — до 20 000 строк | `audit_log.ts` |
| Рассылки | `limit` 100 / 2000 CSV | `notify_dispatches.domain`, `recipient_id`, `ref_id` |
| История кара | `limit` 200 | `ix_car_history_car_ts` |
| Архив ночи | `limit ≤ 365`, без offset | `night_reports.date` |
| Отметки | `limit = 2000` в коде (`punches.py:354`) | `ix_punches_emp_ts` |
| Фото | только по `(kind, ref_id)` | `ix_photos_kind_ref` |

Индексы на основных фильтрах есть (04-schema.md). Слабое место — `count(*)` журнала аудита по
`ILIKE '%…%'` (`audit_api.py:79`): полный скан. На сотнях тысяч записей (≈3 года) поиск будет
занимать секунды. Low.
