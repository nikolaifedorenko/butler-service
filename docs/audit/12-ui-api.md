## 12.2. Есть в UI, но работает не так
1. **UI-01. «Стартовый банк часов»** (`employees.js:453`, отправка `:518`, подсказка
   `:95` «старт + переработки − отгулы ± корректировки»). Значение сохраняется в
   `employees.balance_hours` (`employees.py:151,237,291`), но движок v7.1 банк из него **не
   берёт**: `bank_as_of` = итог последнего закрытого периода (`employees.py:408-412`), посев
   начального банка — корректировка `OPENING_SEED` (`:419-445`). Проверено запуском (EXP-BANK):
   2 → 999, `bank_now` 0.0 → 0.0. Побочный эффект: supervisor, которому корректировка банка
   запрещена (`_guard_bank`, `:389-392`), это поле менять может (EXP-SUPBANK). Ни на что это
   не влияет, но вводит в заблуждение.
2. **UI-02. Видимость по роли, а не по праву** (8 мест, список в
   [03-perm-matrix.md](03-perm-matrix.md)):
   - `timesheet_layers.js:140-143`: сетка Графика только для чтения, если `role === 'employee'`.
     Сотрудник с индивидуальным allow `schedule.edit` редактировать не сможет, а супервайзеру с
     deny `schedule.edit` клики по ячейкам открывают модалку, и уже при сохранении API ответит
     403. Тулбар при этом уже смотрит на право (`:21`), то есть поведение непоследовательно;
   - `app.js:296`: справочник сотрудников (`loadDirectory`) грузится по роли. Сотруднику с allow
     `employees.view` он не загрузится, а супервайзеру с deny получит 403, тихо пойманный;
   - `cars.js:313,339`: поле «кто вернул» показывается по роли, а API принимает `by_name` от
     любого (BUG-03);
   - `employees.js:408-409`: список ролей повторяет `can_manage_user`. Здесь роль уместна
     (правило иерархии ролей), но правило записано дважды;
   - `app.js:239`: стартовый раздел по роли. Это UX, не находка.
3. **UI-03. Обрыв долгих операций на клиенте**. `api()` по умолчанию прерывает запрос через
   20 с (`core.js:141`), а `timeout` передаёт только загрузка фото (`multipartApi`, 60 с). При
   этом отправка недостатков (`night.js:1505`) идёт последовательно по службам и каналам, по
   `notify_timeout` до 20 с каждый (`notify/application/config.py:27`). PDF через LibreOffice
   считается до 180 с, а закрытие периода выполняется в цикле по сотрудникам. Пользователь
   видит «Сервер не ответил вовремя», хотя сервер продолжает работу и всё сделает. Повторное
   нажатие повторяет отправку (CONC-02).
4. **Ошибки 403/409/410/413/422.** Единый разбор `httpError` (`core.js:113-131`) показывает
   `detail`, массив pydantic разворачивает в «поле: текст», у структурных 409 читает `payload`
   (`night.js:439,635`). Исключение — **413 от nginx** при теле больше 8 МБ (OPS-01): ответ
   HTML, `multipartApi` кладёт весь текст страницы в `detail`, и в тосте оказывается разметка
   nginx (`core.js:186-189`).
5. **UI-04. Кэш service worker** (`static/sw.js`). Навигация идёт сначала в сеть, статика берётся
   из кэша с фоновым обновлением по ключу `?v=`. Версии `index.html` и `sw.js` совпадают
   (`bump_version --check` ✓). Слабое место: `--check` проверяет только согласованность строк
   версии, а не «JS изменился, версию не подняли» (`tools/bump_version.py:54-100`). Забытый bump
   отдаст старый JS с кэшированным `?v=` при первой загрузке после деплоя.
6. **Глобальные функции.** `gen_js_globals.py --check` ✓ (322 имени). ESLint `no-undef` не
   запускался (нет Node, решение владельца).
