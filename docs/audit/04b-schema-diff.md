## Обновление более старых баз: старт падает (Факт, запуск)

Тем же скриптом (`schema_diff.py <коммит>`) проверено обновление баз, созданных кодом
трёх более ранних коммитов. Во всех трёх случаях `init_db()` текущего `main` падает:

| Коммит старой базы | Дата | Результат `init_db()` текущего кода |
|---|---|---|
| `d2e0ea2` | 06.10.2026 (движок v4) | `TypeError: tuple indices must be integers or slices, not str` |
| `66a264b` | 11.10.2026 (движок v7.1) | то же |
| `206d948` | 16.10.2026 (уже есть прод-профиль PostgreSQL) | то же |
| `b929007` | 19.10.2026 | успешно, 1 расхождение (таблица выше) |

Место: `app/bootstrap/migrations.py:757-758`. Строка результата `con.execute(text(...))`
без `.mappings()` — кортеж, обращение `r["id"]` в SQLAlchemy 2.x невозможно. Ветка
выполняется, только если в `shift_types` ещё есть колонка `tzh_code`, то есть у любой
базы, не обновлявшейся с 18.10.2026. Тестов на обновление старой базы нет, поэтому CI это
не ловит. Подробности в REPORT.md, находка DB-01.
