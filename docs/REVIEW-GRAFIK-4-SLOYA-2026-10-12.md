## 6. Вопросы — решены (ответы владельца от 12.10.2026)

**Q1. ✅ Ручное окно Графика — влияет ли на часы?** Противоречие снято: дело было в терминологии.
Решение: стандартное окно жёстко привязано к коду Табеля (Я 10,75 → 08:00–20:00, Я 8 → 09:00–18:00);
в Графике по умолчанию показывается табельное окно (стандартное окно сессии), его можно заменить
на ручную смену из справочника; **ручная смена на Табель не влияет никак** — при ночной смене
стандартное окно не меняется, движок всё делает сам, как сейчас.
**В прототипе v2.1:** переключатель режимов убран; демо — Петров 06.10 (в Графике ночная смена
20:00–08:00, окно и часы — из кода Табеля «Я 10,75»: план 12ч, отработано 12ч, без недоработки).

**Q2. ✅ Название пункта меню** — «График» (подтверждено). Внутри — слои 0 Табель / 1 План-График /
2 Факт / 3 Управленческий Табель.

**Q3. ✅ «Отпросился» и «выходной за часы» — одна сущность** (подтверждено): одна запись словаря,
две точки ввода (интервал / вся смена).

**Q4. ✅ Отсутствия из Графика — только «за счёт часов».** Отпуск / больничный / за свой счёт /
оплачиваемый выходной — только из Табеля (там же заявления). **«Недопуск» не добавлять** —
в Графике остаётся только «отпросился (выходной за часы)».

**Q5. ✅ «Сбросить» в Табеле** — как в прототипе: убирает введённые вручную коды за период,
возвращает автозаполнение, с подтверждением; закрытых периодов не касается.

**Q6. ✅ Код «НД» (недопуск к работе) — не добавляется.** «Забудь пока о нём; если будет надо —
я введу в табель новый код» (замечание 1). Задача T2 снята.

**Q7. ✅ Доска «Отметки»** — согласовано: оперативная доска остаётся отдельным пунктом меню,
сетка номеров с округлением — внутри слоя «Факт».

**Q8. ✅ «Отпросился / выходной за часы» — только информация** («чтобы мы не ждали сотрудника»).
Отсутствие отработанных часов в стандартном рабочем окне просто уходит в недостачу; при закрытии
периода недостачу оплачивает банк 1:1 — расчёт не меняется, отсутствие план не уменьшает.

**Q9. ✅ APP-SHIFT-CODE (6 ошибок в панели здоровья).** Ваша модель верна и не меняется: код Табеля
жёстко определяет стандартное окно, эти же часы попадают в График первоначальными сменами, далее
редактируются. Проблема не в модели, а в технической ошибке редактора смен: он отправляет короткое
имя смены («08-20»), а API записывает его в поле «код в табеле» (`tzh_code`). Значение «08-20» —
не код Табеля, его нет в словаре дневных кодов: health-панель честно выдаёт 6 ошибок, а ночные и
суточные смены из-за этого перестали заполнять Табель из циклов. Лечение минимальное (T1): в поле
«код в табеле» — только коды из словаря Табеля или пусто; границы смены уже хранятся в отдельных
полях. Новых сущностей и новых полей не нужно.

**Замечание 1 (12.10.2026). ✅ «Недопуск» — забыт.** Убран из прототипа (кнопка, тип отсутствия,
код «НД», легенда); если понадобится — владелец введёт новый код Табеля сам.

**Замечание 2 (12.10.2026). ✅ Деление переработок ДЯ/ДН — из настроек.** Движок уже берёт границы
категорий из конфигурации («Категории дневных кодов»: ДЯ/ДН/ДЯ2/ДН2, по умолчанию день 06:00–22:00,
ночь 22:00–06:00). В прототипе v2.1 границы вынесены в явные константы `CFG.dayFrom/dayTo` с пометкой,
что в приложении они берутся из настроек; упоминание добавлено в слои «Факт» и «Управленческий Табель».
