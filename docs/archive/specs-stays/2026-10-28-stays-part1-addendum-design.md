# Шахматка (stays), часть 1 — дополнение по итогам проверки владельцем — дизайн

**Статус:** согласовано владельцем 28.10.2026 (ответы на пять замечаний после проверки части 1 в
приложении). Опирается на часть 1 (`2026-10-26-stays-fund-versions-design.md`), выполняется до
части 2: пункты 3–5 меняют брони и гостей, на которые опираются части 2–4. Боевой базы нет —
**переноса старых данных не делаем** (колонки удаляются, демо-сид пересоздаётся).

## 1. Справочник видов категорий

Сейчас вид — четыре значения в коде (`fund.KINDS`: вилла, имение, апартаменты, номер); используется
только фильтром «Вид» и правилом «какие разделы дерева раскрыты по умолчанию».

* **Справочник** `stays_category_kinds`: `id, title TEXT(40) UNIQUE, sort_order, expanded BOOL`
  («раскрывать на шахматке по умолчанию»), `archived BOOL`. Не версионируется (как флаги);
  использованный вид — только в архив, удаление — 409.
* Категория в версии фонда ссылается на вид: `stays_category_states.kind_id → stays_category_kinds`
  (вместо строки `kind`). Вид обязателен.
* **Экран:** «Настройки → Фонд», вкладка «Виды»: название, порядок, «раскрывать», архив; права —
  `stays.setup`. В форме категории — выбор вида из справочника.
* **Где действует:** фильтр «Вид» (по `kind_id`); раздел дерева раскрыт по умолчанию, если в нём
  есть категория вида с `expanded = да`; файл фонда — колонка «Вид» на листе «Категории» по
  названию вида (неизвестное название — ошибка файла, новые виды файлом не заводятся).
* Демо-сид заводит четыре вида (вилла, имение, апартаменты — раскрывать; номер — нет).

## 2. Дерево в Excel — колонка «Родитель»

Путь одной ячейкой («Корпус / Блок B / Вид на море») неудобен, а колонки «Уровень 1…N» ограничивают
глубину.

* **Лист «Дерево»:** `ID | Название | Родитель | Порядок`. Одна строка — один узел. «Родитель» —
  полный путь родителя («Корпус / Блок B»), пусто — корневой узел. Глубина не ограничена.
* **Лист «Объекты»:** колонка «Узел» — полный путь узла.
* **Выпадающие списки:** при выгрузке файл получает скрытый лист «Списки» со всеми путями дерева, а
  колонки «Родитель» и «Узел» — проверку данных «список из листа „Списки“». Для новых узлов,
  добавленных в файл, список не обновляется сам — путь нового узла вводится руками (или файл
  выгружается заново после загрузки черновиком).
* **Разбор:** узлы строятся по «Родителю» в любом порядке строк (родитель может стоять ниже
  ребёнка); родитель не найден — ошибка «нет узла-родителя „…“» с листом и строкой; цикл
  невозможен (родитель задаётся путём). Уникальность пути держится запретом одинаковых названий у
  соседей и «/» в названии (уже есть).
* Файл, выгруженный и загруженный без правок, — по-прежнему пустой черновик.

## 3. Справочник гостей — вкладка «Гости»

* **Вкладка «Гости»** шахматки (право `stays.guests`; уровню «без персональных данных» вкладки
  нет): список — фамилия имя отчество, уровень, телефон (только полный уровень), последний заезд,
  число проживаний; поиск по фамилии, телефону (при `stays.guests`), номеру брони; фильтры —
  уровень, «был в периоде», «день рождения в ближайшие 30 дней»; сортировка по колонкам; по 200.
* **Карточка гостя:** профиль (с новым полем «Пол»), предпочтения, особые даты, настраиваемые поля,
  примечание, **семейное дерево** (§4), прочие связи, история проживаний (все брони, где гость
  жил, с объектом по фонду дня и батлером).
* **Создание и правка** — как сейчас в форме брони, теперь и отдельно; **объединение дублей**:
  выбрать двух гостей → «объединить в …»: брони, связи, предпочтения и особые даты переносятся,
  второй профиль удаляется; предпросмотр «что перенесётся»; аудит.
* **Пол гостя:** `stays_guests.gender` — `m | f | ''` (не указан).

## 4. Семейное дерево гостей

Сейчас связи — плоский список видов (`spouse`, `child`, `relative`, …): «невестки, свекрови»
приходится заводить вручную, и они не следуют друг из друга.

* **Храним только первичные связи:**
  * `parent` — A родитель B (у ребёнка не больше двух родителей);
  * `spouse` — A и B супруги (с признаком «бывшие»).
  Остальные виды связей — **не семейные** и остаются как есть: ассистент, охрана, водитель, няня,
  коллега, другое. Вид `relative` («родственник» без уточнения) остаётся для случаев, когда
  степень неизвестна. Связь `child` заменяется на `parent` (боевой базы нет — без переноса).
* **Родство вычисляется** (`domain/kinship.py`, чистая функция) обходом графа «родитель / супруг»:
  родители, дети, братья и сёстры (общий родитель), бабушки/дедушки и внуки, прабабушки/прадедушки
  и правнуки, дяди/тёти и племянники, двоюродные братья/сёстры, а также свойственники через брак:
  свёкор, свекровь, тесть, тёща, зять, невестка, деверь, золовка, шурин, свояченица, свояк.
  Название — по полу: без пола — нейтрально («родитель супруга», «ребёнок ребёнка»). Глубина — до
  прародителей и правнуков; дальше — «родственник (N-я степень)».
* Пример владельца: у Ивана и Марии добавлен сын → он сразу виден правнуком у бабушки Ивана и
  внуком у родителей Марии, без отдельных связей.
* **Проверки:** нельзя стать своим предком; родителей у ребёнка не больше двух; супругом нельзя
  сделать своего предка или потомка; при ошибке — 422 с объяснением.
* **Визуальный редактор** в карточке гостя: гость в центре, родители сверху, супруг(а) рядом, дети
  снизу, братья и сёстры по бокам; клик по человеку — он в центре; кнопки «+ родитель», «+
  супруг(а)», «+ ребёнок» — поиск существующего гостя или новый (фамилия, имя, пол); удалить связь
  — крестик на линии. Список «Все родственники» под деревом — вычисленные родственники с
  названиями.
* **Где ещё:** «Табло дня» и карточка брони показывают у гостя родственников среди проживающих
  («мать Ивана Петрова — Мария»); правило «явные гости другого батлера» (покрытие) не меняется.
* Видимость: семейное дерево — уровень «с фамилиями» и выше; даты рождения и телефоны — только
  полный уровень.

## 5. Бронь: «Оплата за» — категория, «Повод визита» — убрать

* `stays_reservations.paid_category_id → stays_categories NULL` вместо текста `paid_by`; в форме —
  выбор категории из фонда на дату заезда, по умолчанию — категория брони. Отличается от категории
  брони — в карточке и в «Бронях» пометка «апгрейд: оплачена DKG».
* `purpose` («Повод визита») удаляется: это примечание.
* Запертые для батлера поля брони (часть 4) — `paid_category_id` вместо «оплата»; «повод» из списка
  убирается. Колонки выгрузок и вкладки «Брони» — так же.

## 6. Тесты

* Виды: справочник CRUD, архив использованного, удаление использованного — 409; фильтр «Вид»;
  раскрытие по `expanded`; файл фонда — вид по названию, неизвестный — ошибка.
* Дерево в файле: «Родитель» в любом порядке строк; нет родителя — ошибка со строкой; глубина 6+;
  выпадающие списки в выгрузке; круговая выгрузка → пустой черновик.
* Гости: список, поиск, фильтры, права и уровни (телефон только при полном уровне и `stays.guests`);
  объединение дублей с предпросмотром ≡ сохранению; история проживаний.
* Родство: все названия из §4 по полу и без пола; пример владельца (сын → правнук бабушки Ивана);
  запреты (свой предок, третий родитель, супруг-потомок); бывшие супруги не дают свойственников.
* Бронь: «оплата за» — выбор категории, пометка апгрейда; повода визита нет в форме, API, выгрузке.
* jsdom: вкладка «Гости», семейный редактор (+ родитель / супруг / ребёнок, перецентровка), вкладка
  «Виды».
