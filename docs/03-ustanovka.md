# 3. Установка и эксплуатация

## 3.1 Локальная машина

Приложение, воркер, база и сервис PDF (Gotenberg) запускаются в Docker. Образ Gotenberg большой
(~2,4 ГБ с LibreOffice): при первом запуске нужен интернет.

* Нужны Docker Desktop (или Docker Engine с плагином compose) и ~4 ГБ под образы.

```bash
cd butler-service
docker compose up -d --build
```

Откройте http://127.0.0.1:8000, вход `admin` / `demo1234`. При первом запуске пустая база
заполняется демо-данными: сотрудники, блоки графика, Табель из циклов, отметки за ~1,5 месяца,
начальный банк, шахматка. Локальный профиль слушает только `127.0.0.1`, пароль базы в нём учебный.

| Команда | Что делает |
|---|---|
| `docker compose up -d --build` | собрать и запустить (после обновления кода — то же самое) |
| `docker compose logs -f app` | журнал приложения |
| `docker compose down` | остановить, данные сохранить |
| `docker compose down -v` | остановить и удалить данные (сброс демо-базы) |
| `PORT=9000 docker compose up -d` | другой порт |
| `DEMO_SEED=0 ADMIN_PASSWORD=… docker compose up -d` | пустая база с одним администратором |

Проверка схемы: http://127.0.0.1:8000/api/selfcheck. Swagger: http://127.0.0.1:8000/api/docs.
Для проверки с телефона в той же сети замените в `docker-compose.yml` публикацию порта на `"8000:8000"`.

### Если приложение не стартует

| Что видно | Что делать |
|---|---|
| `docker compose ps`: `app` перезапускается | `docker compose logs app` — причина в последних строках |
| «База данных не задана» | приложение запущено без compose: задайте `POSTGRES_HOST` и остальные `POSTGRES_*` |
| `port is already allocated` | порт занят: `PORT=8010 docker compose up -d` |
| «Нет прав на запись в …» | тома созданы не от пользователя `app`: команда в `deploy/README.md`, раздел 6 |
| Белый экран | консоль браузера (F12); чаще всего кэш — `Cmd/Ctrl+Shift+R` |

## 3.2 Боевой сервер

Одно место описания — [`deploy/README.md`](../deploy/README.md): Docker-профиль
(`docker-compose.prod.yml`: `db`, `gotenberg`, `migrate`, `app`, `worker`, `nginx`, `backup`), бэкапы с
шифрованием и проверкой восстановления, обновление версии, запуск не от root и установка без
Docker (systemd + nginx + HTTPS).

Обязательные значения в `.env` боевого профиля:

| Переменная | Смысл |
|---|---|
| `POSTGRES_PASSWORD` | пароль базы |
| `ADMIN_PASSWORD` | пароль `admin` при первом старте на пустой базе; демо-учёток в проде нет |
| `NOTIFY_SECRET_KEY` | ключ Fernet, шифрует токен Telegram-бота и пароль SMTP в базе. Храните копию вне сервера: потерян — токен и пароль вводятся заново |
| `BACKUP_AGE_RECIPIENT` | открытый ключ шифрования бэкапов (`BACKUP_REMOTE` — второй сервер) |

## 3.3 Переменные окружения приложения

Источник — `app/core/config.py` (читается из `.env` и окружения; лишние переменные игнорируются).

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DATABASE_URL` | — | адрес PostgreSQL целиком; старше `POSTGRES_*` |
| `POSTGRES_HOST` / `_PORT` / `_USER` / `_PASSWORD` / `_DB` | — / 5432 / timetrack / — / timetrack | адрес собирает приложение, пароль экранирует: допустимы любые символы |
| `APP_TZ` | `Europe/Moscow` | часовой пояс отеля |
| `SESSION_TTL_HOURS` | 48 | срок жизни сессии |
| `COOKIE_SECURE` | 0 | `1` — cookie только по TLS (включайте за HTTPS) |
| `CSRF_ENABLED` | 1 | защита CSRF; выключается только в тестах |
| `ALLOW_IMPERSONATION` | 1 | вход «как сотрудник»; `0` — выключить |
| `TRUST_PROXY_HEADERS` | 0 | IP клиента для лимита входа из `X-Forwarded-For`; `1` только за своим nginx |
| `CSP_REPORT_ONLY` | 0 | CSP без блокировки, для осторожной раскатки |
| `LOG_JSON` | 0 | JSON-лог запросов (в проде `1`, uvicorn стартует с `--no-access-log`) |
| `METRICS_ENABLED` | 0 | `/metrics` для внутреннего скрейпера |
| `API_DOCS` | 1 | Swagger и `/api/openapi.json`; в проде `0` |
| `MIGRATE_ON_START` | 1 | `0` — воркеры схему не мигрируют, а сверяют ревизию; миграции делает сервис `migrate` |
| `UVICORN_WORKERS` | — | число воркеров `app`; корректность при N > 1 обеспечена (лимит входа и сессии в базе, схему готовит `migrate`) |
| `NIGHT_SYNC_SECONDS` | 60 | период задачи «ночные отчёты» (не меньше 5) |
| `JOBS_POLL_SECONDS` / `JOBS_LEASE_SECONDS` | 5 / 900 | опрос очереди; на сколько секунд задача закрепляется за воркером |
| `DEMO_SEED` / `ADMIN_PASSWORD` | 0 / — | демо-данные; пароль `admin` пустой базы |
| `GOTENBERG_URL` | — | адрес сервиса PDF (в compose `http://gotenberg:3000`); пусто — PDF отключён |
| `GOTENBERG_TIMEOUT_SECONDS` | 60 | сколько ждать конвертацию одного документа |
| `NOTIFY_SECRET_KEY` | — | см. выше; `новый,старый` — смена ключа |
| `NOTIFY_TELEGRAM_API` | — | адрес Telegram Bot API (корпоративный прокси); из интерфейса не меняется |

## 3.4 Первый вход и настройка

1. Войдите под `admin` (пароль — `ADMIN_PASSWORD`; на демо-базе `demo1234` — смените демо-пароли:
   «Сотрудники» → «Изменить» → новый пароль).
2. Заведите сотрудников, группы графика, цвета должностей.
3. В «Настройках» добавьте смены (часы) и проверьте правила расчёта (округление, окна отметок).
4. Заполните график на месяц («Заполнить графиком»: цикл, сдвиг фазы, только пустые ячейки).
5. Раздайте логины; покажите кнопку «Пришёл на работу» («Мои отметки»).

Перед боевым запуском — чек-лист в [документе 5](05-bezopasnost.md), раздел 5.9.

## 3.5 Обновление версии

`docker compose up -d --build` (локально) или процедура из `deploy/README.md`, раздел 5 (боевой
профиль): сервис `migrate` применяет ревизии до старта `app`. Если после обновления странные
ошибки интерфейса — очистите кэш браузера: статика версионируется (`tools/bump_version.py`),
но service worker может держать прежнюю оболочку до перезагрузки.
