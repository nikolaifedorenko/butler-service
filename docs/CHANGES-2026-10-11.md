# Изменения батча «Движок v7.1» — 11.10.2026

Полное переписывание расчётного движка по спецификации v7.1
(`docs/overtime_spec_v7_1_final.md`) и ТЗ ред. 3 (`docs/archive/overtime_ai_tz_v3.md`);
UI/UX приведён в соответствие разделу 16; документация обновлена.
Карта «что было → что стало» — `docs/MIGRATION-MAP-v7.md`.

## Решения владельца (раунд вопросов от 11.10.2026)

1. **Цикл-редактор сохранён** как инструмент заполнения **Табеля**: циклы/блоки пишут
   коды и планы в первичный документ; График генерируется из Табеля по окнам
   CFG-WINDOWS (16.3).
2. **«Отпросился» — строго по спецификации**: согласованное отсутствие больше не
   списывает часы с банка и не уменьшает план — оно логически режет График для флагов
   и доски (RUL-ABSENCE-ONLY-FLAGS, v7/R17); недостача возникает из отсутствия
   присутствия в окне и гасится банком/кодами по периоду.
3. **Миграция данных не выполнялась**: расчётные данные прежних версий были тестовыми —
   при старте они очищаются (однократный маркер `engine_v7_reset`), демо-база
   пересоздаётся; отметки, сотрудники, периоды работы, корректировки и справочники
   сохраняются.
4. **Документация — полный комплект**: спецификация v7.1 и ТЗ ред. 3 включены в
   репозиторий как норматив; SPEC/README/ARCHITECTURE переписаны;
   `docs/overtime_spec_v4.md` удалён.
5. **EX-14 контроль 3 — таблица примера была ошибочна** (подтверждено после
   приёмочного тестирования, 11.10.2026): для куска [00:00, 12:00) на 31.10 выход
   «рабочее 12, недостача 0, кодов нет» противоречил модели (рабочее = кусок ∩ окно)
   и прогону B того же примера. Верна нормативная модель: рабочее 4, недостача 8,
   переработка ДН 6/ДЯ 2 гасится каскадом целиком (код УТ — «ДН 4» на 31.10).
   Спецификация исправлена (правка F-20, приложение А.11).

## Движок (app/engine)

* Домен переписан по каталогу 8.1 (одна функция — один файл): ~120 модулей;
  старое ядро v4 удалено (не параллельная ветка).
* Модель v7/v7.1: **окно — единственная операционная норма** (рабочее время, недостача,
  план карточки и ёмкость переносов — от окна; план строки Табеля — информационный
  атрибут, R15/R34/R13); «План=Факт» — единый предикат из 4 условий, освобождает день
  от недостачи, синтетика запрещена (R30/R12/R16); «Авто» — только колонка кода (R19).
* Согласованные отсутствия — UTC-интервалы через полночь ≤ 24 ч (R17); `domain/schedule/`
  (отрезки смен, слияние смежных, ожидаемые подинтервалы).
* Флаги — три кода: LATE (включая `actual_at = None` — след «не пришёл», R21),
  EARLY_DEPARTURE, OFF_SHIFT_ATTENDANCE; ABSENCE_GAP и MISSED_DAY удалены (R18/R21).
* Ядро сопряжения `pair_marks` (общее для часов, флагов и истории) проверяет чередование
  (`CHK-PUNCH-SEQUENCE`) и **не чинит** последовательность (R31/R32); пересортировка
  отметок в домене удалена — округление без изменения порядка (EX-47).
* `DeferredBlock` без `reason_code` (R1); `Adjustment.period` + CHK-OPENING «ошибка,
  не фильтр» (R9); каноническая сортировка `deferred_in` (R4/F-12); `OPENING_ROUNDED`
  возвращает стадия 2 (R8); `PLAN_EQUALS_FACT` восстанавливает `build_trace`.
* Effective-период по трудоустройству (R23/R27/R35): `EmploymentPort`, сужение периода,
  Табель читается полным периодом, отказ вне трудоустройства — раньше всех проверок.
* Четыре режима (R33): view незакрытого / чтение закрытого (без домена, снимок флагов) /
  close (атомарно: результат+флаги+банк+переносы+ClosingInputs+версии+состояние) /
  recalculate (ClosingInputs заморожены, данные свежие — R28, сохранение заменяет).
* Гранулярность периодов «месяц / половина месяца» (R36): цепочка, обёртки
  `month_period`/`half_month_period`, `close_month`/`recalculate_month`.
* Начальный банк — посев корректировкой `OPENING_SEED` только первого периода (R37);
  `PeriodState.opening_bank_set`; последовательное закрытие конструктивно без лазеек.
* Доска (16.2): `PresenceBoard` (a–d), популяция — `active_employees` (R38),
  `yet_to_come` — одна ближайшая запись на сотрудника (R40); история сессий
  `view_sessions` (16.4) — три индексных запроса, признаки диапазона.
* `now` — параметр use case'ов (R10); `ClockPort` удалён (F-15); системное время —
  в composition root (`app/api/engine_common.now_utc`).
* Валидация трёх уровней: 14 проверок CHK-* уровня 1 (файл на проверку), 9 проверок
  уровня 2 (`domain/validation/`, стадия 1, включая новый `CHK-PERIOD-BOUNDS`),
  уровень 3 — в адаптере Графика при чтении.
* Глубокая неизменяемость результатов (MappingProxyType по копиям, DataValue);
  каноническая форма SettleResult/FlagsResult (3.4) — тесты сравнивают целиком.

## Адаптеры и БД

* Новые таблицы: `schedule_shifts` (generated/manual, UTC), `schedule_absences`
  (логический разрез); колонки: `bank_adjustments.reason_code`, `period_closings.flags_json`.
* Удалены: `timesheet_rows` (legacy-расчёт), `schedule_entries` (старый график);
  `deferred_carry.reason_code` не мапится (base 15).
* Адаптеры: стабильный порядок отметок (ts, id) и sanitize как первая линия чередования;
  выборки по пересечению с периодом (F-04); opening = closing предыдущего периода
  цепочки; `PeriodState` с previous/next по гранулярности и признаком посева;
  save_deferred — замена входа следующего периода; группа сотрудника — из истории
  блоков подневно (RUL-GROUP-PER-DAY) без N+1.

## API и вкладки (раздел 16)

* «Отметки» — доска (a–d) вместо дублей «Кто на работе»/«Посещения»; ≤ 5 батч-запросов.
* «Факт» — новая вкладка истории сессий (`/api/fact/sessions`); сотрудник видит только свою.
* «График» — сетка из Табеля и смен (generated/manual) с логическими разрезами;
  редактор ячейки: ручная смена (якорь accepts_ut), «пропуск/отлучка» (в т.ч. через
  полночь), переход в Табель за кодом; «Назначить отсутствие» — коды Табеля на период;
  «План/Факт»-оверлей удалён (тяжёлый конвейер — только УТ, 16.1 п.2), `factview.py` удалён.
* «Табель» — коды и информационный план; «Заполнить из циклов» (ночная/суточная смена
  дробится на два значения — «С 16»/«С 8»/«С 24», строки справочников в демо-настройках);
  lock-состояния (open / last_closed с предупреждением / locked); валидация записи
  доменными проверками (F-16); guard «день вне трудоустройства» (409).
* «Управленческий табель» — период месяц/полмесяца (R36); view без режима «preview-close»
  (предпросмотр = живой view); карточка дня: расчётный план (окно) + информационный план
  строки (R39), флаги с текстами, «не в штате» дни (R35); закрытие/пересчёт по сотрудникам
  и пакетом; трасса и изъятия в карточке; Excel-выгрузка.
* «Мои отметки» — лёгкие данные без тяжёлого конвейера: смена из Графика, ожидаемые
  интервалы, часы по отметкам, банк **последнего закрытого периода**; корректировки банка:
  `OPENING_SEED` только в первый период, закрытый период — только через пересчёт.
* Настройки движка — новая структура payload (day_code_policy, windows {start,end},
  categories, weights, cascade/placement, groups, modifiers, global_defaults,
  period_granularity); граница версии — 1 или 16 число.

  юниты всех функций каталога, валидация 3 уровней, property-based (hypothesis:
