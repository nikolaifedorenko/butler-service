Перенесено из README 22.10.2026 (аудит, шаг 6.2) без изменений текста. Норматив расчёта —
[`overtime_spec_v7_1_final.md`](overtime_spec_v7_1_final.md), спецификация приложения — [`SPEC.md`](SPEC.md).

## Вкладки учёта (спецификация v7.1, раздел 16)

Пять вкладок расчётного контура независимы: открытие одной никогда не запускает
расчёт другой. Тяжёлый конвейер (`settle()` + `evaluate_flags()`) запускает
**только** вкладка «Управленческий табель».

### 1. Отметки — доска «прямо сейчас» (16.2)
* **(a)** сколько сотрудников на работе прямо сейчас и **(b)** сколько должно быть
  по Графику — независимые счётчики (расхождение не ошибка: Табель всегда прав).
* **(c)** карточки открытых сессий: «на работе с HH:MM», «уже работает N ч», ожидаемые
  интервалы сегодня. **Забытый уход виден как есть** — счётчик растёт, доска ничего
  не «закрывает»; такие карточки — рабочий материал для разбора перед закрытием месяца.
* **(d)** «кто ещё должен прийти» — **ближайший** незавершённый ожидаемый интервал
  сотрудника (одна запись на человека); завершившиеся интервалы не показываются —
  непроход фиксирует флаг `LATE` («ожидался — не пришёл») в УТ.
* Популяция — трудоустроенные на «сегодня»; ≤ 5 батч-запросов, обновление каждые 30 с.

### 2. График (16.3)
* Сетка **ФИО × дни месяца**, сгруппированная по блокам («Смена 1», «Смена 2»,
  «Пятидневка», «Другие смены»); в ячейке — значение Табеля и интервалы смен.
* **График — производный документ**: генерируется из Табеля по окнам CFG-WINDOWS
  (`source = generated`); ручная смена (`source = manual`) заменяет генерацию дня
  целиком и может пересекать полночь. День редактируем ⇔ его код Табеля принимает
  коды УТ (`accepts_ut = Да`, проверка по дню-якорю).
* **«Пропуск/отлучка»** — согласованное отсутствие: UTC-интервал (может через полночь,
  ≤ 24 ч), **логический разрез** смены (08:00–12:00 | 15:00–20:00) — хранимая смена
  физически не делится, удаление отсутствия восстанавливает отображение. Отсутствие
  **не влияет на план, часы и банк** — только на флаги и доску.
* Правка Графика не меняет часы (График — только флаги); она пересчитывает флаги
  незакрытого периода при следующем просмотре УТ. Закрытый период заморожен.
* Печать, Excel, PDF; батлеры видят сетку только на просмотр (без заметок).

### 3. Факт — история сессий (16.4)
* Сырые сессии «пришёл — ушёл» за произвольный диапазон (до 92 дней): точные моменты
  без округления, сессии через полночь, признаки «начата до диапазона» / «закрыта
  после диапазона» / «открыта сейчас». Три индексных запроса на диапазон.
* Вкладка не зависит ни от чего, кроме отметок: ни Табеля, ни Графика, ни расчётов.
* Сотрудник видит только свою историю.

### 4. Табель — первичный документ (16.5)
* Код дня и **информационный (зарплатный) план** строки; значение «Я 12», «К 9»,
  «Я 10,75»… Окно рабочего времени, недостача и план карточки УТ считаются **от окна**
  (CFG-WINDOWS), информационный план может быть меньше окна (обед в зарплатной норме).
* **Циклы — инструмент заполнения Табеля** (2/2, 3/3, 1/3, 5/2 с выбором выходных,
  произвольный цикл «ВВРРРРВВ»): «Заполнить из циклов» раскладывает смены по дням и
  подбирает значение по окнам. **Смена через полночь оформляется одной строкой в дне
  начала**: у суточных 08:00–08:00 это явка с окном, начинающимся вместе со сменой
  (08:00–20:00). Присутствие режется полуночью, поэтому часы после 00:00 попадают в
  карточку следующего дня: рабочее время = присутствие ∩ окно своего дня, всё вне
  окна — переработка. График после заполнения перегенерируется.
* Валидация записи — доменными проверками: код из CFG-DAY-CODES; код с часами ⇒ план
  > 0 и кратен 15 мин; код без часов ⇒ без плана; для значения с часами нужна строка
  CFG-WINDOWS.
* Редактируемость: незакрытый период — свободно; **последний закрытый** — с
  предупреждением «изменения попадут в результат только через пересчёт»; более ранние
  закрытые — только чтение. Дни вне трудоустройства не редактируются.
* «Назначить отсутствие» на период любой длины (в т.ч. через границы месяцев). Два
  способа: вид с кодом Табеля пишет код первичного документа (ОТ/ДО/Б/ОВ/НН…), вид без
  кода («Выходной за часы») — согласованное отсутствие в Графике, Табель остаётся явкой;
  заявление печатается по всему периоду целиком.

### 5. Управленческий табель — часы, переработки, банк (16.6)
* Период — календарный **месяц** либо **половина месяца** (1–15 / 16–конец) по настройке
  `period_granularity`; цепочка «предыдущий/следующий» — по той же гранулярности,
  границы цепочки — трудоустройство сотрудника.
* **Открытие**: месяц не закрыт → живой расчёт (`view`: недостача показана, коды не
  изымаются, банк предварительный, ничего не сохраняется); месяц закрыт → сохранённые
  результат и **снимок флагов** без пересчёта. При незакрытом предыдущем месяце —
  «сначала закройте предыдущий период».
* **Карточка дня**: значение Табеля, план (= длина окна), информационный план строки,
  полный факт, рабочее время, переработка, недостача, коды дня, итог УТ, флаги
  (`LATE`, `EARLY_DEPARTURE`, `OFF_SHIFT_ATTENDANCE`), признак «План=Факт».
  Дни вне трудоустройства — «не в штате».
* **Сводка банка**: входящий остаток (и нормализация при смене шага), корректировки,
  зачислено неоплачиваемых переработок, погашено банком, банк на закрытие (может быть
  отрицательным — перенос долга), общий долг и остаток.
* **Закрыть период**: недостача гасится банком (1:1), затем кодами по очереди
  CFG-CASCADE целыми гранулами; остаток переносится минусом банка; отложенные блоки
  (не нашедшие приёмника) — во вход следующего периода. Всё сохраняется одной атомарной
  транзакцией: результат, снимок флагов, банк, переносы, входной снимок, версии настроек.
* **Пересчитать**: только последний закрытый период и только пока следующий не закрыт;
  отметки, Табель и корректировки перечитываются **свежими**, входные остатки
  (`ClosingInputs`) заморожены; результат, банк, переносы и снимок флагов **заменяются**;
  исчезнувшие переносы удаляются из входа следующего периода.
* Отчёт об исключениях (`NO_RECEIVER`), изъятия каскадом и **трасса расчёта** —
  в карточке сотрудника; Excel-выгрузка сеткой «ФИО × дни».

### 6. Мои отметки (PWA)
* Большие кнопки **«Пришёл на работу» / «Ушёл с работы»**, смена сегодня (из Графика),
  ожидаемые интервалы, «вы на смене N ч», часы сегодня по отметкам, банк **последнего
  закрытого периода** (живой итог — только в УТ), история отметок с описанием
  переработок («с кем работал, что делал»).
* Отметиться можно только в период трудоустройства; во время согласованного отсутствия
  с запретом отметок (настройка вида в словаре) кнопка неактивна. Ворот отметок нет:
  все реальные отметки участвуют в расчёте (RUL-ALL-MARKS-COUNTED).
* Менеджер может поставить/исправить отметку за сотрудника задним числом (аудит) и
  отменить ошибочную.

### Прочие разделы (вне расчётного контура)
* **Сотрудники**: карточка (гражданство, служба, контакты близких), периоды работы
  (приём → увольнение → повторный приём), история должностей, переводы между блоками,
  ручные корректировки банка (+/−, с причиной, датой и автором).
* **Настройки** — единый центр конфигурации объекта (ред. 19.10.2026): область
  с под-разделами (у каждого собственный адрес `#/settings/…`, поиск по ⌘K),
  а не одна длинная страница:
  **Обзор** (действующая версия, здоровье конфигурации — теперь и по справочникам
  обхода/служб, что вступит в силу, изменения за 30 дней);
  *«Расчёт»*: **Расчёт** (лимит опоздания, часовой пояс, период, шаг,
  категории ДЯ/ДН, веса кодов УТ, порядки каскада и размещения) · **Правила оплаты**
  (четыре модификатора карточками: глобальное значение, переопределения, мастер
  «что → кому → когда» и «Проверитель») · **Коды и окна Табеля** (флаги кодов, цвета,
  значения и окна, полоса суток) · **Календарь правил**
  (день × кто: переопределения, двойные дни, ВИП-периоды, версии — слоями);
  *«Персонал и смены»*: **Группы и графики** · **Смены и отсутствия** (словарь Графика,
  архив вместо удаления, ревизии, связь словарей);
  *«Объект»*: **Ночной обход** (зоны → объекты → чек-листы → службы: master-detail
  вместо прежней модалки в разделе, право `night.edit`) · **Электрокары** (парк
  и места стоянки, право `cars.manage`) · **Документы и справочники** (реквизиты, виды
  заявлений и бланки .docx, департаменты/службы, прочие правила объекта);
  *«Доставка»*: **Чаты и Почта** (транспорт один на приложение);
  *«Администрирование»*: **Права доступа** и **Журнал аудита** (убраны из верхнего
  меню — открываются отсюда) · **Система** (данные, версии и откат, аудит настроек,
  диагностика) · **Режим эксперта** (тот же черновик в виде JSON). Правки справочников
  расчёта идут через черновик → diff → публикацию версии; проверка CHK-* выполняется
  до сохранения, конфликт правил одного уровня не сохраняется (409). Перенос
  справочников из разделов и карта изменений — `docs/archive/changes/CHANGES-2026-10-19-settings-ia.md`,
  упрощения 18.10 — `docs/archive/changes/CHANGES-2026-10-18-settings-simplify.md`.
* **Ночной отчёт** (v2, 19.10.2026): обход построен в три уровня — **зона → объект →
  чек-лист** («Семейные виллы» → «Вилла 4001»… → пункты), поэтому десятки однотипных
  объектов не сваливаются в один длинный список; на каждом уровне свой прогресс
  (закрыто / в работе / замечания). Чек-лист задаётся **на зону** и действует для всех
  её объектов, а индивидуальные особенности объекта правятся точечно (своя формулировка,
  отключить пункт, свой пункт). Отметки ОК/Не ОК с комментарием и фото, перехваты
  объектов, шаг «Проверка электрокаров» (отдельный шаг, не зона), закрытие смены
  и выгрузка DOCX/PDF (в выгрузке области сгруппированы по зонам).
  Смена закрывается сама в 08:00 — это делает фоновая задача сервера (запросы
  раздела только читают базу); незакрытые области дают итог «неполный».
  Супервайзер может **переоткрыть** закрытый отчёт для правок: автозакрытие для
  него отключается, и смену закрывают повторно вручную (в выгрузке и интерфейсе
  такой отчёт подписан «переоткрыт вручную»).
  Справочник обхода (зоны · объекты · чек-листы · службы, включая мастера серии
  «Вилла 4001…4012») с 19.10.2026 живёт в «Настройках → Ночной обход»; кнопка
  «Справочник ↗» в разделе — deep-link туда. Правки применяют к ещё не начатым
  объектам текущей и следующих смен: чек-лист попадает в отчёт снимком при создании смены. План дальнейшей переработки (ответственные службы и рассылка
  недостатков в Telegram/почту) — `docs/archive/changes/CHANGES-2026-10-19-night-report-v2.md`. Окно отметки кара
  в обходе (19.10.2026) сделано так же, как окно возврата кара в «Электрокарах»:
  чекбокс **«Кар найден на месте»**, место — выпадающим списком из справочника мест,
  заряд, группа чекбоксов состояния («Технически исправен», «Чистый», «В салоне вещи»,
  «Тент», «Заряжается»), комментарий и **фото** (съёмка камерой смартфона или выбор
  из галереи, оригинал до 12 МБ). Снимок привязывается к отметке обхода, виден
  в списке обхода (значок 📷) и попадает в DOCX/PDF вместе с таблицей каров.
  Мест в отметке два: **«Где нашёл»** и — при отмеченном чекбоксе **«Перепаркован на
  другое место»** — **«Куда переставил»** (оба списка из справочника): найденный кар
  батлер мог переставить, а место в карточке могло устареть. Перепарковка — факт,
  а не замечание: переход «X → Y» виден в обходе (бейдж «перепаркован»), в истории
  кара (`found_location`/`location_from`) и в выгрузке.
  Правило статуса отличается от возврата: на обслуживание кар уводит только снятая
  галочка «Технически исправен», а «кар не найден» и «не исправен» идут в замечания
  супервайзеру; «в салоне вещи» и «не чистый» — факты карточки кара.
* **Электрокары** — раздел прежний (операции взять/вернуть/передать/выдать, история),
  но справочник парка и мест стоянки переехал в «Настройки → Электрокары»: кнопки
  «+ Кар ↗» и «Места ↗» ведут туда (право `cars.manage`). **Права доступа** и
  **Журнал аудита** убраны из верхнего меню — они в «Настройках → Администрирование»
  (меню: 7 пунктов вместо 9).

## Правила расчёта — модель v7/v7.1 (кратко)

Полная норма — [`docs/overtime_spec_v7_1_final.md`](overtime_spec_v7_1_final.md).

1. **Сессии первичны, дни — нарезка.** Отметки сопрягаются в сессии на всей временной
   оси (ядро `pair_marks` проверяет чередование «пришёл/ушёл» и **не чинит** его —
   нарушение данных останавливает расчёт), обрезаются по горизонту
   `H = min(now, полночь после конца периода)` и режутся локальными полуночами.
   «Ушёл ровно в 00:00» — кусок нового дня нулевой и отбрасывается. Забытый уход =
   непрерывное присутствие до горизонта.
2. **Округляются только моменты** отметок и `now` — до ближайшего кратного шагу
   (ровно половина — вперёд по времени). Длительности не округляются никогда: границы
   окон и категорий лежат на той же сетке, поэтому факт, рабочее время, переработка,
   коды, недостача и план карточки кратны шагу автоматически.
3. **Окно — единственная операционная норма** (R34): рабочее время = факт ∩ окно;
   переработка = части факта **вне окна**; **недостача = max(0, длина окна − рабочее
   время)**; **план карточки = длина окна**; ёмкость дня для переносов =
   `лимит − длина окна − Σ размещённых кодов`. Информационный план строки Табеля —
   зарплатный атрибут: может быть меньше окна (обед) и в расчёте не участвует.
4. **Две валюты**: недостача начисляется 1:1; погашение кодом и зачисление в банк —
   по весу кода (1 ч ДЯ2 = 2 ч банка); погашение банком — 1:1.
5. **Долг — часть периода**, не дня: общий долг = Σ недостач + отрицательная часть
   банка; гасится банком, затем кодами по CFG-CASCADE (ДЯ → ДН → ДЯ2 → ДН2), внутри
   тарифа — по дате происхождения; изъятие — целыми гранулами шага, гранула дороже
   остатка не изымается; непогашенный остаток переносится минусом банка.
6. **Перенос кодов — только вперёд**: коды дней, не принимающих УТ (ОТ, ДО), и
   неоплачиваемые переработки размещаются в ближайшие дни с `receiver_ok = Да`
   (порядок тарифов — CFG-PLACEMENT); недопустимый день пропускается, а не
   превращается в банк; не нашедшие приёмника блоки уходят в следующий период
   (`deferred_blocks`) с исключением `NO_RECEIVER`.
7. **«План=Факт»** — единый предикат из четырёх условий: значение несёт часы ∧
   модификатор разрешён в «Да» («Авто» — только колонкой кода, стартово у «К») ∧
   в дне нет ни события присутствия (исходной отметки), ни факта. Применение
   **освобождает день от недостачи** и обнуляет план карточки; синтетические отметки
   и факт не создаются; флаг «не пришёл» в такой день не ставится.
8. **Табель — часы, График — флаги.** Расхождение Табеля и Графика не ошибка
   (RUL-TIMESHEET-WINS). Флагов три: `LATE` (в т.ч. `actual_at = None` — след
   «ожидался — не пришёл», живёт до конца дня и остаётся в снимке закрытого периода),
   `EARLY_DEPARTURE`, `OFF_SHIFT_ATTENDANCE`. Согласованное отсутствие отдельного
   флага не имеет и на часы не влияет.
9. **Периоды закрываются последовательно**: закрыть (и посмотреть) период можно,
   если предыдущий закрыт либо для **первого** периода сотрудника посеян начальный
   банк корректировкой `OPENING_SEED`. Периоды вне трудоустройства не рассчитываются
   и не показываются; период сужается до эффективного (∩ трудоустройство), а Табель
   читается полным периодом — строки вне трудоустройства отбраковывает домен.
10. **Закрытый период иммутабелен**: просмотр — из сохранённых данных (включая снимок
    флагов); исправления попадают в результат только через пересчёт последнего
    закрытого периода.

## Администратору: справочники и операции (DoD-чеклист)

Все справочники — данные (формы в «Настройки → Коды и окна Табеля» / «Расчёт», тот же
черновик в JSON — «Настройки → Режим эксперта», либо таблица `engine_settings_versions`);
новое требование реализуется **строкой справочника, а не правкой кода**. Перед сохранением
версия проверяется правилами CHK-* уровня 1 — все нарушения сообщаются разом, а «Обзор»
показывает их до публикации (`GET /api/engine-settings/health`).

**Запуск расчёта.** Вкладка «Управленческий табель» → выбрать период → открыть
(живой `view`) → «Закрыть период» / «Пересчитать». Из кода:
`app.engine.application.view_period / close_period / recalculate(employee_id, period, now, ports)`
(`now` передаёт вызывающий слой; порты собирает `app.engine.adapters.factory.build_ports`).

**Кодов «Суточная смена» и «Выходной за отработанные часы» в Табеле нет** (норматив
от 12.10.2026): первый случай — графиковая смена с явкой в Табеле (см. выше), второй —
согласованное отсутствие в Графике при явке в Табеле, а день оплачивается из банка
часов (недостачу гасят накопленные переработки, паттерн EX-29).

**Добавить код Табеля** — строка в `day_code_policy` (CFG-DAY-CODES):
`{"Ночной код": {"carries_hours": …, "accepts_ut": …, "counts_in_ut": …,
"plan_equals_fact_auto": …}}`. `plan_equals_fact_auto = true` — единственный источник
разрешения «План=Факт = Авто» (стартово — у «К»).

**Добавить значение Табеля и окно** — строка в `windows` (CFG-WINDOWS): ключ
канонический `"<код> <часы>"` (дробь через запятую, ≤ 2 знаков, без хвостовых нулей:
«Я 10,75»), границы кратны шагу, окно не пересекает полночь. **Информационный план
строки может быть меньше длины окна** (обед в зарплатной норме, CHK-WINDOW-PLAN);
план карточки, рабочее время и недостача всегда считаются от окна. Пример:
`"Я 10,75": {"start_minute": 480, "end_minute": 1200}` — план строки 645 мин,
план карточки 720 мин (паттерн EX-15/EX-51) — именно так в демо оформлена суточная
смена: в Табеле «Я 10,75», по факту работа 08:00–08:00 через полночь.

**Суточная и ночная смена — данные Графика, а не код Табеля** (норматив от 12.10.2026).
В справочнике кодов Табеля нет «Суточной смены»: в Табеле стоит обычная явка, а расчёт
сам разделяет присутствие по полуночам — рабочее время это пересечение с окном своего
дня, всё вне окна становится переработкой.

Пример: 01.10 в Табеле «Я 10,75» при окне 08:00–20:00, в Графике смена 08:00–08:00
следующих суток, сотрудник пришёл 01.10 08:00 и ушёл 02.10 08:00. Присутствие делится
на 01.10 08:00–24:00 и 02.10 00:00–08:00; из первого куска вырезается окно —
переработка 01.10 ДЯ 2 (20:00–22:00) и ДН 2 (22:00–24:00), 02.10 ДН 6 (00:00–06:00)
и ДЯ 2 (06:00–08:00). Недостачи нет: рабочее время 01.10 равно длине окна.

Часы в значении Табеля («10,75») — **информационный зарплатный атрибут**: в расчёте
участвует только окно (план карточки, рабочее время и недостача считаются от него,
R34/RUL-PLAN-BELOW-WINDOW). Отдельной сущности «зарплатная норма смены» в системе нет
и не нужно: значение в ячейку ставит табельщик, а строка справочника окон для него
должна существовать (в демо — «Я 10,75» с тем же окном 08:00–20:00).

**Глобальные значения правил оплаты** («Оплачиваются ли переработки», «Двойные
переработки», «План=Факт») — «Настройки → Правила оплаты»: карточка правила с
переключателем (уровень 7). Сохранение создаёт новую версию справочников; она
применяется к периодам, **начинающимся** с указанной даты (версия выбирается по
`period.start`) — диалог публикации показывает настоящую дату применения, а экран
«Обзор» держит список «Вступит в силу». Какое значение подействовало у конкретного
сотрудника в конкретный день и почему — «Проверитель»
(`GET /api/engine-settings/rules/resolve`): уровень приоритета 1–7 и источник
(ручное правило, производственный календарь, ВИП-период, глобальный дефолт, колонка кода).

**Добавить модификатор дня** — «Настройки → Правила оплаты» (мастер «что → кому →
когда») или «Календарь правил» (клик по дню); таблица `day_modifiers`,
либо строка `modifiers` в версии справочников: имя (`double_overtime`, `pays_overtime`,
`plan_equals_fact`, `counts_in_ut`), значение и ровно одна из шести форм области:
сотрудник+день, сотрудник+период, группа+день, группа+период, день, период.
Приоритет разрешения — от сильной формы к слабой, завершается глобальным дефолтом
(для «Учитываются ли часы в УТ» — колонкой кода). Дни двойной оплаты и ВИП-периоды
подмешиваются как «Двойные переработки» автоматически.

**Добавить группу** — элемент списка `groups` (CFG-GROUPS); группа хранится в строке
Табеля каждого дня, перевод между группами внутри периода допустим (RUL-GROUP-PER-DAY).

**Изменить порядок размещения / каскада** — `placement_order` (CFG-PLACEMENT: порядок
тарифов при переносе) и `cascade_order` (CFG-CASCADE: очередь погашения недостачи
кодами; банк гасит долг первым всегда — это закон). Изменение одного не влияет на другое.

**Закрытие и пересчёт.** «Закрыть период» доступен с 00:00 дня после конца
(эффективного) периода, при закрытом предыдущем периоде либо посеянном начальном банке.
«Пересчитать» — только последний закрытый период, пока следующий не закрыт.
Повторное и конкурентное закрытие исключены (уникальный ключ + транзакция).

**Просмотр закрытого периода** — открывается так же, как живой: данные читаются из
хранилища (результат + снимок флагов), расчёт не выполняется.

**Передача отложенных блоков** — автоматически при закрытии: `deferred_blocks`
сохраняются во вход следующего периода (`CarryOverPort.save_deferred`); пересчёт
**заменяет** их (исчезнувшие удаляются). Входящие блоки принимаются как есть
(в банк повторно не зачисляются), при смене шага нормализуются к новому шагу
(`OPENING_ROUNDED` в трассе).

**Начальный банк (посев)** — карточка сотрудника → корректировка банка с кодом
`OPENING_SEED` в первом периоде цепочки (посев разрешён только первому периоду;
в остальные — отказ). Посев виден в «корректировках» сводки банка.

**Гранулярность периода** — `period_granularity`: `"month"` (по умолчанию) или
`"half_month"` (1–15 / 16–конец месяца); меняется только на границе цепочки периодов.
