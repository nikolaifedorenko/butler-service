# Изменения 16.10.2026 (батч 7) — Настройки: сняты предупреждения APP-CODE-NO-SHIFT («К», «НБ») + аудит всех проверок

Задача владельца: в разделе «Настройки» (экран «Обзор») остались два предупреждения —
`APP-CODE-NO-SHIFT` для кодов Табеля «К» и «НБ» («У кода Табеля … нет вида смены с этим
кодом — поставить его из Графика нельзя»). Требовалось убрать их и **проверить ещё раз
все настройки**.

## Аудит всех проверок (до правок)

Свежая демо-БД, `GET /api/engine-settings/health` под админом:

* доменные проверки CHK-* — чисто (расчёт не останавливается);
* прикладные сверки APP-* — ровно два предупреждения `APP-CODE-NO-SHIFT` («К», «НБ»);
  APP-SHIFT-CODE, APP-GROUP-UNUSED/UNKNOWN, APP-CODE-NO-WINDOW — чисто;
* паспорт: версия справочников #1, 9 кодов, 7 окон, 4 группы, правил/UQ-версий нет.

То есть конфигурация здорова, два предупреждения — единственные. Разбор показал, что
причины у них **разные**: «НБ» — настоящее отсутствие вида в словаре, «К» — код, которому
вид смены не нужен по устройству домена.

## «НБ» — новый вид отсутствия «Неоплачиваемый больничный»

«НБ» в справочнике CFG-DAY-CODES не несёт часы (`carries_hours=False`) — это настоящий
код первичного документа (лист нетрудоспособности без оплаты), такой же, как «Б», «ОТ»,
«ДО». Назначение отсутствия на период (`POST /api/schedule/range-absence`) ставит такие
коды в Табель по `tzh_code` вида — но вида с кодом «НБ» в словаре не было, поэтому из
Табеля его поставить было нельзя, и health честно предупреждал.

* **seed**: в `SHIFT_TYPES` добавлен вид `SICK_UNPAID` — «Неоплачиваемый больничный»,
  подпись «НБ», код Табеля «НБ», `kind=absence`, `is_working=False`,
  `counts_as_worked=False`, цвет `#c0504d` (тот же, что у кода «НБ» в `CODE_COLORS`),
  порядок 85 (рядом с «Больничным»). Заявления у вида нет (как у «Б» — оформляется
  справкой, не заявлением), отмечаться не запрещён.
* **существующие БД**: добирает уже имеющаяся `_migrate_missing_shifts()` (в
  `migrate_db()` при старте) — новых миграций не потребовалось. Проверено на БД,
  созданной кодом до правки: после старта вид появился, health стал чистым.
* вид автоматически попал в модалку «Назначить отсутствие (код Табеля)» слоя 0
  («Неоплачиваемый больничный · код Табеля «НБ»») — списки строятся из словаря.

## «К» — документарному коду вид смены не нужен (проверка пропускает «Авто»)

«К» (командировка) устроен иначе: код **несёт часы** и это единственный код с
`plan_equals_fact_auto=True` (R19 — «План=Факт = Авто» разрешается в «Да» только им).
Табель первичен (приказ о командировке), График генерируется из Табеля
(`rebuild_generated_schedule`), а назначение отсутствия коды с часами отклоняет
(«Код несёт плановые часы — это не отсутствие»). То есть из Графика «К» не ставится
**по устройству домена**, а не из-за разрыва словарей, — предупреждение было ложным.

* `_app_checks()` (`app/api/engine_settings_api.py`): коды с `plan_equals_fact_auto`
  больше не дают `APP-CODE-NO-SHIFT`. Для остальных кодов проверка прежняя.
* хинт панели «Связь словарей · справочно» дополнен: документарному коду с
  «План=Факт = Авто» (R19) вид смены не нужен — Табель первичен, График генерируется
  из Табеля.

## Попутные дефекты, найденные аудитом (исправлены здесь же)

1. **Архивные виды считались «живыми»** — `_app_checks` фильтровал словарь через
   `getattr(s, "archived", False)`, но атрибута `archived` у модели `ShiftType` нет
   (архив — это `active=False` + `archived_at`, см. `_shift_dict`): getattr всегда
   возвращал False, и разрыв справочников через архив вида проверка не видела.
   Исправлено на `s.active and not s.archived_at`; регресс-тест архивирует «НБ» и
   ждёт предупреждение, после возврата — снова чисто.
2. **Падение старта на миграции словаря** — raw-INSERT в `_migrate_missing_shifts()`
   не перечислял `punch_in_allowed`/`punch_out_allowed`, а в БД, созданных
   `create_all` (колонки NOT NULL без серверного дефолта), такой INSERT падал с
   `IntegrityError` — приложение не стартовало. Поймано прогоном миграции на старой
   БД (см. выше). Колонки добавлены в INSERT (значения — из `SHIFT_EXTRA`, дефолт 1).
3. **Демо-«отпросился» попадал на выходной** — сид ставил интервальное отсутствие
   Иванова на фиксированный `today−3`; раз в 4 дня это «В» цикла 2/2, а в дне без
   смены с часами блок отсутствия в ячейке не показывается (правило 16.10.2026) —
   сценарий `run_norms_scenario.sh` на чистом main сегодня валился (7 провалов:
   модалка дня без блока «Отпросился», второй интервал, печать). Теперь демо-день —
   ближайший рабочий день по Табелю назад от `today−3` (`plan_minutes > 0`).
