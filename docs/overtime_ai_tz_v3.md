## 1. Назначение

Реализовать детерминированный расчётный движок: часы и переработки, банк минут, управленческий табель (УТ), закрытие/пересчёт периода, информационные флаги посещаемости, доску «кто сейчас на работе» и историю сессий — на данных Табеля, отметок `in/out` PWA, Графика (смены и согласованные отсутствия), банка и настроек. Домен — чистые функции «данные → данные»; чтение/запись, текущее время и состояние закрытия — в `application`, `ports`, `adapters`, человекочитаемые тексты — в `interface`.

Существующий прототип: сначала изучить (расчётный код, модели, источники, точки вызова, тесты), составить карту «что есть → какой слой/порт заменяет» (base 0.1). Спецификация главнее прототипа; старый движок в конце удаляется, а не остаётся параллельной веткой.

## 2. Архитектурная модель

Пять слоёв, зависимости только вниз (base 2.1):

- `domain` — типы, справочники, чистые функции, инварианты. Не импортирует никого.
- `application` — use case'ы: собрать вход из портов → вызвать домен → сохранить/склеить. Знает `domain` и `ports`.
- `ports` — только `Protocol` + доменные типы.
- `adapters` — реализации портов поверх БД/PWA/часов прототипа; валидация уровня 3 (График) — здесь.
- `interface` — существующие HTTP/UI-точки; **единственное место** человекочитаемых текстов (по коду + параметрам `Reason`/`Flag`).

**Четыре независимых расчёта** (base 2.1, 16.1): `settle()`, `evaluate_flags()`, `assemble_board()`, история сессий (`view_sessions` на ядре `pair_marks`). Расчёты друг друга не вызывают. Из результата `settle()` флаги получают **только** `plan_equals_fact: Mapping[date, bool]` — никаких карточек, банка, кодов, долга (архитектурный тест, base 13 п.5). Общее ядро сопряжения отметок — `pair_marks` (без настроек, без состояния).

В `domain` запрещены: `datetime.now()`/`date.today()`, I/O (БД/файлы/сеть/окружение), `print`/`logging`, случайность, неявное глобальное состояние. `tz` — только поле `Settings`. «Сейчас» — параметр `now` (UTC-aware).

## 3. Принципы реализации

### 3.1 Обязательные свойства

- **Детерминизм:** одинаковые входы → идентичные результаты, включая порядок кортежей (каноническая форма, §4.4). Порядок строк из источников не влияет: отметки — стабильная сортировка адаптера (base 7.4 п.7), `deferred_in` — каноническая сортировка домена (R4).
- **Глубокая неизменяемость** (base 2.5): `frozen` dataclass; последовательности в полях — `tuple`; `Mapping`-поля — read-only представление по копии; значения `Reason.data`/`Flag.data` — только `DataValue`. Единственное исключение — аккумулятор `Codes` внутри `settle()` (наружу не выходит, внутренние коллекции не отдаёт).
- **Трассируемость:** каждое действие, меняющее результат, — запись `Reason(step, code, data)` с исчерпывающим фиксированным составом `data` (base 6.2); изъятия — `Cut`.
- **Поведение из справочников** (base 2.3): разрешены три вида условий — защита от структурно невозможного, чтение из справочника, арифметика/сравнение. Никаких веток по строковым кодам (`if day.code == "ОТ"` — запрещено).
- **Одна функция — одно действие** (base 2.2): ≤ ~20 строк, вложенность ≤ 2, один цикл, всё параметрами. Функции-сценарии — только `settle()` и `evaluate_flags()` (каждая строка — вызов стадии).

### 3.2 Запреты (индекс антипаттернов — base 12)

Смешивание слоёв в одной функции; ветвление по строковым кодам; системное время в домене; скрытое состояние между вызовами; «магические» корректировки минут; мутация входов; **округление длительностей** (округляются только моменты отметок, `now` и входящие остатки при смене шага — base 4.5, RUL-ROUNDING-SCOPE); пересортировка отметок после округления; **синтетические отметки/факт** (включая «План=Факт» — R16); человекочитаемые строки из домена; тип отметки из её позиции; привязка сессии к смене Графика / «сменный день»; График и отсутствия в `settle()` (RUL-SCHEDULE-ONLY-FLAGS); «сальдо» и `abs(work − plan)`; проверки, требующие строк Табеля, внутри `validate_settings`; **«починка» последовательности отметок в домене** — пропуск дубля, тип по позиции, пересортировка, синтетическая пара, молчаливое продолжение расчёта (base 12.22, R31); **собственная копия условия «План=Факт»** или его расширение окном/Графиком (base 12.23, R30); **оркестрация режимов «на глаз»** — сохранение в `view`, `settle()` при чтении закрытого периода, старт `recalculate` с прошлого результата (base 12.24, R33).

### 4.4 Каноническая форма результата (тесты сравнивают целиком!)

- `cards` — по одной на каждый день периода, по возрастанию; `mgmt_timesheet` — ключ на каждый день (пустой день — пустой `Mapping`).
- `exceptions` — по стадии, затем по дате, затем по порядку тарифов CFG-PLACEMENT.
- `trace` — по стадиям; внутри стадии по дате и порядку обхода: размещение и `credit_unpaid` — CFG-PLACEMENT, каскад — CFG-CASCADE, нормализация — банк первым, затем блоки в каноническом порядке `deferred_in` (R3).
- `deferred_blocks` — по `source_day`, затем по порядку тарифов CFG-PLACEMENT (R2).
- `cuts` — в порядке каскада.
- `flags` — по `day`, затем по порядку кодов реестра (§11), затем по возрастанию временного ключа. Порядок флагов в таблицах примеров **не нормативен** (R6).
- `data` записей — **ровно** ключи реестра; значения — `DataValue`; моменты UTC-aware, даты `date`, длительности — целые минуты.

## 5. Источники данных и выборка отметок

Внешние источники (base 1.1): Табель, PWA (отметки), График (смены, отсутствия — **только флаги и доска**), модификаторы, банк (остаток + корректировки), настройки, входящие `deferred_in`. Период, режим и `now` — внешние входы use case'а.

**Формула выборки (base 7.4, нормативно):**

```
from_utc = локальная 00:00 period.start − step   → UTC
to_utc   = локальная 00:00 (period.end + 1) + step → UTC
marks        = PunchPort.marks_between(employee, from_utc, to_utc)     # [from, to) — R7
opening_mark = PunchPort.last_mark_before(employee, from_utc)           # строго < from — R7
```

Запас в шаг нужен, чтобы отметки у границ, округлённые внутрь периода, не терялись (EX-38); `opening_mark` восстанавливает сессию, открытую до периода (одной отметки достаточно — чередование гарантировано; EX-14 прогон B). Домен сам округляет, сопрягает, обрезает по горизонту и режет по дням; всё за горизонтом отбрасывается (часы через границу периода не переносятся).

Обязанности адаптера отметок (постусловия выборки — base 7.4, семь пунктов, R31): UTC-aware; корректный `kind` из источника; **все отметки одного сотрудника**; допустимое чередование по всей выборке включая `opening_mark` (**первая линия**; вторая — проверка ядра `pair_marks`, `CHK-PUNCH-SEQUENCE`); нет отметок позже `now`; не восстанавливать тип по позиции и не подмешивать синтетические отметки; **стабильный порядок** — сортировка по исходному моменту, при равенстве — по id источника, иначе «пришёл» раньше «ушёл» (RUL-DETERMINISM-AND-ORDER). Домен округляет **без пересортировки** (EX-47). Нарушение чередования — граница данных, не доменный сценарий: домен бросает исключение и ничего не «чинит» (EX-14 контроль 2).

## 6. Контракты доменных функций

Параметр настроек везде `st: Settings` (`tz`, шаг, лимиты — только из него). Сигнатуры — по каталогу base 8.1; ниже — критичные контракты. Агент может дробить функции мельче, но эти контракты обязаны сохраняться.

### 6.1 Время

- `round_moment(t, st) -> datetime` — до ближайшего кратного шагу от локальной полуночи; ровно половина — вверх; результат UTC-aware на сетке (base 4.5). Локальные сутки = 1440 мин, DST игнорируется.
- `calc_now(now, st) -> datetime` — `now_calc` тем же правилом.
- `calc_horizon(period, now_calc, st) -> datetime` — `H = min(now_calc, полночь дня после period.end)`. Горизонт флагов: `H_raw = min(now, та же полночь)`.
- `local_minute(t, day, st) -> int` (0..1440); `today_of(now, st) -> date` — локальная дата **исходного** `now`.

### 6.2 Табель и настройки

- `value_of(day, st) -> str` — `<код>` без часов; `<код> <часы>` с часами: ровно один пробел, дробь через запятую, ≤ 2 знаков, без хвостовых нулей (720→«12», 645→«10,75»).
- `plan_of_day(day, st) -> Minutes` — **длина окна** значения, 0 если окна нет (R34, v7.1; RUL-PLAN-FROM-WINDOW). `Day.plan_minutes` — информационный план строки: ключ значения (`value_of`), CHK-PLAN-*, отображение вкладки «Табель».
- `window_of_day(day, st) -> Window | None` — `st.windows.get(value_of(day, st))`; `None` = окна нет (base 3.3, CFG-WINDOWS): рабочее 0, весь факт — переработка, недостача 0.
- `resolve_modifier(name, day, st)` — приоритет 1–7 (сотрудник+день … период, глобальный дефолт), подневно, группа — из строки дня (RUL-GROUP-PER-DAY); «Учитываются ли часы в УТ» на уровне 7 — колонка CFG-DAY-CODES.
- `resolve_plan_equals_fact(day, st)` — «Авто» разрешается **только** колонкой CFG-DAY-CODES (единственный источник — R19; стартово «Да» у «К»), и только для значений с часами.

### 6.3 Присутствие — два представления

**Нормативный порядок (base 4.5, 9.1): сначала округление моментов, затем сопряжение.** Пересортировка по округлённому времени запрещена; при совпадении моментов порядок задаётся исходным (EX-47).

- `to_calc_mark(mark, st) -> CalcMark`.
- `pair_marks(marks, opening_mark, closing_mark=None, horizon=None) -> tuple[Session, ...]` — чистое ядро (без `st`): «пришёл» открывает, «ушёл» закрывает, в исходном порядке. **Проверка входа (R31):** `check_punch_sequence(marks, opening_mark)` — линейная проверка чередования, нарушение → `InvalidInputDataError("CHK-PUNCH-SEQUENCE", data)` (base 5.3 уровень 2; выполняется в ядре, не на стадии 1). Чинить последовательность запрещено (антипаттерн base 12.22). **Граничные отметки (base 4.3, R32):** `opening_mark = None` → первая сессия с первой отметки выборки; `opening_mark = "in"` → начинает первую сессию (`started_before_range = True` в истории); `opening_mark = "out"` → игнорируется; незакрытый «пришёл» — открытая сессия (`end=None`), обрезается по `horizon` (если задан) либо закрывается `closing_mark` типа «ушёл» (`closed_after_range = True`, история — base 16.4); `closing_mark = "in"` → игнорируется, сессия остаётся открытой; пустая выборка допустима. Постусловия: `end ≥ start`; порядок сессий = порядок отметок; сессия никогда не заканчивается моментом «пришёл».
- `split_by_day(sessions, period, st)` — нарезка локальными полуночами; нулевые куски отбрасываются (EX-48, EX-50); «ушёл ровно в 00:00» — кусок нового дня нулевой (следствие нарезки, не отдельное правило).
- `presence_intervals(period, calc_marks, opening_mark, now_calc, st)` — расчётный путь: сопряжение → обрезка по `H` → нарезка → `Interval` (на сетке).
- `raw_presence_intervals(period, marks, opening_mark, now, st)` — исходный путь (флаги): те же шаги по **исходным** отметкам, обрезка по `H_raw` → `RawInterval` **с секундами**; усечение/округление до минут запрещено (EX-49). Открытый интервал текущего дня заканчивается в `now`.
- `has_presence_event(day, raw_marks, st) -> bool` — **только исходные отметки** (не сессии!): в дне есть отметка с моментом в полуинтервале `[00:00, 24:00)`. Сессия, схлопнувшаяся округлением в ноль, всё равно даёт событие (EX-48).

### 6.4 Карточка дня

- `fact_of_day(intervals) -> Minutes`; `cut_working_time(intervals, window) -> Minutes` (пересечение с окном; `window=None` → 0); `overtime_parts(intervals, window)` — части факта **вне окна** (план не участвует — «сверхплановых» минут в модели нет); `category_of` / `category_cuts` / `split_by_category` (категория с `end ≤ start` пересекает полночь); `classify_overtime(parts, st)`; `weight_of_day(day, st)` (1 или 2 по `double_overtime`); `codes_of_day(day, parts, st) -> Mapping[str, Minutes]` — коды `<категория>[<вес>]` слитно (`ДЯ`, `ДН`, `ДЯ2`, `ДН2`); **длительности не округляются**.
- `apply_plan_equals_fact(day, fact, plan, has_event, st) -> (plan_minutes, applied)` — план := 0 только при `carries_hours` ∧ модификатор «Да» ∧ ¬событие ∧ `fact = 0`; синтетические отметки/факт/рабочее время не создаются (R12, R16).
- `debt_of_day(day, work, applied, st) -> Minutes` — **v7 (R15/R16):** `applied` ⇒ 0; окна нет ⇒ 0; иначе `max(0, длина окна − work)`.
- Признаки дня (base 5.2): `counts_in_ut`, `pays_overtime = counts_in_ut ∧ «Оплачиваются ли переработки»`, `accepts_ut`, `receiver_ok = accepts_ut ∧ pays_overtime`.
- `build_day_card(day, intervals, day_raw_marks, st) -> DayCard` — композиция: window → fact → has_event → plan/applied → work → parts → debt → codes → DayCard. `timesheet_value` — по **информационному** плану строки (ключ CFG-WINDOWS); `plan_minutes` карточки — от окна (R34).

### 6.5 Коды, размещение, переносы

- `Codes` (единственное мутабельное исключение, 2.5): блоки `{source_day, tariff, placed_day | None, minutes}`; `take` — только для конкретного блока, только при положительном изъятии.
- `seed_codes(cards, st)` — собственные коды дней; день с `pays_overtime ∧ accepts_ut` → `placed_day = source_day` (занимают ёмкость раньше переносов); иначе `placed_day = None`.
- `accept_deferred(deferred_in, codes)` — входящие блоки с `placed_day = None`; в банк повторно не зачисляются (RUL-DEFERRED-IN-ACCEPTED). Вход предварительно канонически отсортирован (R4).
- `created_totals(codes)` — контрольная сумма для INV-MINUTES-CONSERVED.
- `credit_unpaid(cards, codes, st)` — дни с `pays_overtime = Нет`: снять **собственные** коды, зачислить в банк **по весу**; записи `UNPAID_CREDITED` (внутри дня — порядок тарифов CFG-PLACEMENT, R3); входящие блоки не трогает.
- Первичное размещение (стадия 8): `pending_blocks` → `merge_same_blocks` (одинаковые `source_day`+`tariff`) → `placement_order` (`source_day`↑, затем CFG-PLACEMENT) → для каждого блока: `candidate_days` (строго после `source_day`, по возрастанию) → пропуск дней с `receiver_ok = Нет` (RUL-SKIP-NON-RECEIVER) → `free_capacity(card, codes, st) = day_limit − длина окна значения − Σ размещённых кодов` (R13; окно из `st.windows[card.timesheet_value]`, нет строки → 0) → разместить `min(free, remaining)` (`CODE_PLACED`), остаток — следующий кандидат; неразмещённый остаток остаётся с `placed_day = None`.
- `relocate_pending(cards, codes, st)` (стадия 12, только `close`) — тот же алгоритм для оставшихся неразмещённых, в ёмкость, освобождённую каскадом; уже размещённые не перемещаются; **второго каскада нет**; `CODE_PLACED` с `pass = "after_cascade"`.
- `collect_deferred(codes)` — окончательные (в `view` — предварительные) неразмещённые остатки + `NO_RECEIVER` в exceptions.

### 6.6 Нормализация, банк, каскад

- `normalize_opening_bank(value, old_step, new_step)` / `normalize_deferred(blocks, old_step, new_step)` — при смене шага: ближайшее кратное, ровно половина — вверх по абсолютной величине, знак сохраняется (кроме округления до нуля); банк — как один остаток, блоки — **каждый отдельно**; блок → 0 исключается, запись остаётся. Возвращают значения **и записи `OPENING_ROUNDED`** (R8). При равных шагах не выполняется.
- `available_bank(opening, adjustments, credited)` и `total_debt(cards, available_bank)` — формулы base 4.8 (`opening` — нормализованный входящий остаток, стадия 2): `A = opening + adjustments + credited`; `T = Σ debt + max(0, −A)`; отрицательная часть банка входит в долг **ровно один раз**.
- `pay_debt_with_bank(debt, positive_bank) -> (used, need, bank_left)` — **только банк** (стадия 10): `used = min(debt, max(0, A))`, 1:1; `BANK_APPLIED` при `used > 0`. Никакого каскада внутри.
- Каскад (стадия 11, только `close`): `sacrifice_order(codes, st)` — тарифы по CFG-CASCADE, внутри тарифа по `source_day`, затем по `placed_day` (неразмещённые последними); размещённые и неразмещённые участвуют на равных. Формула изъятия (CFG-GRANULE, **неделимая гранула**):

```
число гранул = min(available // q, rest // (q * weight))   # q = step_minutes
снято        = число гранул * q
погашено     = снято * weight
```

  Гранула дороже остатка → изъятие 0, код сохраняется, долг переносится минусом банка (EX-21). Изъятие никогда не перекрывает остаток долга. На каждый блок — `Cut` + `CODE_CUT`.
- `close_bank(bank_left, residual)` — `bank_left − residual`; `RESIDUAL_CARRIED` при `residual > 0`. **Банк может быть отрицательным** — это штатный перенос долга (RUL-CLOSING-BANK).
- **Две валюты (base 4.1):** недостача начисляется 1:1; погашение кодом и зачисление в банк — по весу кода; погашение банком — 1:1.

### 6.7 `settle()`

```python
def settle(period, days, marks, opening_mark, bank_open, adjustments, deferred_in,
           st, now, mode: Literal["view", "close"], previous_step_minutes) -> SettleResult
```

Стадии (base 6.3 — нормативно): 1 валидация входа (уровень 2, §9) → 2 нормализация входящих остатков (`OPENING_ROUNDED` возвращаются явно) → 3 округление отметок и `now` → 4 сессии и расчётные интервалы (сопряжение в исходном порядке, обрезка по `H`, нарезка) → 5 карточки дней → 6 аккумулятор кодов (`seed_codes`, `accept_deferred`, `created_totals`) → 7 `credit_unpaid` → 8 первичное размещение → 9 `available_bank`, `total_debt` → **только `close`:** 10 погашение банком → 11 каскад → 12 повторное размещение → 13 переносы и банк (в `view`: предварительные `deferred_blocks`, `bank_closed = A`) → 14 результат (`mgmt_timesheet`, `exceptions`, `trace`, итоговые инварианты).

**Стадии 6–9 и 13 выполняются и в `view`** (размещение и зачисление в банк — не close-only). Режим `view` (INV-VIEW-MODE): `paid_with_bank = 0`, `cuts` пуст, `residual_debt = total_debt`, `bank_closed = A`, `deferred_blocks` предварительные, результат не сохраняется. Изъятия — только в `close` (RUL-VIEW-NO-CUT).

`PLAN_EQUALS_FACT` (стадия 5) не возвращается функцией стадии — восстанавливает `build_trace` из полей карточек и `resolve_plan_equals_fact` (R8). Реестр кодов `Reason` — base 6.2 (исчерпывающий состав `data`).

### 6.8 `evaluate_flags()`

```python
def evaluate_flags(period, days, plan_equals_fact: Mapping[date, bool],
                   marks, opening_mark, shifts, absences, st, now) -> FlagsResult
```

**Вход из часового конвейера — только `plan_equals_fact`** (`{day: card.plan_equals_fact_applied}`); ключ обязан быть на каждый день периода (INV-CARDS-COVER-PERIOD, иначе `InvariantViolationError`). Карточки/банк/коды/долг флаги не получают и не читают. Работает на **исходных** отметках и **исходном** `now`, без округления.

Стадии (base 6.6): 1 `raw_presence_intervals` (обрезка по `H_raw`) → 2 `shift_segments` (дневные отрезки, INV-SEGMENT-WITHIN-DAY; вне периода отбрасываются; **смежные и пересекающиеся отрезки в пределах дня сливаются** — R17) → 3 `merge_absences` (на UTC-оси) → 4 `expected_subintervals` (отрезки дня минус `absence ∩ отрезок`; не осталось — сотрудник не ожидается) → 5 флаги дня отдельными функциями → 6 сборка.

Реестр флагов (порядок = канон сортировки, §4.4): `LATE`, `EARLY_DEPARTURE`, `OFF_SHIFT_ATTENDANCE`. **`ABSENCE_GAP` и `MISSED_DAY` удалены (R18, R21): след «ожидался — не пришёл» — `LATE` с `actual_at = None`.** Формулы условий и исчерпывающий состав `data` — base 6.6 (реестр); ключевые гейты:

- `LATE` — по каждому ожидаемому подинтервалу S: `now ≥ S.start + late_limit` ∧ ¬`present_at(S.start)` ∧ (`actual_at = None` ∨ `actual_at > S.start + late_limit`); `actual_at` — по **исходным** интервалам. **`LATE(None)` (v7, R21):** ставится с `S.start + лимит` и живёт до конца дня, а в снимке закрытого периода остаётся следом «ожидался — не пришёл».
- `EARLY_DEPARTURE` — `now ≥ S.end` ∧ присутствие в S есть ∧ `last_end(S) < S.end − late_limit`; при отсутствии присутствия в S не ставится (случай покрывает `LATE(None)`); уход ровно в `S.end` — флаг не ставится (`last_end = S.end`).
- `OFF_SHIFT_ATTENDANCE` — подинтервалов нет ∧ в дне есть исходное присутствие; смена Графика, накрывающая день с кодом-отсутствием, флаг снимает.
- Подавление: `plan_equals_fact[day] = True` ⇒ `LATE(None)` не ставится (единственное подавление, v7). **Присутствие в дне вне всех подинтервалов не отменяет `LATE(None)`** и не порождает `OFF_SHIFT_ATTENDANCE` (R11/R21). `first_presence_at` для сессии через полночь — синтетическая граница 00:00; синтетические границы флагов, привязанных к отметкам, не порождают.
- Согласованное отсутствие отдельного флага не имеет (R18): оперативную информацию несут доска (`expected_at` следующего подинтервала) и история сессий.

Флаги не меняют ни одного числа `SettleResult`; тексты собирает `interface`.

### 6.9 Доска и история (base 16.2, 16.4)

- `open_sessions(last_marks, now)` — у кого последняя отметка `in`; `expected_now(shifts, absences, now, st)` — `now` внутри ожидаемого подинтервала в смысле `[start, end)` (в момент `S.start` уже ожидается — v7); `expected_arrivals(shifts, absences, present_ids, now, st)` — подинтервалы сегодня, где сотрудника нет сейчас: начало позже `now` (`already_started = False`) либо уже началось, а человека нет (`True`); **завершившиеся подинтервалы (`S.end ≤ now`) не входят** (R20 — непроход на завершившуюся смену фиксирует `LATE(None)` во флагах); `assemble_board(...)` — композиция. Забытый уход показывается как есть (`minutes_open` растёт), доска ничего не «закрывает».
- `view_sessions(employee_id, from_utc, to_utc)` (application) — три запроса: `marks_between([from, to))`, `last_mark_before(from)` (строго <), `first_mark_after(to)` (первая ≥ to — R7); `pair_marks(marks, opening_mark, closing_mark)` **без горизонта**; `SessionView.started_before_range` — `opening_mark.kind == "in"`; `closed_after_range` — хвостовой «пришёл» закрыт `closing_mark` типа «ушёл»; `session.end = None` — только если закрывающего «ушёл» нет вовсе. Моменты исходные, без округления и нарезки; визуализация — фронтенд.

## 7. Application-слой

```python
def view_period(employee_id: str, period: Period, now: datetime) -> PeriodView: ...
def close_period(employee_id: str, period: Period, now: datetime) -> PeriodView: ...
def recalculate(employee_id: str, period: Period, now: datetime) -> PeriodView: ...
```

`now` передаёт `interface` (адаптер часов); use case'ы системное время не читают (R10). Для **разрешённого** `close` результат не зависит от конкретного `now` (`H`/`H_raw` схлопываются в полночь после `period.end`); `now` определяет право закрытия и целиком определяет картину `view`.

- **`view_period`:** период закрыт → прочитать сохранённые `SettleResult` + снимок `FlagsResult`, **без пересчёта** (RUL-CLOSED-PERIOD-IMMUTABLE). Не закрыт → **отклонить, если `previous_closed = False` и `opening_bank_set = False`** (RUL-VIEW-AFTER-PREVIOUS, R22/R26 — типизированная ошибка application, домен не вызывается) → сузить период до эффективного (∩ трудоустройство, R23) → `load_inputs` (формула §5; Табель — полным периодом, R27) → `settle(mode="view")` → извлечь `{day: plan_equals_fact_applied}` из `cards` → `evaluate_flags` → `PeriodView`. Ничего не сохраняет.
- **Эффективный период (R23/R27):** все use case'ы тяжелого конвейера работают с `effective = period ∩ [Employment.start, Employment.end]` (`end` — последний рабочий день включительно; `None` — работает); `Employment` читает `EmploymentPort`; домен о трудоустройстве не знает; дни вне трудоустройства в UI — «не в штате». Эффективный период передаётся в `settle()`/`evaluate_flags()` и задаёт границы выборки отметок; `TimesheetPort.days` вызывается **полным** запрошенным периодом, чтобы строки вне трудоустройства дошли до домена и были отброшены (`CHK-DAYS-IN-PERIOD`, EX-55 к.1). `PeriodView` несёт `employment` (v7.1) и `days` — строки Табеля для информационного плана в карточке УТ (R39); по `employment` `interface` показывает дни вне трудоустройства «не в штате» (base 16.6). Эффектив = ∅ (период целиком вне трудоустройства) — типизированный отказ `application` **до** всех прочих проверок, домен не вызывается; UI такие периоды не предлагает и сотрудника в отчёте не показывает (R35).
- **`close_period`:** проверки до домена (отказ — типизированное исключение application): период ещё не закрыт; `previous_closed` либо `opening_bank_set` (RUL-SEQUENTIAL-CLOSING, R26); право по `now` (CHK-CLOSE-ALLOWED). Затем `settle(mode="close")` + `evaluate_flags(now)` → в одной транзакции `UnitOfWork` атомарно сохранить: результат, снимок флагов, закрывающий банк (`BankWritePort`), исходящие `deferred_blocks` во вход следующего периода (`CarryOverPort.save_deferred`), входной снимок `ClosingInputs`, версии настроек, состояние периода. Любое исключение домена → ничего не сохраняется. Повторное и конкурентное закрытие невозможно.
- **`recalculate`:** только **последний закрытый** период; запрещён, если следующий уже закрыт (`PeriodState.next_closed`). Старт — с **исходных** `ClosingInputs` (не с результата прошлого прогона); отметки, Табель и корректировки **перечитываются из портов свежими** — пересчёт существует, чтобы отражать исправления после закрытия (R28, EX-53, base 16.5); настройки — действовавшие для периода с учётом ретроспективных исправлений; флаги пересчитываются на `now` пересчёта. Сохранение **заменяет** (не дополняет) результат, банк, переносы и снимок флагов; исчезнувшие переносы удаляются из входа следующего периода. Собственной логики нет — тот же `settle()`.
- Обёртки `month_period(year, month)` / `half_month_period(year, month, half)` (гранулярность — `Settings.period_granularity`, R36: 1–15 / 16–конец месяца), `close_month`, `recalculate_month` (пробрасывают `now`); цепочка «предыдущий/следующий» — соседние периоды гранулярности, граница цепочки — периоды, содержащие `Employment.start`/`Employment.end` (R35/R36); `day_views(view)` — склейка карточка+флаги+информационный план (R39).

**Режимы — truth table (base 7.2, R33; нормативен base, таблица здесь — карта оркестрации).** Режимов **четыре**: чтение закрытого периода — отдельный режим без вызова домена.

## 9. Валидация — три уровня (не смешивать!)

**Уровень 1 — конфигурация** (`validate_settings(st)`, при загрузке; вход — только `Settings`; все нарушения сообщаются разом → `ConfigError`): CHK-WINDOW-PLAN, CHK-WINDOW-BOUNDS, CHK-WINDOW-KEY, CHK-CATEGORIES-COVER, CHK-CODES-EXIST, CHK-CASCADE-FULL, CHK-WEIGHTS-POSITIVE, CHK-STEP-DIVIDES-60, CHK-GRID, CHK-PLACEMENT-FULL, CHK-DEFAULTS, CHK-MODIFIER-SCOPE, CHK-MODIFIER-TYPE, CHK-MODIFIER-CONFLICT (base 5.3).

**Уровень 2 — входные данные** (стадия 1 `settle()`; нарушения одного типа сообщаются разом; расчёт не запускается): CHK-PERIOD-BOUNDS (`start ≤ end`, v7.1), CHK-DAY-CODE-KNOWN (`UnknownDayCodeError`), CHK-TIMESHEET-COVERS (`IncompleteTimesheetError`), CHK-DAYS-IN-PERIOD, CHK-WINDOW-EXISTS (`UnknownTimesheetValueError`), CHK-PLAN-CONSISTENT, CHK-PLAN-FORMAT (кратность 15), CHK-SINGLE-EMPLOYEE, CHK-GROUP-EXISTS, CHK-DEFERRED-IN (`minutes > 0`, кратны `previous_step_minutes`, `source_day < period.start`), CHK-OPENING (`previous_step_minutes > 0` и делит 60; `Adjustment.period` равен периоду — **ошибка, не фильтр**, R9), CHK-NOW-IN-PERIOD, CHK-CLOSE-ALLOWED (`IncompletePeriodError`) — остальные `InvalidInputDataError(code, data)`. **CHK-PUNCH-SEQUENCE (R31)** — тоже уровень 2, но выполняется **не на стадии 1**, а ядром `pair_marks` (`settle`: стадия 4; `evaluate_flags`: стадия 1; `view_sessions`): отметки не входят во вход стадии 1.

**Уровень 3 — данные Графика** (адаптер при чтении, до домена): CHK-SHIFT-ORDER, CHK-ABSENCE-ORDER, CHK-ABSENCE-LENGTH → `ConfigError`.

Проверки, требующие строк Табеля, внутри `validate_settings` запрещены (антипаттерн 12.21).

## 10. Инварианты

Нарушение — `InvariantViolationError(code, data)`: ошибка реализации, расчёт прерывается, результат не сохраняется, в `exceptions` не попадает. Полный список и формулы — base 10; моменты проверки — base 10.1 (после соответствующих стадий + итоговая проверка на стадии 14). Критичные уточнения v7:

- **Банк может быть отрицательным** (перенос долга, RUL-CLOSING-BANK). «Отрицательные минуты» запрещены только для факта/рабочего/переработки/кодов/изъятий.
- **INV-GRID (v7, v7.1):** границы интервалов, полный факт, рабочее время, переработка, коды УТ, **недостача и план карточки** (= окно, R34) кратны шагу; информационный план Табеля и банк кратности не требуют.
- **INV-DAY-LIMIT (v7.1):** план карточки = длина окна (R34) ⇒ «план + Σ кодов ≤ лимита» равносилен формуле ёмкости и выполняется точно.
- **INV-PLAN-EQUALS-FACT-ZERO (v7):** `applied ⇒ plan = fact = work = overtime = debt = 0`, собственных кодов нет.
- INV-CLOSE-BALANCE: `T = P + C + R`; INV-BANK-CLOSED: `bank_closed = max(0, A) − P − R`; INV-VIEW-MODE: `P = 0`, `cuts` пуст, `R = T`, `bank_closed = A`.
- INV-MINUTES-CONSERVED: нормализованные входящие + созданные = размещённые в УТ + исходящие неразмещённые + снятые неоплачиваемые (физические) + изъятые каскадом.
- INV-DETERMINISM — свойство тестов, не пост-проверка.

## 11. Ошибки и реестры кодов

Типизированные исключения (base 2.8): `ConfigError`, `UnknownDayCodeError`, `UnknownTimesheetValueError(value)`, `InvalidInputDataError(code, data)`, `IncompleteTimesheetError`, `IncompletePeriodError`, `InvariantViolationError(code, data)`. Никаких `-1`, `None`-как-ошибка, проглатывания исключений; бизнес-ситуации (нет приёмника) — структурированные записи, не ошибки.

Реестры (строки попадают в результаты и тесты — побуквенно):

- `Reason.code` (base 6.2): `OPENING_ROUNDED`, `PLAN_EQUALS_FACT`, `UNPAID_CREDITED`, `CODE_PLACED`, `NO_RECEIVER` (единственный код в `exceptions`), `BANK_APPLIED`, `CODE_CUT`, `RESIDUAL_CARRIED`. Перечисления: `OPENING_ROUNDED.kind ∈ {"bank","deferred_block"}`; `PLAN_EQUALS_FACT.policy ∈ {"yes","auto_code"}` (**`auto_group` удалён — R19**); `CODE_PLACED.pass ∈ {"primary","after_cascade"}`.
- `Flag.code` (v7): `LATE`, `EARLY_DEPARTURE`, `OFF_SHIFT_ATTENDANCE` (пишется с двумя подчёркиваниями!). **`ABSENCE_GAP` и `MISSED_DAY` удалены (R18, R21): след «не пришёл» — `LATE` с `actual_at = None`.**
- Значения `Reason.step` — каноническое перечисление (base 6.2, v7.1): `opening`, `cards`, `credit_unpaid`, `placement`, `replacement`, `deferred`, `bank`, `cascade`, `closing`; у `CODE_PLACED`: `placement` (pass=primary) / `replacement` (pass=after_cascade).
- `INV-*`, `CHK-*` — коды ошибок совпадают с мнемоникой; имена файлов проверок — по каталогу base 8.1 (уровень 1 — `snake_case` имени проверки: `CHK-WINDOW-PLAN` → `window_plan.py`) (base 0.3, 5.3). `RUL-*` — только ссылки в коде/тестах, не runtime-коды.

## 15. Критерий готовности

- EX-01…EX-55 воспроизведены цифра в цифру; все инварианты проверяются в моментах base 10.1.
- Слои физически разделены; домен чист; время — параметром; поведение — из справочников.
- Валидация конфигурации сообщает все нарушения разом; повторный расчёт детерминирован.
- Конвейеры вкладок независимы (архитектурные тесты).
- Старый движок удалён, все точки вызова переключены.
- README: запуск расчёта; добавление кода/значения Табеля и окна (информационный план < окна; план карточки — от окна, R34); модификатора; группы; изменение CFG-PLACEMENT/CFG-CASCADE; закрытие и пересчёт; просмотр закрытого периода; передача отложенных блоков; **модель v7/v7.1: недостача, ёмкость и план карточки от окна** (base А.6, А.9).

## 16. Памятка исполнителю

Канонические цепочки:

```
часы:   marks → calc_marks (округление) → pair_marks(horizon=H) → split_by_day → Interval
        → DayCard (fact/work/overtime/debt от окна/codes) → Codes → credit_unpaid
        → размещение (ёмкость от окна) → [close: банк → каскад (гранулы) → повторное размещение]
        → deferred/NO_RECEIVER → mgmt_timesheet → SettleResult (+ trace, exceptions)

флаги:  raw marks → pair_marks(horizon=H_raw) → split_by_day → RawInterval (секунды)
        + shift_segments (слияние смежных) − absences (UTC, через полночь) → expected_subintervals
        → LATE / EARLY_DEPARTURE / OFF_SHIFT_ATTENDANCE → FlagsResult

доска:  last_marks + shifts_on_day + absences_on_day → assemble_board → PresenceBoard
история: marks_between + last_mark_before + first_mark_after → pair_marks(closing_mark) → SessionView
```

- Окно — единственная операционная норма: и для недостачи, и для ёмкости, и для **плана карточки** (R34, v7.1). План строки Табеля — информационный/зарплатный атрибут (ключ значения).
- Табель — часы, График — флаги и доска (RUL-SCHEDULE-ONLY-FLAGS); расхождение Табеля и Графика не ошибка (RUL-TIMESHEET-WINS).
- Долг — часть периода (RUL-DEBT-IS-PERIOD-WIDE): банк → коды по CFG-CASCADE; перенос кодов — только вперёд.
- «План=Факт» — **один** предикат из четырёх условий (base CFG-MODIFIERS, R30); окно, план строки, График и отсутствия в нём не участвуют; других ограничителей нет.
- Отметки: адаптер гарантирует чередование, ядро `pair_marks` **проверяет** его (`CHK-PUNCH-SEQUENCE`) и никогда не чинит (R31); `opening_mark = "ушёл"` и `closing_mark = "пришёл"` игнорируются (R32).
- Режимов четыре: `view` незакрытого / чтение закрытого (без домена) / `close` / `recalculate` — карта в §7 и base 7.2 (R33).
- Период UI — месяц или половина месяца по настройке `period_granularity` (R36); цепочка периодов сотрудника — от приёма до увольнения, периоды вне трудоустройства не учитываются (R35).
- Начальный банк первого периода — ручная корректировка `OPENING_SEED` (R37); посев только в первый период — закрытие в обход предшественника невозможно.
- Доска — только трудоустроенные сегодня (R38); «кто ещё должен прийти» — ближайший подинтервал (R40); в карточке УТ два плана: расчётный (= окно) и информационный (R34/R39).
- Любая неоднозначность — остановиться и спросить владельца (base 0.1 п.6); прежние открытые вопросы O1–O5 закрыты (часть VII патча). Приоритет документов — §0.
