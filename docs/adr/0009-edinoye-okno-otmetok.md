# ADR-0009. Единое окно отметок: вся история (доска = личный экран = кнопка)

**Статус:** принят 15.10.2026 (решение владельца)

## Контекст
Исторически личный экран «Мои отметки» искал открытую сессию только в окне
«начало смены по плану − 4 ч» (`WINDOW_BEFORE_H`), а доска «кто на работе» —
по всей истории. Окно вводилось как защита от «забытого ухода»: чтобы старая
незакрытая сессия не заставляла сотрудника первым тапом закрывать её задним
числом. На практике окно не защищало расчёт (второй «пришёл» отбрасывает
sanitize адаптера, и сессии склеиваются в любом случае — лечится только
правкой отметок менеджером), но создавало расхождения экранов: при легально
длинной смене личный экран предлагал «Пришёл» поверх открытой сессии.

## Решение владельца
Смены длительностью сутки и более (вплоть до ~3 суток) — **норма** для этого
объекта, а не аномалия. Следовательно: окно поиска открытой сессии — вся
история, одинаково для доски, личного экрана и кнопки/«авто»:
открытая сессия = последняя по (ts, id) отметка является «пришёл».

## Последствия
- Кнопка/«авто» при открытой сессии (любой давности) = «Ушёл»: длинная смена
  закрывается честно, в момент фактического ухода.
- Забытый уход неразличим от длинной смены — это осознанно: сотрудник закрывает
  сессию фактическим «Ушёл», менеджер при необходимости правит ts отметки
  (punches.manage, аудит фиксирует правку). Расчёт (Табель/УТ) до правки
  показывает длинную сессию как есть — аномалия видна в УТ, а не спрятана.
- Явный «Пришёл» при открытой сессии отклоняется (409 «Вы уже на смене с …»)
  независимо от давности — дубли IN больше не протекают в данные.
- `is_late` корректен для многосуточных смен: открытая сессия = не опоздал.
- Окно ±4 ч удалено из кода (`WINDOW_BEFORE_H`); «часы сегодня» на личном
  экране по-прежнему справочные в границах календарных суток (подписано в UI),
  источник истины по часам — Управленческий табель (16.1 п.2).
