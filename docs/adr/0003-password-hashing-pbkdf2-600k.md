# ADR-0003. Хеширование паролей: PBKDF2-HMAC-SHA256, 600 000 итераций, ленивый rehash

**Статус:** принят 15.10.2026 (заменяет параметры от 27.09.2026: 120 000)

## Контекст
OWASP Password Storage (2023): минимум 600 000 итераций для PBKDF2-HMAC-SHA256.
Было 120 000. bcrypt упоминался в requirements.txt, но в коде не использовался;
argon2 требует внешней зависимости и тюнинга памяти.

## Решение
`_ITERATIONS = 600_000` (stdlib, без новых зависимостей). Формат хеша
`pbkdf2$<итерации>$<salt>$<digest>` уже хранит параметры → `needs_rehash()` +
прозрачный пересчёт при успешном входе (ленивая миграция, пароли не сбрасываются).

## Альтернативы
argon2id (лучшая стойкость к GPU/ASIC) — отложен: зависимость + риск несборки
на машинах заказчика без интернета; переход возможен без сброса паролей тем же
ленивым rehash'ем (формат расширяем).

## Последствия
Логин стал дороже (~0.3 c) — приемлемо и полезно как естественный троттлинг.
Сид демо-БД создаётся дольше (несколько секунд, однократно).
