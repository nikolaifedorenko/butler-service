# ADR-0002. Миграции схемы: Alembic (пересмотрено 21.10.2026)

**Статус:** принят 15.10.2026 («самодельные шаги, Alembic отложен»), **пересмотрен 21.10.2026**:
переход на Alembic выполнен (аудит `docs/audit/REPORT.md`, находки DB-01…DB-06).

## Контекст
`app/bootstrap/migrations.py` (~770 строк) выполнял raw-DDL при каждом старте. Без таблицы
версий применённое угадывалось по наличию колонок, а проверки на PostgreSQL не было. Итог
аудита: базы старше 18.10 не обновлялись (DB-01), на PostgreSQL старт падал
(`boolean = integer`, DB-02), тип колонки в существующих базах нельзя было поменять (DB-06),
а пустые и противоречивые шаги шли при каждом старте (DB-03).

## Решение
* Схема ведётся ревизиями Alembic: `app/bootstrap/alembic/versions/`. `0001_baseline` — схема
  `main 3801abf` вместе с индексами, которые базы получали шагами `migrate_night_*`.
* `init_db()` (под `startup_lock`, как и раньше):
  * пустая база — `upgrade head`, схема целиком из ревизий;
  * база под Alembic (есть `alembic_version`) — `upgrade head`;
  * база до перехода (таблицы есть, `alembic_version` нет) — прежние шаги `migrations.py` и
    `create_all`, затем `stamp 0001` и `upgrade head`.
* `migrations.py` заморожен: новых шагов туда не добавлять, только правки legacy-пути.
* Страж — `tests/test_db_upgrade.py`: `alembic check` (модели = ревизии), путь старой базы,
  обновление схемы до 18.10. Тесты идут на SQLite и PostgreSQL 16 (CI-джоб `postgres`).

## Последствия
* Изменение схемы = правка модели + `alembic revision --autogenerate -m "…"` (адрес БД из
  `DATABASE_URL` / `.env`), ревизию проверить глазами. Без ревизии падает
  `test_models_match_migrations`.
* Legacy-путь верен, пока ревизии после `0001` не создают таблиц и колонок: `create_all`
  текущих моделей выполнится раньше штампа. С первой такой ревизией legacy-ветку в
  `app/main.py` удалить: к тому времени все стенды уже будут со штампом.
* Отдельного шага `migrate` в деплое пока нет: миграции применяет первый воркер под замком.
  Вынести в сервис compose — когда понадобится долгий DDL на больших таблицах.
