# ADR-0012. Манифест модуля

**Статус:** принят 22.10.2026 (фаза 5 аудита, шаг 5.3; находка ARCH-02). Развивает ADR-0010
(модульный монолит): модули остаются те же, меняется способ их подключения.

## Контекст
Чтобы добавить модуль, приходилось вручную править 16 мест (аудит,
`docs/audit/TARGET-ARCHITECTURE.md` §1.1):
* импорт роутеров и `include_router` в `main.py`;
* импорт моделей в `bootstrap/registry.py` — иначе таблица молча не создаётся;
* каталог прав и наборы ролей в `core/permissions.py`;
* заголовки журнала в `audit_api.py`;
* разделы уведомлений в `notify/domain/templates.py`;
* кортеж модулей в тесте архитектуры;
* фронтенд и генерируемые файлы.

Списки расходились: модели забывали регистрировать, у прав не было владельца.

## Решение
* Каждый пакет `app/modules/<имя>/` содержит `manifest.py` с `MODULE = ModuleManifest(...)`
  (`app/core/manifest.py`):
  * `name`, `title`, `order` — порядок подключения и строк каталога прав;
  * `routers` — строки «`пакет.модуль:атрибут`»;
  * `models` — модули с ORM-моделями;
  * `permissions` — `Perm(key, section, title, roles)`, где `roles` — встроенные роли,
    получающие право по умолчанию: `EVERYONE`, `SUPERVISOR_UP`, `MANAGER_UP`, `ADMIN_ONLY`;
    администратор получает все права всегда;
  * `audit_actions` — названия действий журнала аудита;
  * `notify_domains` — `NotifyDomain(title, template, placeholders)`;
  * `menu` — `MenuItem(id, title, order, perms)` и `settings_screens` — `Screen(id, title,
    order, group, perm, external)`: фронтенд-часть, шаг 5.4 (дополнение к ADR-0008).
* Ядро описывает себя тем же типом (`core.manifest.CORE`): роутер медиа, модели ядра, право
  `media.delete_any`.
* `bootstrap/modules.discover()` находит манифесты через `pkgutil.iter_modules(app.modules)`.
  Пакет без `manifest.py` — ошибка старта.
* `bootstrap/registry.wire()` регистрирует манифесты в ядре и заполняет каталог прав
  (`permissions.load_catalog`). `ensure_models()` импортирует модели из манифестов,
  `main.py` подключает роутеры из манифестов.
* Ядро модули не импортирует (R5): журнал аудита и `notify` читают зарегистрированные описания
  (`core.manifest.audit_titles()` и `notify_domains()`). Константы `DOMAIN_TITLES`,
  `DEFAULT_TEMPLATES` и `PLACEHOLDERS` модуля `notify` — «живые» словари прикладного слоя.

## Последствия
* Новый модуль — это новые файлы в `app/modules/<имя>/`, включая `manifest.py`, и
  `static/js/modules/<имя>.js`; в `main.py`, `registry.py`, `core/permissions.py`,
  `audit_api.py`, `notify`, тесте архитектуры, `.importlinter`, `index.html`, `app.js` и
  `settings.js` ничего не меняется (генерируемые файлы обновляют `tools/*`).
* Проверено при переходе:
  * маршруты, OpenAPI (как словарь), каталог прав, права ролей по умолчанию, заголовки аудита
    и разделы уведомлений совпали со снимком до перестройки;
  * маршруты теперь подключаются группами по модулям — пересечений путей, для которых важен
    порядок, нет (проверено скриптом);
  * в каталоге прав «Мои отметки» стоят рядом с остальными отметками.
* Стражи (`tests/test_modules_architecture.py`):
  * список модулей берётся из манифестов, у каждого пакета есть манифест;
  * одно право не объявлено двумя модулями;
  * каталог прав совпадает с манифестами.
* Не сделано: свои каталоги ревизий Alembic у модулей (`version_locations`), сид модуля,
  выключение модуля через окружение — понадобятся с первым модулем, которому это нужно.
  Пока таблицы нового модуля создаёт ревизия в общем каталоге `app/bootstrap/alembic/versions/`.
* Механизм проверен пробным модулем (`tests/test_module_probe.py`, вместо пилота «Гости» по
  решению владельца). Модуль из временной папки подключается в отдельном процессе и из одного
  `manifest.py` получает маршрут под своим правом, модель, право с ролями по умолчанию,
  название действия аудита, раздел уведомлений, пункт меню и экран Настроек — только у тех,
  кому положено.
