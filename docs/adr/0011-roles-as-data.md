# ADR-0011. Роли и права как данные

**Статус:** принят 22.10.2026 (фаза 5 аудита, шаг 5.5; решение владельца: свои роли нужны).

## Контекст
Ролей было четыре, и они были зашиты в код:
* константы `core/roles.py`;
* названия `ROLE_TITLES` на сервере и во фронтенде;
* иерархия `can_manage_user` — ветвления по ролям;
* список ролей в форме сотрудника — ветвление по роли во фронтенде.

Права ролей уже настраивались в «Правах доступа» (гранты `access_grants(role=…)`), но новую роль
(«Ночной супервайзер», «Бухгалтерия») без программиста завести было нельзя.

## Решение
* Таблица `roles(code, title, rank, max_assignable_rank, builtin)`, ревизия `0007`:
  * `rank` — уровень роли;
  * `max_assignable_rank` — до какого уровня её обладатель управляет учётками и назначает роли
    (`-1` — никого).

  Встроенные роли заводит ревизия: администратор 100/100, менеджер 80/80, супервайзер 60/10,
  сотрудник 10/−1.
* `can_manage_user(db, principal, target, new_role)` разрешает действие, если уровень роли цели
  и назначаемой роли не выше `max_assignable_rank` действующего. На встроенных ролях решения
  совпадают с прежними правилами; это проверено перебором всех сочетаний
  (`tests/test_roles_as_data.py`).
* Права роли — по-прежнему гранты `AccessGrant(role=code)` поверх прав по умолчанию из
  манифестов (ADR-0012). У своей роли умолчаний нет: права выдаются в «Правах доступа».
  Отдельная таблица `role_permissions` не понадобилась, и настройки заказчика переносить не нужно.
  Новые права из модулей сами доходят до встроенных ролей.
* API (право `access.manage`):
  * `POST /api/access/roles` — код вида `role_N` даётся автоматически;
  * `PUT /api/access/roles/{code}/settings`;
  * `DELETE /api/access/roles/{code}` — только своя роль и только без пользователей.

  Встроенные роли не меняются и не удаляются, меняются только их права. Уровень своей роли —
  от 1 до 99, назначать выше своего уровня она не может.
* `/api/auth/me` отдаёт названия ролей и роли, которые пользователь вправе назначать
  (`auth_guards.assignable_roles`). Фронтенд берёт названия (`roleTitle`) и список ролей в
  форме сотрудника оттуда.

## Последствия
* В «Права доступа → Роли» можно создать, настроить и удалить свою роль. Уровни подписаны
  словами: «как у сотрудника», «как у супервайзера», «как у менеджера». Проверено вживую в
  браузере.
* Особые случаи по коду роли остались только для администратора: он всегда сохраняет
  `access.manage`, и подробности selfcheck видит только он.
* Не сделано: наследование своей роли от встроенной («как супервайзер, но без X») — права
  своей роли задаются явно; ограничение прав своей роли тем, что есть у создателя, — создаёт
  роли только обладатель `access.manage`.
