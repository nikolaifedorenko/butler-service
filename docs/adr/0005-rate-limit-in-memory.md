# ADR-0005. Rate-limit входа: in-memory per-worker; Redis отложен

**Статус:** принят 15.10.2026

## Контекст
Лимит «10 неудач / IP / 5 минут» живёт в словаре процесса. При N воркерах
каждый считает свою копию (эффективный лимит ×N), при нескольких инстансах —
аналогично. За reverse-proxy без `TRUST_PROXY_HEADERS=1` все клиенты видны
как IP прокси (один бакет).

## Решение
Оставить in-memory: деплой-профиль — один хост, 2 воркера (×2 к лимиту —
приемлемо), nginx передаёт XFF + флаг доверия включён. Redis/БД-таблица —
когда появится несколько инстансов или требование точного глобального лимита;
интерфейс `_too_many_attempts/_record_login_failure` изолирован в
`auth_routes.py`, замена локальна.

## Последствия
Ограничение задокументировано в deploy/README.md. Точечные лимиты на другие
чувствительные операции (смена пароля, массовые экспорты) — в backlog;
сейчас их частично гасят права доступа и аудит.
