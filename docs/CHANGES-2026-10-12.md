# Изменения батча «Норматив справочника Табеля + горячие фиксы» — 12.10.2026

Две группы изменений: **нормативные правки справочника кодов Табеля** (решения
владельца от 12.10.2026) и **горячие фиксы интерфейса и API** — этап 0 плана
`docs/SETTINGS-UI-PROPOSAL-2026-10-12.md`. Перестройка раздела «Настройки»
(этапы 1–6) — отдельными PR.

---

## 1. Норматив: кодов «С» и «НВ» в Табеле больше нет

Из справочника кодов Табеля (CFG-DAY-CODES) исключены два кода — оба случая
оформляются данными Графика и банка, а не кодом первичного документа.

### Суточная смена — графиковая смена

Было: код «С» (Суточная смена, части дня) и три окна «С 16» 08:00–24:00,
«С 8» 00:00–08:00, «С 24» 00:00–24:00; смена через полночь дробилась на два значения
двух дней.

Стало: в Табеле **одна строка в дне начала смены** — обычная явка, окно которой
начинается вместе со сменой. По факту сотрудник работает 08:00–08:00 (или 20:00–20:00)
через полночь, и расчёт разделяет присутствие сам, режа его локальными полуночами:
рабочее время = факт ∩ окно своего дня, всё вне окна — переработка
(4.7, RUL-WORK-AND-OVERTIME, RUL-WINDOW-FROM-TIMESHEET).

Пример владельца (проверен расчётом и закреплён тестом `TestDailyShiftExample`):
01.10 в Табеле «Я 10,75» при стандартном окне 08:00–20:00, в Графике смена 08:00–08:00
следующих суток; сотрудник пришёл 01.10 08:00, ушёл 02.10 08:00. Присутствие делится на
01.10 08:00–24:00 и 02.10 00:00–08:00, из первого куска вырезается окно — переработка
01.10 ДЯ 2 (20:00–22:00) и ДН 2 (22:00–24:00), 02.10 ДН 6 (00:00–06:00) и ДЯ 2
(06:00–08:00). Недостачи нет: рабочее время 01.10 равно длине окна.

Часы в значении Табеля («10,75») — **информационный зарплатный атрибут строки**: в
расчёте участвует только окно, план карточки и недостача считаются от него
(R34, RUL-PLAN-BELOW-WINDOW, EX-51). Отдельной сущности «зарплатная норма смены» в
системе нет и не появилось: значение в ячейку ставит табельщик, строка справочника окон
для него должна существовать (в демо — «Я 10,75» с тем же окном 08:00–20:00), а ручные
строки Табеля заполнение из циклов не перезаписывает.

* `engine_bootstrap.APP_EXTRA_DAY_CODES` — коды «С» и «НВ» удалены;
* `engine_bootstrap.APP_EXTRA_WINDOWS` — вместо «С 16/С 8/С 24» добавлено «Я 10,75»
  (08:00–20:00): значение нужно, чтобы ячейку «Я 10,75» можно было сохранить
  (CHK-WINDOW-EXISTS);
* `tabel_fill._is_overnight` / `_anchor_value` — смена через полночь заполняет Табель
  одним значением в дне-якоре; значение подбирается по **началу** окна (в смене через
  полночь часов больше, чем в окне, поэтому границы целиком совпасть не могут), а при
  нескольких значениях одного начала берётся первое по порядку в справочнике — расчёт от
  этого не зависит, окно одно. Без строки CFG-WINDOWS значение не пишется — вместо этого
  предупреждение при заполнении (иначе расчёт остановился бы на CHK-WINDOW-EXISTS);
  «утро» следующего дня в Табель не переносится;
* `seed.SHIFT_TYPES`: SUTKI — код Табеля «Я», смена 08:00–08:00 через полночь.

### Выходной за отработанные часы — отсутствие в Графике

Было: код «НВ» в Табеле; «Назначить отсутствие» перезаписывало явку этим кодом.

Стало: вид отсутствия `TIMEOFF_HOURS` **не имеет кода Табеля**. В Табеле остаётся
соответствующая явка («Я» или «К»), отсутствие пишется в График как согласованное
(`schedule_absences`), план не меняется (RUL-ABSENCE-ONLY-FLAGS), а недостача дня
гасится банком часов — то есть ранее накопленными переработками. Это в точности
вход и выход приёмочного примера **EX-29** спецификации.

* `POST /api/schedule/range-absence` для вида без кода Табеля пишет согласованные
  отсутствия (`mode: "schedule_absence"`), а не отвечает 422; интервал — окно значения
  Табеля этого дня, иначе сутки;
* редактор ячейки Графика: кнопка «На всю смену» (границы берутся из смены дня) и
  подсказка с часами для заявления;
* модалка «Назначить отсутствие» показывает, какой из двух способов будет применён.

### Часы «выходного за часы» — выводятся, а не задаются константой

Настройка `timeoff_default_hours` (8 ч) не читалась нигде в коде, а заявление
«Выходной за часы» печаталось с **нулем**: `absence-period` не возвращал `hours`,
фронтенд слал `null`, `docs_api` подставлял `hours_val or 0`.

* `schedule.standard_day_hours()` — три шага: окно значения Табеля этого дня →
  ближайшее предыдущее рабочее окно сотрудника → мода окон за 90 дней → глобальный
  fallback (`timeoff_default_hours`, теперь подписан как «если окно не определилось»);
* `GET /api/schedule/absence-period` возвращает `hours` и `hours_source`;
* новый `GET /api/schedule/timeoff-hours?employee_id=&date=`;
* фронтенд печатает в заявлении реальные часы.

### Изъятие кодов из сохранённых версий

`engine_bootstrap.strip_removed_day_codes()` — идемпотентно убирает «С»/«НВ» и их окна
из `engine_settings_versions.payload_json`. **Код изымается, только если в Табеле нет ни
одной строки с ним**: иначе версия стала бы невалидной для уже посчитанных периодов
(UnknownDayCodeError). В таком случае версии не трогаются, а ситуация пишется в лог —
сначала нужно заменить коды в Табеле. Возвращает `{removed_codes, removed_windows,
blocked_by_timesheet}`.

## 3. Починены два теста, которые не запускались с даты ≤ 11

`test_15f` и `test_15g` в `tests/test_api.py` имели `skipTest("нужно число месяца >= 12")`
и на 12-е число падали — то есть CI был зелёным только в первые 11 дней месяца:

* `test_15f` брал `rows[0]` и первый будний день месяца, не проверяя трудоустройство →
  законный `409 «День вне периода трудоустройства»`. Берёт сотрудника и день, где
  `employed` и есть строка Табеля;
* `test_15g` читал `cell["shift"]["kind"]` — поля нет в сетке v7 (ячейка несёт `shifts`
  и `tabel`), и сравнивал фазу с демо-сотрудником «Смены 2», у которого в истории
  блоков индивидуальный шаблон 1/3, а не базовый цикл. Переписан: фаза сверяется по
  Табелю, эталон — базовый цикл 2/2 в противофазе, базовые настройки задаются явно.

## 5. Миграция существующих баз

* **структура таблиц не меняется** — новых колонок в батче нет, `selfcheck` берёт
  ожидаемую схему из `models.py` и проходит без изменений;
* `migrations._apply_timesheet_code_normative` — SUTKI получает код Табеля «Я» (только
  если стоял «С» или код пуст); у TIMEOFF_HOURS код Табеля очищается (только если стоял
  «НВ»);
* `engine_bootstrap.strip_removed_day_codes` — изъятие кодов из версий справочников
  (см. §1); пока коды стоят в Табеле, версии не меняются и пишется предупреждение;
* история Табеля **не переписывается**: строки с кодом «С» в закрытых периодах остаются
  как есть, вместе с ними остаётся и код в справочнике.

Проверка на боевой базе перед запуском:

```sql
SELECT code, COUNT(*) FROM tabel_days WHERE code IN ('С','НВ') GROUP BY code;
```

Если строки есть — заменить их на явку («Я» с нормой) или на отсутствие в Графике,
и только затем перезапустить приложение.
