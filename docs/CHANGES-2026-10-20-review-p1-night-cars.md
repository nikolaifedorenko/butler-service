# Изменения 20.10.2026 — батч review-P1: ночной отчёт и электрокары

Второй батч по внешнему ревью `REVIEW-2026-10-20.md` (продолжение P0, PR #65).
Закрыты пять находок P1 в модулях **night** и **cars**. Ключевое решение владельца
(20.10.2026): конфликт reopen/`sync_reports` исправлен по **варианту B** — записи
убраны из GET-запросов, обслуживание перенесено в фоновую задачу с лидер-замком.

Версия статики: `2026-10-20c`. Новые стражи: `tests/test_review_p1_night_cars.py` (13).

## 1. P1 — GET /today и /reports с побочными записями + reopen «жил» < 2 минут (вариант B)

**Проблема.** `sync_reports(db)` (досоздать наступившие смены, автозакрыть прошедшие
дедлайн 08:00) выполнялся в каждом GET `/api/night/today` и `/api/night/reports`:

* GET переставал быть идемпотентным — запрос чтения писал в базу и гонялся сам с
  собой при параллельном поллинге несколькими клиентами;
* переоткрытый супервайзером отчёт закрывался снова ближайшим же sync (троттлинг
  120 с) — «Переоткрытие живёт < 2 минут», а правки падали в 409 «Смена закрыта»;
* в двух воркерах каждый запрос мог параллельно досоздавать отчёт одной даты —
  IntegrityError по `night_reports.date` (unique).

**Исправление.**

* `sync_reports` **целиком убран из `night_api`** (страж-исходник
  `test_night_api_bolshe_ne_vyzyvaet_sync_reports`): GET /today и /reports — чистое чтение.
* Обслуживание выполняется в двух местах:
  * при старте сервера — `init_db()` под замком `startup_lock` (как раньше);
  * **фоновым потоком** каждые `NIGHT_SYNC_SECONDS` (по умолчанию 60) —
    `app/bootstrap/night_sync.py`, старт/остановка в lifespan (`app/main.py`).
    Тестовый `TestClient` lifespan не запускает — поток не мешает прогонам.
* Несколько воркеров: поток живёт в каждом, но раунд выполняет **один процесс** —
  под неблокирующим замком `core/startup_lock.try_lock("night-sync")`
  (PostgreSQL — сеансовый `pg_try_advisory_lock` по хешу имени; SQLite — `flock`
  на файле `<БД>.night-sync.lock`, добавлен в `.gitignore`). Соседи пропускают
  раунд без ожидания. Гонка создания отчёта между воркерами исключена.
* **Reopen**: момент переоткрытия фиксируется новой колонкой
  `night_reports.reopened_at` (лёгкая идемпотентная миграция
  `migrate_night_reopened_at()`); `sync_reports` пропускает переоткрытые отчёты —
  автозакрытие для них выключено, повторно смену закрывает вручную тот, кто
  переоткрыл (решение владельца: вариант B). Интерфейс показывает «переоткрыта
  вручную — автозаключение отключено» (подпись смены, бейдж архива, текст
  подтверждения), DOCX — ту же формулировку в строке статуса.
* **Изменение контракта** (единственный потребитель — наша SPA):
  * reopen УЖЕ ОТКРЫТОГО отчёта — **409 «Отчёт не закрыт — переоткрывать нечего»**
    (прежде «идемпотентный» 200 без проверки статуса; теперь такой no-op проставил
    бы `reopened_at` и навсегда выключил автозакрытие текущей смены). Симметрично
    закрытию уже закрытого (409). Кнопка в UI видна только на закрытом отчёте;
  * payload отчёта дополнен полем `reopened_at` (аддитивно; схемы ответов в
    OpenAPI пустые — дельта `docs/openapi.json` только в описаниях маршрутов);
  * GET /today в окне «20:00 → первый фоновый раунд» (≤ 60 с) возвращает
    `available: false` с пометкой «отчёт создаётся; обновите страницу через
    минуту» вместо прежнего «смена ещё не началась».
* Тест `test_zakrytie_i_pereotkrytie_smeny` (права) переведён на новую семантику:
  403 → close 200 → reopen 200 → повторный reopen 409.

**Стражи:** `test_pereotkrytyi_otchet_ne_zakryvaetsya_snova`,
`test_get_today_i_reports_ne_pishut_v_bazu`, `test_night_api_bolshe_ne_vyzyvaet_sync_reports`,
`test_run_sync_once_zakryvaet_prosrochennyi_otchet`,

## 2. P1 — автозакрытие не проставляло `close_reason="auto"`

**Проблема.** `finalize_report()` ставил status/closed_at/result, но не причину;
DOCX-выгрузка автозакрытого отчёта подписывалась «Открыт · закроется 08:00»
(ветка строилась по пустому `close_reason`).

**Исправление.** `finalize_report(rep, *, reason="auto")` — автозакрытие пишет
`"auto"`, ручное закрытие вызывает `finalize_report(rep, reason="manual")`
(прежде эндпоинт присваивал поле отдельной строкой после вызова). Строка статуса
выгрузки дополнена веткой «переоткрыт вручную».

**Стражи:** `test_finalize_report_stavit_close_reason_auto`,
`test_ruchnoe_zakrytie_daet_close_reason_manual`,
`test_docx_pokazyvaet_prichinu_zakrytiya_i_pereotkrytie` (проверяет текст внутри
реального .docx: «Закрыт автоматически в 08:00» / «переоткрыт вручную» / «Закрыт вручную»).

## 3. P1 — повторная отметка кара не обновляла `checked_at`

**Проблема.** `check_car_night()` — перезапись «last write wins», но `ch.checked_at`
присваивался только `default=now_local()` при INSERT: после второй отметки время
оставалось от первой, `car.last_checked_at` старел, а флаг «кар взяли ПОСЛЕ
проверки» (`car.last_taken_at > checked_at`) ложно горел, если кар брали между
двумя отметками.

**Исправление.** `ch.checked_at = now_local()` при КАЖДОМ сохранении;
`car.last_checked_at = ch.checked_at` (по-прежнему только для найденного кара —
«не найден» карточку не меняет).

**Страж:** `test_povtornaya_otmetka_kara_obnovlyaet_checked_at` (две отметки с
реальным интервалом: checked_at растёт, карточка кара свежая, флаг
`taken_after_check` гаснет после повторной отметки).

## 4. P1 — формула окна досоздания `min(len(have) + 31, 31)` всегда давала 31

**Проблема.** Формула в `sync_reports` имитировала «умное» окно, но при любом
`len(have)` результат — 31; поведение (сервер, пролежавший > 31 дня, старые смены
не восстанавливает) не соответствовало впечатлению от кода.

**Исправление.** Поведение сохранено, код честный: константа `BACKFILL_DAYS = 31`
и прямая формула `start = today - timedelta(days=BACKFILL_DAYS)`; ограничение
задокументировано (модуль, докстринг `sync_reports`).

**Страж:** `test_backfill_okno_chestnoe` (константа + страж-исходник: формула-обманка не вернулась).

## 5. Попутная гигиена тестов (найденное при работе батча)

* **Прогрев схем маршрутов** (`tests/conftest.py`, `app_stack`): FastAPI строит
  pydantic-схемы лениво при первом матчинге; если первая сборка попадала внутрь
  `freeze_time`, `dt.date` оказывался `FakeDate` и запрос падал — тесты были
  порядок-зависимыми (`test_night_shift` падал при одиночном запуске, в т.ч. на
  main). `app.openapi()` на старте сессии собирает схемы всех маршрутов вне
  заморозки.
* **`test_demo_sluzhby_zakrepleny_za_punktami_shablona`**: фильтр `active` —
  мягко удалённые пункты test_night_zones протекали при нестандартном порядке
  запуска (GET /zones/{id}/items возвращает и выключенные пункты).
* **Фикстура `open_shift`**: сбрасывает и восстанавливает `reopened_at` /
  `close_reason` (герметичность при прогоне во время настоящей ночной смены).
* Напоминание в тестах: `SessionLocal(expire_on_commit=False)` — после записей
  чужой (HTTP) сессии тестовая сессия должна делать `expire_all()`, иначе
  identity map отдаёт устаревшие атрибуты.
