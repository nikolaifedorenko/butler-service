# Изменения 16.10.2026 — ячейка Графика: плашки смен, заявления по интервалам, модалки не закрываются

Батч из пяти правок пути пользователя в «Слой 1 · План / График» и «Слой 0 · Табель»
(решения владельца 16.10.2026).

## 1. Ручная смена — плашками из словаря (слой 1)

В редакторе ячейки Графика пресет ручной смены выбирался из выпадающего списка,
после чего время всё равно показывалось полями ввода. Теперь словарь смен —
плашки (тот же приём, что у значений Табеля в слое 0): «08–20 · 08:00–20:00»,
«20–08 · 20:00–08:00 · +1 сутки», «СУТ», …; цвет плашки — цвет смены из словаря,
в подсказке — полное название. Плашка «⚙ Вручную» раскрывает поля начала/конца
и флаг «через полночь». Текущая ручная смена предвыбирается: совпадает со
словарём — её плашка, не совпадает — «⚙ Вручную» с её временем. Сохраняет
по-прежнему кнопка «Сохранить ручную смену» (PUT /api/schedule/shift).

## 3. Несколько отлучек в один день: одно заявление со списком или по каждому интервалу

Раньше `GET /api/schedule/absence-period` брал ПЕРВУЮ запись дня (`limit(1)`) —
второй интервал в заявлении было не увидеть, и напечатать его отдельно было нельзя.

- **Бэкенд** (`app/api/schedule.py`): эндпоинт собирает ВСЕ интервалы дня, у
  которых есть вид с заявлением (`_interval_info`): для каждого — время, часы
  (вся смена — стандартное окно, EX-29; интервал — длина записи), `whole_shift`
  и `doc_type`. Ответ дополнен `intervals` (список) и `intervals_text` —
  «с 14:00 до 16:00 (2 ч) и с 18:00 до 20:00 (2 ч)»; `hours` — сумма,
  `hours_source` — `combined`. Новый параметр `absence_id` — заявление по одному
  интервалу (404, если интервал не в этом дне). Смешанные точки ввода (вся
  смена + интервал) печатаются документом «об отсутствии на рабочем месте».
  Контракт одиночного интервала сохранён (прежние поля — как раньше).
- **Шаблон** (`app/doc_templates.py`): новый плейсхолдер `{intervals}`; штатный
  текст «об отсутствии» переведён на него — для одного интервала документ
  читается ровно как раньше. `{from_time}/{until_time}/{hours}` остались.
  `POST /api/docs/render` принимает `intervals` и сам собирает строку из
  from/until, если её нет (старые вызовы работают).
- **Миграция** (`migrate_time_off_template`): сохранённые тексты настройки
  `tpl_time_off_request` и вида заявления `time_off_request`, которые НЕ
  редактировали вручную, заменяются на версию с `{intervals}`; пользовательские
  правки не трогаются. Идемпотентна.
- **Фронтенд**: у каждого интервала в списке модалки — кнопки «Печать» и «PDF»
  (заявление только по нему, появляются, когда интервалов больше одного);
  нижние кнопки печатают ОДНО заявление со всеми интервалами, подпись и
  подсказка это объясняют. Быстрая печать (`printAbsenceRequest`) подставляет
  `intervals` из ответа сервера.

### Попутно: settings.value — TEXT (продакшн-баг PostgreSQL)

Шаблоны документов (277–307 символов) хранятся в `settings.value VARCHAR(255)`:
SQLite длину не контролирует, а PostgreSQL отклонял сохранение шаблонов
(«value too long») — и миграция текста на Postgres упала бы так же. Модель
переведена на `Text`, миграция `migrate_settings_value_text` расширяет колонку
на PostgreSQL (на SQLite — no-op).

## 5. Модалки не закрываются после действия — печать доступна сразу

- **Слой 1**: «На интервал», «На всю смену» и «Удалить» у отсутствия больше не
  закрывают редактор ячейки: после действия модалка пересобирается по свежим
  данным (список интервалов, кнопки печати, часы «выходного за часы») —
  заявление печатается одним кликом, заново открывать ячейку не нужно.
  «Сохранить ручную смену» и «Вернуть к генерации» закрывают модалку, как раньше.
- **Слой 0**: «Сохранить» в ячейке Табеля оставляет модалку открытой — после
  сохранения кода отпуска/ДО/ОВ заявление печатается сразу (прежде сохранение
  закрывало окно, и за печатью ячейку приходилось открывать заново). Кнопка
  «Отмена» переименована в «Закрыть».
