# Решения — Уведомления (notify)

**Статус:** реестр действующих решений
**Редакция:** 1.0 от 03.11.2026

Только действующие решения; отменённые не хранятся (история — CHANGELOG). Нумерация
собственная (NT-#); из кода не цитируется. Сквозные решения безопасности секретов —
P8/P14 в [`../platform/decisions.md`](../platform/decisions.md).

| ID | Дата | Решение | Обоснование | Где реализовано |
|----|------|---------|-------------|-----------------|
| NT1 | 19.10.2026 | Отправка только вручную — никакой автоотправки при закрытии объекта или смены | Контроль состава и момента отправки | `application/dispatch.py` |
| NT2 | 19.10.2026 | Право отправки — `night.dispatch`, по умолчанию у всех ролей; отправленное помечается | Отправить может дежурный, не только менеджер | `manifest` (night), `dispatch.py` |
| NT3 | 19.10.2026 | Всё скопом или выборочно; состав получателей фиксируется в журнале снимком | Журнал отвечает «кому именно ушло» | `notify_dispatches` |
| NT4 | 19.10.2026 | Исправили после отправки — повторно не отправляем (ни «исправлено», ни отзыва) | Простота и предсказуемость переписки | `application/dispatch.py` |
| NT5 | 19.10.2026 | Общая служба у нескольких получателей не объединяется: каждая служба шлёт своё сообщение всем своим получателям | Сообщения служб разные по содержанию | `application/dispatch.py` |
| NT6 | 19.10.2026 | Почта — через MS Exchange: релей без авторизации либо SMTP AUTH; Graph/EWS позже за тем же интерфейсом | Решение владельца по инфраструктуре | `application/config.py` |
| NT7 | 25.10.2026 | Секреты транспорта — в БД зашифрованы (`NOTIFY_SECRET_KEY`, Fernet), в API маскированы, в журналах не печатаются; пустое значение при сохранении = «не менять» | В базе и бэкапах секретов нет; интерфейс не стирает токен | `application/secrets.py`, `config.py` |
| NT8 | 22.10.2026 | Рассылки — через outbox-таблицу в транзакции операции; доставляет фоновый отправитель | Надёжность: сообщение не теряется при сбое процесса | outbox, `bootstrap` |
| NT9 | 22.10.2026 | Журнал `notify_dispatches` общий для всех разделов (domain + ref_id) | Один журнал на будущие разделы | `adapters/orm.py` |
