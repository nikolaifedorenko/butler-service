# Модуль «Уведомления: Telegram и почта» (notify) — спецификация

**Статус:** норматив
**Редакция:** 1.0 от 03.11.2026 (консолидация действующего поведения по коду HEAD a3304a9)

## 1. Назначение

Доставка сообщений приложения (ночной отчёт и другие разделы) в Telegram и по почте.
Порядок в меню — 90 (манифест, ADR-0012); экран «Чаты и Почта» в Настройках.

## 2. Правила отправки (решения владельца 19.10.2026)

* Отправка **только вручную** — никакой автоотправки при закрытии объекта или смены.
* Отправка — право `night.dispatch` (по умолчанию у всех ролей); отправленное помечается.
* Всё скопом или выборочно; состав получателей **фиксируется в журнале снимком**.
* Если недостаток исправили после отправки — повторно ничего не отправляется (ни
  «исправлено», ни отзыва сообщения).
* Общая служба у нескольких получателей **не объединяется**: каждая служба шлёт своё
  сообщение всем своим получателям.
* Доставка — через **outbox-таблицу** (надёжность, P14 платформенного реестра): запись
  создаётся в транзакции операции, фоновый отправитель доставляет и отмечает.

## 3. Транспорт и секреты

* **Telegram** — токен бота; **почта** — MS Exchange: либо релей без авторизации
  (user/password пустые), либо SMTP AUTH; позже возможен Graph/EWS — транспорт останется
  за тем же интерфейсом (решение владельца).
* Учётные данные хранятся в таблице `settings`, но это **секреты**: в БД — зашифрованы
  ключом `NOTIFY_SECRET_KEY` (Fernet: AES-128-CBC + HMAC-SHA256), в API — маскированы
  (`public_config`), в журналах и аудите не печатаются вовсе.
* Пустое значение секрета при сохранении означает «не менять» (интерфейс не показывает
  токен и не должен его стирать).
* Ключ потерян или сменился — секрет считается незаданным, экран просит ввести заново;
  смена ключа — `NOTIFY_SECRET_KEY=новый,старый`; без ключа секрет не сохранить; ключ не
  в формате Fernet — приложение не стартует; в prod-compose ключ обязателен.

## 4. Получатели и шаблоны

Службы и получатели (`recipients.py`), шаблоны сообщений (`templates.py`), чаты Telegram
(`chats.py`). Журнал `notify_dispatches` общий для всех разделов: `domain + ref_id`
(ночной отчёт и будущие разделы — одна таблица).

## 5. Права

Экран и API настроек транспорта — `settings.edit` (часть маршрутов принимает одно из
`settings.edit` / `night.edit`); отправка разделов — права разделов (`night.dispatch`).
Отдельных прав модуля в манифесте нет.

## 6. Тесты

`tests/test_notify_secrets.py` (шифрование, маскировка, «пусто = не менять», смена
ключа), юнит-тесты outbox и диспетчера, сценарий настроек (jsdom/смоук).
