# Модуль «Журнал аудита» (audit) — спецификация

**Статус:** норматив
**Редакция:** 1.0 от 03.11.2026 (консолидация действующего поведения по коду HEAD a3304a9)

## 1. Назначение

Единый журнал изменений приложения: кто, когда, что и «было → стало». Порядок в меню —
50 (манифест, ADR-0012). Ядро записи — `app/core` (audit); модуль — экран и API чтения.

## 2. Правила

* Запись аудита — часть use-case'а (в той же транзакции, что изменение); цель
  (`target`) и разница полей (`changes`) обязательны.
* Журналируются: изменения данных всех модулей (брони, гости, фонд, покрытие, Табель,
  График, настройки, права), выгрузки (включая экспорт stays и «Броней»), начальная
  загрузка stays (`stays_reset`), «добавить смену в График» (две записи — шахматки и
  Графика), включение/выключение «Шахматка в эксплуатации».
* **Открытия профилей и просмотр в аудит не пишутся** — только изменения (для stays —
  решение S53 в `../stays/decisions.md`; общая практика та же).
* Действия аудита модулей объявляются их манифестами (ADR-0012).
* Журнал доступен на чтение с правом `audit.view`; записи не редактируются и не
  удаляются (журнал — только добавление).

## 3. Права

| Право | Что даёт |
|---|---|
| `audit.view` | чтение журнала с фильтрами |

## 4. Тесты

Юнит-тесты записи (цель/разница/транзакционность), матрица прав чтения, проверки, что
операции модулей пишут ожидаемые действия (в тестах модулей).
