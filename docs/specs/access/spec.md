# Модуль «Вход и права доступа» (access) — спецификация

**Статус:** норматив
**Редакция:** 1.0 от 03.11.2026 (консолидация действующего поведения по коду HEAD a3304a9)

## 1. Назначение

Аутентификация (вход, сессии), роли как данные, группы доступа и индивидуальные права,
имперсонация. Порядок в меню — 40 (манифест, ADR-0012). Ядро механики — `app/core`
(`auth`, `security`, `permissions`, `identity`); модуль — интерфейсы и экраны.

## 2. Правила

* **Роли как данные** (ADR-0011): роль — строка `Role(code, title, rank,
  max_assignable_rank, builtin)` + гранты `AccessGrant(role, permission, effect)`;
  ранги задают иерархию (EVERYONE < … < SUPERVISOR_UP < MANAGER_UP < ADMIN_ONLY);
  права модулей объявляются их манифестами (ADR-0012).
* **Группы доступа и индивидуальные права** пользователя — поверх ролей
  (`access_api.py`); вычисление — `principal_permissions` (кэш на запрос:
  `gate_permissions`).
* **Пароль** — PBKDF2, 600 000 итераций (ADR-0003); начальный пароль сервер не
  возвращает и интерфейс не показывает; сгенерированный показывается один раз в окне
  до кнопки, с «Скопировать».
* **Сессия** — токен формата ADR-0007; принимается только тип `session`; rate-limit
  входа in-memory (ADR-0005); login-endpoint исключён из CSRF double-submit (P5
  платформенного реестра), остальные маршруты — под CSRF и CSP (ADR-0004).
* **Имперсонация** включена по умолчанию: администратор «становится» любым
  пользователем (`employees.impersonate`); выход из имперсонации — возврат в свою
  сессию (P1 платформенного реестра).
* **Увольнение** закрывает сессии сотрудника (батч 418d62f).
* Принадлежность прав проверяется на сервере каждым запросом (`require_perm`);
  интерфейс лишь прячет недоступное.
