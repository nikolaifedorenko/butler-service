# Модуль «Ночной отчёт» (night) — спецификация

**Статус:** норматив
**Редакция:** 1.0 от 03.11.2026 (консолидация: действующее поведение по коду HEAD a3304a9;
исходное предложение — [`docs/archive/proposals/PROPOSAL-NIGHT-REPORT-V2.md`](../../archive/proposals/PROPOSAL-NIGHT-REPORT-V2.md),
реализовано полностью)

## 1. Назначение

Чек-лист ночной смены 20:00–08:00 (Europe/Moscow) по областям объекта: ночной персонал
отмечает пункты, менеджер видит картину и закрывает отчёт. Порядок в меню — 60
(манифест, ADR-0012); интерфейс — `static/js/modules/night.js` (без сборки, ADR-0008).

## 2. Правила

* Отчёт создаётся **автоматически ровно на каждую ночную смену** — в 20:00; если сервер
  был выключен, отчёт создаётся «задним числом» при старте.
* Список областей и пункты чек-листов **фиксируются снимком** на момент создания отчёта —
  правки справочников позже не ломают открытые и закрытые отчёты.
* Закрепление области за батлером — **рекомендательное**: второй может «перехватить»,
  система предупреждает и пишет факт перехвата в историю.
* В 08:00 следующего дня отчёт **закрывается сам**: все области закрыты → «полный», есть
  незакрытые → «неполный». После закрытия отчёт только для чтения.
* Секцию может закрыть кто угодно; переоткрыть — только закрывший или супервайзер.
* Менеджер может **переоткрыть** закрытый отчёт (`night.reopen_any`): автозакрытие для
  такого отчёта выключается (`reopened_at`), он закрывается вручную повторно — фоновая
  синхронизация его больше не трогает.
* Обслуживание (досоздание смен отчётов и автозакрытие) работает при старте сервера и
  фоновым потоком (`bootstrap/night_sync.py`), а **не в GET-запросах** раздела.
* Время смены хранится в локальном времени объекта (naive), как `Punch.ts`.
* Экспорт отчёта — `application/night_export.py`; рассылка — через модуль notify
  (`night_notify.py`, право `night.dispatch`, см. `docs/specs/notify/spec.md`).

## 3. Справочники и данные

Области ночного отчёта и пункты чек-листов — справочники модуля (модели
`adapters/orm.py`); отчёт — сущность с датой смены, статусом (открыт/полный/неполный),
отметками по пунктам и историей (перехваты, закрытия, переоткрытия).

## 4. Права

| Право | Что даёт |
|---|---|
| `night.view` | просмотр отчётов |
| `night.edit` | отметки чек-листа, перехват областей |
| `night.close` | закрытие секций/отчёта |
| `night.dispatch` | рассылка отчёта (по умолчанию у всех ролей) |
| `night.reopen_any` | переоткрытие закрытых отчётов (менеджер и выше) |

## 5. Тесты

Юнит-тесты домена и API (`tests/`), UI-сценарий ночных зон (jsdom/смоук), проверка
«заднего числа» и автозакрытия. Бюджет запросов — как в SPEC.md §9.
