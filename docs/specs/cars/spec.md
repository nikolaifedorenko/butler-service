# Модуль «Электрокары» (cars) — спецификация

**Статус:** норматив
**Редакция:** 1.0 от 03.11.2026 (консолидация действующего поведения по коду HEAD a3304a9)

## 1. Назначение

Справочник парка электрокаров: статусы, история, выдача / передача / возврат.
Интерфейс — `static/js/modules/cars.js`; прикладной слой — `application/cars.py`
(роутер тонкий, ADR-0006).

## 2. Правила (по ТЗ)

* Кар можно взять **свободный, занятый или стоящий на зарядке** — статусы различаются;
  «на зарядке» — отдельный статус (кар может понадобиться владельцу).
* Один сотрудник — один закреплённый кар; закрепление **рекомендательное** и ставится в
  карточке сотрудника (право супервайзера и выше), здесь только отображается.
* При выдаче кара внутреннему сотруднику с его согласия оформляется **передача**: кар
  остаётся занятым, меняется держатель, возврат отмечает новый держатель.
* Внешние сотрудники (без учётной записи) — по ФИО; возврат отмечает любой.
* Замечания по возврату → кар автоматически **«на обслуживании»**; снять с обслуживания
  может только менеджер/администратор.
* Все события (выдача, передача, возврат, обслуживание, ночные проверки) — в истории кара.

## 3. Связь с другими модулями

Ночной отчёт читает кары через публичный каталог (`application/catalog.py`: `Car`,
`CarNightCheck`) — проверка каров в ночном чек-листе. Приватные адаптеры чужих модулей
не используются (граница R3 платформенной практики).

## 4. Права

Просмотр — всем; операции выдачи/передачи/возврата — по манифесту модуля (см.
`app/modules/cars/manifest.py` — источник истины); снятие с обслуживания — менеджер и
выше; закрепление за сотрудником — в модуле employees (супервайзер и выше).

## 5. Тесты

Юнит-тесты статусной машины и истории, UI-сценарий (jsdom/смоук), интеграция с ночным
чек-листом.
