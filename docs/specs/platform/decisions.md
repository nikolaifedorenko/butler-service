# Решения — платформа (core, deploy, безопасность)

**Статус:** реестр действующих решений
**Редакция:** 1.0 от 03.11.2026

Сквозные решения, не принадлежащие одному модулю: ядро, деплой, безопасность, CI.
Только действующие; отменённые не хранятся (история — [`CHANGELOG.md`](../../../CHANGELOG.md)
и ADR). Архитектурные решения записаны канонически в ADR — здесь индекс, а не пересказ.
Модульные решения — в реестрах модулей (`../<module>/decisions.md`).

## Решения владельца и осознанные трейд-оффы

| ID | Дата | Решение | Обоснование | Где зафиксировано |
|----|------|---------|-------------|-------------------|
| P1 | 15.10.2026 | Имперсонация включена по умолчанию: администратор «становится» любым пользователем | Удобство поддержки; усиление «подтверждение паролем» предложено, но не принято | `SECURITY.md` |
| P2 | 21.10.2026 | Бэкап fail-fast: без `BACKUP_AGE_RECIPIENT` приложение не стартует | Лучше crash-loop, чем незашифрованные копии (решение В-12 аудита) | `deploy/`, `SECURITY.md` |
| P3 | — | Демо-сид с паролем `demo1234` и `run.sh` на `0.0.0.0` — только dev-режим | Документировано; прод — compose с обязательными секретами | `SECURITY.md`, `run.sh` |
| P4 | — | dev-compose не стартует без `SECRET_KEY`/`ADMIN_PASSWORD` | Намеренный fail-fast против «секрет по умолчанию» | `deploy/` |
| P5 | — | Login-эндпоинт исключён из CSRF double-submit | Осознанный трейд-офф: логин не аутентифицирован, CSRF-защита сессии важнее | комментарий `app/core/observability.py`, ADR-0004 |
| P6 | — | Soft-delete модель без `ondelete`; FK-принуждение включено (`PRAGMA foreign_keys=ON`, на PG — из коробки); hard-delete пути чистят детей вручную | Явный контроль целостности вместо каскадов в схеме | `app/core/db.py`, модели модулей |
| P7 | — | Приложение внутреннее, не распространяется — открытой лицензии нет | Решение владельца | `README.md` |
| P8 | 25.10.2026 | Секреты уведомлений (токен бота, SMTP-пароль) шифруются в БД ключом `NOTIFY_SECRET_KEY` (Fernet); ключ потерян — секрет считается незаданным; смена — `NOTIFY_SECRET_KEY=новый,старый` | В базе и бэкапах секретов нет | CHANGELOG 25.10.2026, `notify` |
| P9 | 25.10.2026 | Сессия принимается только с типом токена `session` (одноразовый выход всех сессий при выкатке принят) | Защита от подмены refresh/session | CHANGELOG 25.10.2026, `app/core/security.py`, `app/core/identity.py` |
| P10 | 25.10.2026 | Загружаемая картинка проверяется по содержимому, не по расширению (HEIC отклоняется) | Content-sniffing против переименованного файла | CHANGELOG 25.10.2026 |
| P11 | 20.10.2026 | Ячейки Excel-выгрузок, начинающиеся с `=`, `+`, `-`, `@`, TAB, CR, предваряются апострофом (OWASP) | Защита от CSV/formula injection при открытии в Excel/LibreOffice | `safe_sheet_cell` в `app/core/format.py` |
| P12 | 20.10.2026 | Цвета в атрибуте `style` — только строгий `#RRGGBB` | Защита от HTML/CSS-инъекции | `normalize_hex_color` в `app/core/format.py` |
| P13 | 22.10.2026 | Версия статики — одна точка (`tools/bump_version.py`): `?v=` в index.html и VERSION/хеш оболочки в sw.js совпадают; CI проверяет (`--check`, UI-04) | Иначе пользователи остаются на старом JS из кэша service worker | `tools/bump_version.py`, CI |
| P14 | 22.10.2026 | Контейнер не от root; рассылки — через outbox-таблицу | Гигиена деплоя и надёжность доставки | CHANGELOG 22.10.2026, `deploy/` |
| P15 | 25.10.2026 | CI-гейты: порог покрытия (приложение ≥ 90 %, ядро расчёта ≥ 95 %), mypy для ядра, Trivy (HIGH/CRITICAL с фиксом блокируют merge), gitleaks, dependabot (pip + Docker-образы), отдельный job полного сьюта на PostgreSQL 16 | Raw-SQL миграции и типы колонок ломались только на PG (DB-02/DB-06) | `.github/workflows/ci.yml` |
| P16 | — | Полный сьют тестов использует общую тестовую БД (conftest пересоздаёт один раз на сессию) — параллельные запуски pytest не поддерживаются | Простота фикстур против изоляции прогонов | `tests/conftest.py` |
