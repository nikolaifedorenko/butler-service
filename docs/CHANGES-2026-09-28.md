# Изменения 28.09.2026 — интерфейс, производительность, инженерная обвязка

Батч сделан по итогам архитектурного разбора (`analysis/ARCHITECTURE.md`, ветка
`fix/architecture-and-ui`). Все изменения покрыты тестами: **153 passed** (до батча —
120 passed / 1 failed).

## 1. Интерфейс: разделы «Ночной отчёт» и «Электрокары» реализованы

**Что было.** Последний коммит добавил бэкенд ночных отчётов и электрокаров
(38 маршрутов), пункты в навигации и контейнеры `<section id="view-night|view-cars">`,
но функции `loadNight()` и `loadCars()` написаны не были. `navigate()` собирал карту
загрузчиков прямыми ссылками на них, поэтому **ReferenceError возникал при каждом
переключении раздела** — контент не загружался нигде, интерфейс выглядел «пустым».

**Что сделано.**
* `static/js/section_night.js` — раздел «Ночной отчёт»: текущая смена и архив,
  прогресс областей, чек-листы ОК/Не ОК с комментариями и фото, перехват области
  с подтверждением, шаг «Проверка электрокаров» (отметка по каждому кару, завершение
  шага), закрытие/переоткрытие смены, выгрузка DOCX/PDF, справочник областей и пунктов
  (включая массовое создание серии), права по ролям.
* `static/js/section_cars.js` — раздел «Электрокары»: парк со статусами, фильтром
  и поиском, «Ваш кар» и «Рекомендуемый свободный кар», операции Взять / Передать /
  Вернуть (multipart + фото) / Выдать / Закрепить / Статус / Карточка / История,
  справочник мест стоянки.
* Определены `CAR_BADGE`, `carHandoverModal()`, `carReturnModal()`: их вызовы уже были
  в `app.js`, из-за чего полоска «Электрокар» в «Моих отметках» показывала
  «Раздел недоступен», а кнопки «Передать»/«Вернул» роняли обработчик.
* `navigate()` ищет загрузчик раздела по имени в глобальной области и показывает внятную
  заглушку с инструкцией: отсутствующая функция раздела больше не может «погасить»
  весь интерфейс.
* `static/css/app.css` — стили новых разделов (адаптив, карточки областей, превью фото).
* `tools/bump_version.py` — версия статики (`?v=` в index.html и `VERSION`/SHELL в sw.js)
  меняется одной командой, режим `--check` для CI. Версия: `2026-09-28a`.

## 2. Исправлены падения и 404 (найдены статически и тестами)

| Где | Было | Стало |
|---|---|---|
| `app/cars.py: return_car()` | условие `(by_employee_id or name)` — переменной `name` не существует → **NameError → 500 при любом возврате кара** без явного указания сотрудника (обычный случай) | `(by_employee_id or by_name)` |
| `app/api/cars_api.py: car_history()` | в `history_dict()` передавался раскрытый список фото вместо карты → **AttributeError → 500 на любом запросе истории кара** | передаётся карта, контракт описан в docstring |

| `app/photos.py: photo_url()` | ссылался на `/api/photos/{id}/file`, а маршрут существовал только как `/api/night/photos/{id}/file` → **каждое фото отдавало 404** | добавлен `app/api/photos_api.py` с каноническими `GET/HEAD /api/photos/{id}/file` и `DELETE /api/photos/{id}`; ночные маршруты стали алиасами той же реализации |
| `app/night.py: ensure_report()` | сравнение с «сегодняшней» датой: смена, идущая ночью (00:00–08:00), не получала отчёт при старте сервера после 20:00 → пустой раздел до автозакрытия | сравнение с моментом старта смены (`20:00` даты смены) |
| `app/api/night_api.py` | дубли `operation_id` для GET/HEAD (предупреждение FastAPI) | отдельные `operation_id`, HEAD скрыт из схемы |

## 3. Производительность: N+1 убран, тяжёлый пересчёт ушёл в фон

Замеры (`SQLAlchemy before_cursor_execute`, демо-база → 50 сотрудников, месяц 31 день):

| Маршрут | До | После |
|---|---|---|
| `GET /api/schedule` | 4 515 запросов / 2 048 мс | **13 / 321 мс** |
| `GET /api/punches/onwork` (поллинг 30 с) | 161 / 82 мс | **11 / 16 мс** |
| `GET /api/employees` | 155 / 72 мс | **5 / 15 мс** |
| `POST /api/settings/recalc-all` | 11 820 / 5,1 с | **1 191 / 0,62 с** |
| `pytest tests/ -q` | 99,5 с | **~40 с** |

* `shiftrev.ShiftCatalog` — словарь смен и ревизии двумя запросами на обработчик.
* `base_schedule.BlockIndex` — записи блоков одним запросом (или из уже выбранных строк).
* `doublepay.DoubleContext` — календарь двойной оплаты и ВИП-периоды на диапазон.
* `employment.ranges_from_periods()` — расчёт по уже загруженным периодам.
* `timesheet.day_pieces/recalc_day/recalc_range` принимают предзагруженные `entry_map`,
  `punches_by_day`, `row_map`, `base_cfg`, `employed`, `catalog`, `index`, `double_ctx`.
* `api/employees.py`: удалён `db_car_of()`, открывавший **отдельную сессию на каждого
  сотрудника**; кары грузятся одним запросом, связи — `joinedload`/`selectinload`.
  Добавлена ORM-связь `Employee.assigned_car ↔ Car.assigned_employee`.
* `POST /api/settings/recalc-all?background=1` + `GET /api/settings/recalc-status`:
  пересчёт месяца выполняется в отдельном потоке со своей сессией, пишет аудит и статус;
  кнопка в «Настройках» опрашивает статус и блокируется на время работы.
  Синхронный режим сохранён по умолчанию (его используют тесты и небольшие базы).

**Проверка корректности:** на одной и той же базе пересчёт трёх месяцев выполнен старым
и новым кодом — **1 430 строк табеля совпадают поле в поле** (включая `detail_json`),
ответы `recalc-all` идентичны.

## 4. Схема, миграции, самодиагностика

* `GET /api/selfcheck` строится из `Base.metadata` (`models.py`) — единственного источника
  правды. Раньше рядом с `migrate_db()` существовал второй рукописный список, который
  разошёлся: шесть добавленных миграцией колонок (включая `users.token_version`) не
  проверялись.
* Миграции вынесены из точки входа в `app/migrations.py` (~330 строк): `main.py`
  уменьшился с 485 до 173 строк. Идемпотентность покрыта тестом.
* `auth.can_manage_user()` — правило «супервайзер не управляет supervisor/manager/admin»
  перенесено из приватной функции одного API-модуля в слой доступа.
