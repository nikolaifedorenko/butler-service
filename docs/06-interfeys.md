# 6. Интерфейс

Решение — ADR-0013, раздел 7 (сборки по-прежнему нет, ADR-0008). Интерфейс — одностраничное
приложение и PWA: `static/index.html`, `static/sw.js`, `static/manifest.webmanifest`.

## 6.1 Устройство

```
static/
  index.html            каркас, подключение модулей (список генерирует tools/bump_version.py)
  sw.js                 service worker: оболочка в кэше, версия строкой VERSION
  css/                  tokens.css, base.css, components.css, app.css
  js/
    core.js             транспорт (api, multipartApi, downloadBlob), состояние, модальные окна, утилиты
    app.js              вход, меню, маршрутизация, сброс состояния при смене пользователя
    registry.js         реестр разделов и экранов Настроек (registerModule)
    ui/                 html.js (lit-html), form.js (поля форм), theme.js (тема)
    modules/            по файлу на раздел и экран: stays*.js, settings*.js, night*.js, cars*.js, …
  vendor/lit-html/      библиотека целиком, без внешних адресов (обновление: npm run vendor)
  fonts/ icons/         шрифты и иконки — свои
  design.html           образец всех компонентов в обеих темах
```

* Все скрипты — ES-модули, у каждого явные `import` / `export`; глобальных имён нет. Снаружи для
  сквозных тестов `app.js` публикует в `window` только `navigate`, `state`, `toast`, `openModal`.
* `core.js` не знает разделов. Обработчик показа входа при `401` ему задаёт `app.js`
  (`setLoginHandler`); реестр разделов вынесен в `registry.js` без зависимостей — иначе круг
  импортов выполнил бы `app.js` раньше ядра.
* Раздел регистрирует себя при загрузке: `registerModule({ views: { id: load } })` либо
  `registerModule({ screens: { id: { render, icon } } })` для экранов «Настроек». Подписи, порядок
  и права пунктов меню задаёт манифест модуля на сервере (`state.menu`, `state.settingsScreens`).
* Если файл раздела не загрузился или загрузчик упал, вместо пустого экрана показывается заглушка
  с причиной.
* Нижняя панель на телефоне оставляет «Сегодня» слева и «Разделы» справа. Между ними помещаются
  до трёх быстрых вкладок. Каталог «Разделы» показывает весь доступный список и отмечает текущий
  экран. Настройка хранится в браузере отдельно для каждой учётной записи и ограничена
  действующими правами. При входе в режиме просмотра за сотрудника действует набор его роли.
* На компьютере при входе в настройки основное меню занимает узкую колонку. Кнопка над разделами
  разворачивает её. Имена иконок доступны программам чтения и видны при наведении или фокусе.
  Панель публикации появляется при наличии неопубликованных изменений.
* Карточка на «Сегодня» открывает конкретную бронь. Для права просмотра только своих гостей
  краткая карточка использует данные «Сегодня». После закрытия фокус возвращается на ту же бронь.
  «Сейчас важно» появляется при наличии годовщин свадеб на текущую дату объекта. Напоминания берутся
  из `GET /api/stays/mine/today` и отображаются отдельно от заездов и выездов.
* Управленческий табель показывает причину общей блокировки рядом с периодом. Ответ
  `GET /api/mgmt` передаёт даты предыдущего периода по действовавшим тогда правилам,
  отдельно отмечает отсутствие начального остатка и сохраняет ошибки в строках сотрудников.
* Стрелки листания берутся из `ui/period_nav.js`. Для каждой пары доступные имена
  называют единицу листания. Поля формы входа сохраняют постоянные подписи и нативное автозаполнение.
* `ui/data_state.js` задаёт общий вид загрузки, ошибки, пустого раздела и пустого результата поиска.
  Используйте сообщение в области данных и действие «Повторить» или «Сбросить фильтры».
  Образцы в обеих темах доступны на `static/design.html`. Для автоматического листания
  к дате используйте `scrollBehavior()`: он учитывает системную настройку движения.

## 6.2 Разметка: lit-html

Разметка строится шаблонами `html` из `ui/html.js`; вставки экранируются по умолчанию.

* `innerHTML`, `outerHTML`, `insertAdjacentHTML` и импорт `unsafeHTML` запрещены ESLint.
* Экран перерисовывается на месте: `render(шаблон, mount(контейнер))`. `mount()` даёт корень внутри
  контейнера, который другой код может стереть (смена пользователя, ошибка загрузки), и создаёт
  его заново, если корня нет. Контейнер, который наполняет другой код, в шаблоне остаётся пустым —
  `render()` дописывает, а не заменяет.
* Обработчики — в шаблоне (`@click=${…}`); значения полей — свойствами (`.value=`, `.checked=`).
  Поле с поиском и задержкой берёт `value=` как атрибут, иначе перерисовка затрёт набранное.
  Динамических имён атрибутов нет: варианты пишутся отдельно.
* Поля форм — `ui/form.js`: `fieldRow`, `textInput`, `checkField`, `selectField`, `optionView`.
* Модальные и боковые окна — `openModal({ title, body, footer, onMount })` и
  `openDrawer({ title, body, footer, onMount })`. Тело и подвал — шаблоны, строка выводится
  текстом. Доступное имя берётся из заголовка. При открытии фокус получает кнопка «Закрыть».
  Если сценарию нужен другой начальный фокус, его можно задать в `onMount`.
* Только верхнее окно в стеке принимает фокус. Tab и Shift+Tab цикличны, Escape закрывает
  верхний слой. При закрытии фокус возвращается к инициатору. Для боковой карточки, чей
  инициатор перерисовывается, `returnFocusTo` позволяет найти его заново.
* Иконки меню (`ICONS` в `app.js`) — собственные постоянные svg-строки, узел из них создаёт
  DOM-разбор; данные сервера так не вставляются.

## 6.3 Дизайн-система

Образец всех компонентов — `static/design.html`; его проверяет `e2e/design.spec.mjs`.

| Файл | Что внутри |
|---|---|
| `css/tokens.css` | **единственное место значений**: цвета (светлая и тёмная тема), шрифты, шкала текста, отступы, радиусы, слои, движение |
| `css/base.css` | шрифты (self-hosted woff2), сброс, общие правила страницы |
| `css/components.css` | компоненты: кнопка, поле, панель, бейдж, сегмент-переключатель, показатель, `.alert`, модальное окно, `.drawer`, уведомление, индикатор загрузки |
| `css/app.css` | вёрстка экранов и каркаса |

Страж `tests/test_design_tokens.py` проверяет цвета вне `tokens.css`, необъявленные переменные
и единственное объявление каждой цветовой роли. Значения адаптивной роли записаны вместе.

Цветовые токены называются по роли, а не по оттенку: поверхности `bg`, `bg-soft`, `panel`,
`surface-1…4`; линии `line-soft`, `line`, `line-strong`; текст `text`, `muted`, `muted-2` (второстепенные
подсказки; контраст не ниже AA), `heading`, `brand-fg`; тон сообщения
`<семья>-bg`, `-line`, `-fg`, `-solid` для `brand`, `ok`, `warn`, `danger`, `info`; текст на
заливке `on-solid`, `on-navy`; `scrim` под модальным окном. Прежние имена (`--primary`, `--navy`,
`--gold`…) сохранены; новый код берёт имена по ролям.

Тема: `ui/theme.js` — обычный скрипт в `<head>` (применяется до отрисовки), выбор хранится в
`localStorage` (`butler-theme`), `data-theme="light|dark"` на `<html>` выбирает `color-scheme`.
Без атрибута браузер выбирает цветовую схему по настройке устройства. Роль цвета берёт значение
светлой или тёмной темы через `--if-light` и `--if-dark`.
Пары «текст на фоне» проходят WCAG AA (≥ 4,5 : 1) в обеих темах. `textOn` в `core.js`
выбирает текст для цветных плашек (полосы броней, коды смен, метки). Если ни один фирменный
цвет не достигает AA на выбранном фоне, используется чёрный текст.

**Доступность.** `e2e/a11y.spec.mjs` прогоняет axe (WCAG 2.1 A и AA) по каждому разделу и экрану «Настроек» под
тремя ролями в светлой и тёмной теме и по форме входа: подписи у кнопок и полей, контраст, имена элементов.
Прокручиваемые области (`.table-wrap`, `.sb-grid`) доступны с клавиатуры. В шахматке объектов с доступными карточками
Tab переводит фокус на одну полосу. Стрелки влево и вправо выбирают бронь в той же строке, вверх и вниз — ближайшую
по дате бронь в соседней строке с бронями. Enter открывает карточку, Escape возвращает к полосе. Если доступных
карточек нет, Tab фокусирует саму область прокрутки. Поля без видимой подписи получают `aria-label`.
Клавиатуру целиком и экранные читалки автоматическая проверка не заменяет.

Заголовки страниц и приветствие сохраняют Playfair Display, показатели используют Manrope
с табличными цифрами. Размер заголовка, плотность подписей панелей и размеры элементов
управления имеют отдельные токены. У компактных стрелок периода и основных сенсорных действий
разные размеры: 32 и 44 px соответственно.

Новый компонент берёт значения из токенов. Стиль компонента — в
`components.css`, вёрстка экрана — в `app.css`; показать на `design.html` и добавить в проверку.

## 6.4 Телефон

Телефон — отдельный сценарий, а не сжатый десктоп. Границы: 1000 px (Настройки, фильтры), 860 px
(нижняя панель вкладок, боковое меню выдвижное), 640 px (таблицы с классом `responsive` — карточками).
На телефоне кнопки, списки и поля не ниже 40 px; «Настройки» вместо ленты экранов показывают кнопку
«Раздел: …» со списком в окне. Страж — `e2e/mobile.spec.mjs`: все разделы меню четырёх ролей и все
экраны Настроек на 375 px не шире окна (вне прокручиваемых блоков), без целей нажатия ниже 40 px.

## 6.5 Версии статики и кэш

`tools/bump_version.py <версия>` пересобирает список скриптов `index.html` и список оболочки в
`sw.js`; CI сверяет их (`--check`). Статика отдаётся с `Cache-Control: no-cache` (ETag → 304),
модули подключают друг друга по адресу без `?v=`. После любой правки JS или CSS версию поднимают.

## 6.6 Проверки

Все проверки интерфейса — Playwright в настоящем Chromium (`e2e/`, `npx playwright test`); jsdom в
проекте нет. Три проекта на трёх серверах со свежими демо-базами:

* `chromium` — быстрые проверки: обход разделов и экранов «Настроек» под пятью ролями
  (`sections.spec.mjs`: текст нарисован, нет «Загрузка…», `undefined`, `NaN`, `[object Object]` и
  ошибок консоли), экраны разделов, мобильные размеры, дизайн-система;
* `scenarios` — длинные пути с изменением данных (`e2e/scenarios/`): настройки, фонд, норматив Табеля и
  Графика, «График = 4 слоя», шахматка под четырьмя ролями. Сценарий — функция, которая выполняется
  внутри страницы (`page.evaluate`): те же `click`/`change`/`check`, настоящие события и сеть; внутренние
  имена интерфейса берутся динамическим `import()` тех же модулей страницы, подмена ответов сервера — перехватом
  `fetch`;
* `night` — ночной обход и электрокары на сервере с часовым поясом, в котором сейчас ~23:00 (идёт ночная
  смена 20:00–08:00), чтобы проверки не зависели от времени суток.

Снимки всех разделов для документации — `npm run screenshots`. Список команд — [документ 4](04-razrabotka.md), раздел 4.3.
