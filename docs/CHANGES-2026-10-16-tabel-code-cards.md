# Изменения 16.10.2026 (батч 8) — карточки кодов Табеля, режим отметок у кода, «НБ» исключён как артефакт

Задача владельца (`changes.md`): применить серию изменений раздела «Настройки» и поправить
две находки предыдущего разбора: (1) флаги отсутствия соблюдались только на фронте —
прямой запрос к API позволял отметиться в отпуске; (2) устаревший комментарий в
`app/models/schedule.py` про несуществующие `ScheduleEntry.punch_*_override`.

Серия большая, поэтому разбита на три очереди. **Этот батч** закрывает разделы задания
«"Коды и окна Табеля"», «Окно "+ КОД ТАБЕЛЯ"», «Окно "+Значение и окно"» и обе находки.
Следующие очереди: «Смены и отсутствия» (Графиковые смены) + окно «Новая смена», затем
«Группы и графики» + карточка сотрудника.

## Находка 1: режим отметок соблюдает сервер (не только фронтенд)

`POST /api/punches` теперь проверяет право отметиться ДО записи (`_punch_locked`):

* покрывающее согласованное отсутствие — режим из словарного вида (как раньше читал
  только `GET /api/punches/status`);
* код Табеля сегодняшнего дня — режим из карточки кода (см. ниже).

Отказ — 409 с тем же текстом статуса, что видит кнопка («Отметку поставить нельзя:
сейчас статус: Ежегодный отпуск — отмечать приход запрещено»). Корректировка задним
числом (`ts`, инструмент менеджера с правом `punches.manage`) ограничению не подлежит:
это способ исправить историю, а не «отметиться в отпуске».

`_punch_permissions` возвращает `(in_ok, out_ok, текст статуса)` — один источник для
`/status` и для приёма отметок.

## Находка 2: устаревший комментарий убран

`app/models/schedule.py`: комментарий у `punch_in_allowed/punch_out_allowed` больше не
ссылается на `ScheduleEntry.punch_*_override` (таблица `schedule_entries` — легаси,
переопределений в текущей модели нет). Заодно зафиксировано, где режим проверяется
на сервере и что второй слой режима живёт в карточке кода Табеля.

## Экран «Коды Табеля» (переименован из «Коды и окна Табеля»)

* **Переименование** — в реестре под-разделов, заголовке, кросс-ссылках экрана
  «Смены и отсутствия», SPEC.md и комментариях. Вкладки экрана прежние:
  «Коды Табеля» / «Окна и значения».
* **Карточки вместо таблицы**: код-пилюля, название, четыре флага
  («Несёт часы», «Принимает коды УТ», «Учитывается в УТ», «"План=Факт" = Авто») —
  **чекбоксы в карточке** (правки копятся в черновике версии, как раньше), счётчик окон
  и виды смены словаря — в подвале карточки.
* **Кнопка «Изменить»** — открывает модалку карточки кода (название, цвет, флаги,
  режим отметок, заявление).
* **Коды разрешено удалять** (кнопка «✕»): код уходит из черновика вместе со своими
  значениями/окнами. Публикацию версии проверяет **сервер**
  (`_guard_removed_day_codes` в `PUT /api/engine-settings`): код, который стоит в
  Табеле, или на который ссылается живой вид смены, удалить не получится — 422 с
  объяснением (та же логика, что в `strip_removed_day_codes` для нормативных изъятий).
  Прежде удаление предлагалось только в режиме эксперта и без защиты.
* **Режим отметок у кода, несущего часы**: чекбоксы «Пришёл на работу» / «Ушёл с
  работы» в карточке и в модалке (видны, когда «Несёт часы» включён). Хранятся в
  строке `day_code_policy` payload'а как данные приложения (`punch_in`/`punch_out`,
  рядом с `title`/`color` — домен их не знает, 2.4). По умолчанию разрешено:
  RUL-ALL-MARKS-COUNTED — отметка в день без плана даёт переработку (в т.ч. в «В»).
* **Заявление у кода без часов**: вместо отметок карточка предлагает шаблон заявления
  (`doc_type` строки кода). `GET /api/schedule/absence-period` для источника
  «Табель» берёт шаблон из карточки кода ПЕРЕД привязкой словарного вида — печать
  заявления больше не требует вида смены с этим кодом Табеля.

## Окно «+ Код Табеля»

* убрано поле «Окно (значение) по умолчанию» — окна настраиваются во вкладке
  «Окна и значения» (решение владельца: дубль не нужен);
* чекбоксы «Пришёл на работу» / «Ушёл с работы» — показываются при включённом
  «Несёт часы»;
* при выключенном «Несёт часы» — выбор шаблона заявления («— не печатать —» либо вид
  из словаря «Документы и справочники»).

## Окно «+Значение и окно»

В списке кодов — только несущие часы (стандартное окно и часы бывают лишь у рабочего
дня); сохранение с кодом без часов отклоняется и на клиенте. Прежнее значение кода,
у которого флаг сняли, остаётся доступным для правки (история).

## «НБ» — артефакт: код исключён из справочника (отмена решения батча 7)

Владелец: «Такого кода просто не существует, это артефакт какой-то из старого».
Батч 7 (16.10.2026) добавил под «НБ» вид смены `SICK_UNPAID` — теперь решение
пересмотрено, код изъят целиком (как ранее «С» и «НВ»):

* `app/engine/domain/settings/defaults.py` — «НБ» убран из стартового `DAY_CODES`;
* `REMOVED_DAY_CODES = ("С", "НВ", "НБ")` — `strip_removed_day_codes` при каждом
  старте изымает код и его окна из сохранённых версий (идемпотентно; если код стоит
  в Табеле — версии не трогает и пишет предупреждение в лог, как для «С»/«НВ»);
* `CODE_TITLES` / `CODE_COLORS` — без «НБ»; `V4_CODE_COLORS` (фронтенд) — без «НБ»;
* seed — вид `SICK_UNPAID` больше не сеется;
* **миграция** `_migrate_remove_sick_unpaid()` (в `migrate_db()`): вид удаляется, если
  на него нет ссылок; при ссылках (отсутствие/смена/ревизия) — архивируется с
  очисткой `tzh_code` (health-проверка APP-SHIFT-CODE смотрит и архивные строки);
* проверка `APP-CODE-NO-SHIFT` для «К» (документарный код с «План=Факт = Авто», R19)
  из батча 7 сохранена — после изъятия «НБ» предупреждений снова нет.

## Данные: `CODE_EXTRA` и `apply_code_app_defaults`

Стартовое наполнение карточек кодов (`app/engine_bootstrap.py`):

| Код | Отметки | Заявление |
|-----|---------|-----------|
| ОТ (Ежегодный отпуск) | запрещены | `vacation_paid` |
| ДО (Отпуск без сохранения) | запрещены | `vacation_unpaid` |
| остальные | разрешены | — |

Значения перенесены из `SHIFT_EXTRA` словаря смен (VACATION/VACATION_UNPAID) — режим
отпуска сохранён, но источником стала карточка кода. `apply_code_app_defaults()` в
`bootstrap_engine` идемпотентно добирает недостающие `punch_in`/`punch_out`/`doc_type`
в строки кодов сохранённых версий (существующие значения не перезаписывает —
расчёт закрытых периодов не меняется: домен app-полей не знает).
