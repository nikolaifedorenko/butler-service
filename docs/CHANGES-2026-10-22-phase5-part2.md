## 1. Манифест модуля, бэкенд (5.3, ADR-0012)

* Каждый модуль описывает себя в `app/modules/<имя>/manifest.py` (`MODULE = ModuleManifest(...)`):
  роутеры, модели, права с ролями по умолчанию, названия действий аудита, разделы уведомлений.
  Ядро описывает себя тем же типом (`core.manifest.CORE`).
* `bootstrap/modules.discover()` находит манифесты сам; пакет без `manifest.py` — ошибка старта.
  Из манифестов берут данные:
  * `main.py` — роутеры;
  * `registry.ensure_models()` — модели;
  * `core/permissions.py` — каталог прав и права ролей по умолчанию (`load_catalog`);
  * журнал аудита — названия действий;
  * `notify` — разделы уведомлений.

  Ядро модули по-прежнему не импортирует (R5).
* Тест архитектуры берёт список модулей из манифестов.
* Сверено со снимком до перестройки: маршруты, OpenAPI (как словарь), каталог прав, права ролей,
  названия аудита и разделы уведомлений совпали. В `docs/openapi.json` изменился только порядок
  путей: маршруты подключаются группами по модулям, пересечений путей нет.

## 2. Манифест модуля, фронтенд (5.4, дополнение к ADR-0008)

* Пункты меню (`MenuItem`) и экраны «Настроек» (`Screen`: группа, порядок, право видимости,
  `external`) объявлены в манифестах. `/api/auth/me` отдаёт их уже по правам (`menu`,
  `settings_screens`).
* Файлы разделов регистрируют загрузчики и рендеры: `registerModule({views, screens})`.
  Удалены захардкоженные `visibleTabs()`, `LOADERS` и `SETTINGS_SCREENS`. Контейнер раздела
  нового модуля создаётся сам. Состав и порядок меню и экранов не изменились.
* Список `<script>` в `index.html` генерирует `tools/bump_version.py`: `core.js`, `app.js`, затем
  все `static/js/modules/*.js` по алфавиту. Порядок файлов разделов больше не важен: убрана
  единственная ссылка между файлами при загрузке (`settings.js` → `night.js`, `cars.js`).
  Проверено загрузкой в jsdom в прямом и обратном порядке.
* Новый `tools/gen_importlinter.py` генерирует контракты `.importlinter`, где перечислены модули
  (изоляция `notify`, R3); `--check` добавлен в CI. Контракты совпали с прежними.
* **Отклонения от плана.**
  * Отдельный `GET /api/app/manifest` не введён: меню едет в `/api/auth/me`, который уже
    запрашивается при входе, входе «как сотрудник» и смене прав.
  * PERF-03 не сделан: сотрудник по-прежнему скачивает все файлы разделов. Service worker
    всё равно кэширует всю оболочку, а ленивое подключение по правам усложнило бы вход и
    имперсонацию.

## 3. Роли как данные (5.5, ADR-0011)

* Таблица `roles(code, title, rank, max_assignable_rank, builtin)`, ревизия `0007` (идемпотентна).
  Встроенные роли: администратор 100/100, менеджер 80/80, супервайзер 60/10, сотрудник 10/−1.
* `can_manage_user` считает по уровням ролей из таблицы. На встроенных ролях решения совпадают
  с прежними — проверено перебором всех сочетаний.
* В «Права доступа → Роли» можно создать, настроить и удалить свою роль. Встроенные роли не
  меняются и не удаляются, назначенную роль удалить нельзя. API:
  `POST /api/access/roles`, `PUT /api/access/roles/{code}/settings`,
  `DELETE /api/access/roles/{code}`.
* `/api/auth/me` отдаёт названия ролей и роли, которые пользователь вправе назначать. Названия
  во фронтенде (`roleTitle`) и список ролей в форме сотрудника берутся оттуда. У нового
  сотрудника по умолчанию выбрана роль «Сотрудник».
* **Отклонение от плана.** Таблица `role_permissions` не понадобилась: права роли — прежние
  гранты `access_grants(role=…)`, настройки заказчика переносить не нужно.

## 4. Пробный модуль вместо пилота (5.8)

`tests/test_module_probe.py` кладёт модуль во временную папку и подключает его в отдельном
процессе со своей базой. В приложение и в основной прогон тестов он не попадает. Из одного
`manifest.py` модуль получает:
* маршрут под своим правом (администратор и супервайзер — 200, сотрудник — 403);
* модель в метаданных;
* право в каталоге с ролями по умолчанию;
* название действия в журнале аудита;
* раздел уведомлений;
* пункт меню и экран «Настроек» на своих местах — только у тех, у кого есть право.

Таблицу нового модуля пока создаёт ревизия в общем каталоге Alembic: свои каталоги ревизий
модулей не сделаны (ADR-0012).
