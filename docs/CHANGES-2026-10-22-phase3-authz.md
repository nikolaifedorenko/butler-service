## 1. Права вместо проверок роли в коде (AUTHZ-05, В-2)

В восьми местах доступ решала роль, и выдать или снять такое действие в «Правах доступа» было
нельзя. Пример: супервайзер с явным правом получал 403 на дни двойной оплаты (EXP-ROLEGRANT).
Новые ключи каталога; по умолчанию они есть у тех же ролей, что и раньше:

| Ключ | Что разрешает | По умолчанию |
|---|---|---|
| `employees.bank` | корректировка банка часов | администратор, менеджер |
| `settings.doublepay` | дни двойной оплаты (запись) | администратор, менеджер |
| `cars.maintenance` | поставить кар на обслуживание и снять с него | администратор, менеджер |
| `cars.override` | передать или вернуть чужой кар | + супервайзер |
| `night.reopen_any` | переоткрыть чужую закрытую область обхода | + супервайзер |
| `media.delete_any` | удалить чужое фото или видео | + супервайзер |

Неактивные места стоянки видны по `cars.issue` (та же аудитория). Название `employees.edit`
уточнено: «Редактирование сотрудников» (банк теперь отдельно).
Страж: роль (`principal.role`, `is_manager`, `is_admin`) читает только ядро прав —
`core/auth.py`, `core/auth_guards.py`, `core/permissions.py` — и `main.py` (подробности
selfcheck). Комментарий в `core/auth.py` приведён к факту (DOC-03).

## 2. Экраны — по правам, а не по роли (UI-02)

* Сетка Графика доступна только для чтения без `schedule.edit`, как и её тулбар. Раньше
  ориентир был роль «сотрудник».
* Справочник сотрудников грузится при `employees.view`. Словарь смен для легенды сетки
  подгружается, если его нет.
* Поле «кто вернул» в окне возврата кара видно только при `cars.issue`.
* Кнопка «Корректировка банка» показывается по `employees.bank`, правка дней двойной оплаты —
  по `settings.doublepay`.
* Список ролей в форме сотрудника не менялся: это иерархия ролей, а не права экрана.

## 3. «Стартовый банк часов» убран (UI-01)

Движок v7.1 это поле не читал (EXP-BANK), а супервайзер, которому корректировка банка
запрещена, мог его менять (EXP-SUPBANK). Поле убрано из формы, из ответа API и из
`/bank-adjustments`, а присланное значение игнорируется. Подсказки исправлены: «банк = итог
последнего закрытого периода ± корректировки»; начальный банк задаётся корректировкой
`OPENING_SEED`. Колонка `employees.balance_hours` остаётся до фазы 5 (удаление — ревизией
Alembic).

## 4. Кары (BUG-02, BUG-03 / В-11)

* «Выдать» отказывает, если кар на обслуживании или отключён. Раньше супервайзер так обходил
  правило «снять с обслуживания — менеджер» (EXP-GIVEMAINT).
* В возврате кара `by_name` и `by_employee_id` принимаются только при `cars.issue`, иначе 403.
  Свой возврат без этих полей работает как раньше.

## 5. Матрица «роль × маршрут» в тестах (ARCH-03)

`tests/test_authz_matrix.py` проходит все маршруты с `require_perm` (166) за администратора,
менеджера, супервайзера и сотрудника. Ещё один прогон — за супервайзера с индивидуальными
deny и allow. Ожидание считается из эффективных прав пользователя: 403 должен быть ровно там,
где права нет.

Обработчики при этом не выполняются: целые параметры пути — «x», тело — `[{}]`. FastAPI
проверяет права раньше входных данных, поэтому гейт пройден, если пришло 422. Без такой
остановки проходят только GET-маршруты (чтение). Отдельный страж проверяет, что в журнале
аудита не появилось записей. Маршрут `/telegram/chats` пропускается: он обращается к сети.

## 6. `bump_version --check` по содержимому (UI-04)

* `bump` записывает в `sw.js` строку `// содержимое оболочки: <хеш>` — хеш css/js оболочки и
  `index.html` без `?v=`. `--check` (он есть в CI) падает, если файлы изменились после
  последнего bump. Первый же запуск поймал правки JS этого батча.
* `--help` и `-h` печатают справку, другие ключи — ошибку. Раньше любой аргумент
  записывался как номер версии.

* Сценарий «сотрудник с индивидуальным allow `schedule.edit` правит сетку» в браузере не
  прогонялся. Условие то же, что у тулбара; права на сервере проверяет матрица.
* В окне смены статуса кара пункт «Обслуживание» по-прежнему виден всем с `cars.issue`, а
  сервер отказывает без `cars.maintenance` с понятным текстом.

  бы они были, у менеджера с deny `employees.edit` корректировка банка открылась бы:
  теперь она зависит от `employees.bank`.
